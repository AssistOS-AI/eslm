# ESLM Processing-Graph Discovery Log

This is the human-readable research ledger for processing-node, coordination-node, authority-gate, strategy, edge,
packet-field, and nested-circuit hypotheses. It is evidence, not design authority: normative contracts live in
`docs/specs/`, machine receipts live in
`docs/results/`, and raw licensed source rows remain in ignored caches. A log entry never registers runtime code,
changes a strategy profile, supplies knowledge, or authorizes an answer.

## How a discovery cycle works

Each cycle freezes its source revisions, component rights, visible splits, projection losses, baseline graph, analysis
methods, work limits, and receipt identity before examining examples. It records only source-neutral structural
summaries in this file. Source text, expected answers, row identifiers, and protected examples are excluded.

A hypothesis must name one stable responsibility, its input and output packets, normal and exceptional edges,
authority, state effects, work dimensions, failure vocabulary, and the existing node that would otherwise own the
behavior. Several independent discovery strategies may vote on support, opposition, recurrence, stability, and
placement. Confidence ranks research hypotheses; it cannot establish truth or waive a schema, safety, semantic, proof,
rights, or promotion gate.

Periodic consolidation compares every retained hypothesis with the current catalog. Two candidates are merged when
they have the same responsibility and authority boundary, even if source vocabulary differs. A candidate is rejected
when it is a decorative wrapper, a source-family label, a hidden solver, answer-conditioned behavior, or an
interpretation/retrieval/reasoning/construction mixture. A new node is preferred only when one existing contract cannot
own the responsibility coherently. Alternative algorithms under one responsibility remain strategies of the same
node. This keeps the graph as small as the task structure permits, while allowing hundreds of independently testable
strategies when evidence genuinely warrants them.

Hypothesis states are `observed`, `retained`, `merge-candidate`, `rejected`, `prototype`, `promoted`, and `retired`.
Only a maintainer-reviewed DS update, implementation, genericity controls, ablation, protected transfer, full
regression, and matching promotion receipt can advance a hypothesis to `promoted`. The receipt records that authority
decision; neither the analyzer, its votes, this ledger, nor the research proposal sink can promote itself.

## Cycle 000 — architecture baseline

**Evidence scope.** Current ESLM implementation, specifications, generated language development cases, reasoning
benchmarks, and metamorphic tests. No external task-feedback row was used in this cycle.

**Consolidated discoveries.** The baseline replaced an opaque subsystem view with five engineering roles:

- a processing node owns one typed responsibility;
- a strategy is one reviewed implementation of a selectable node;
- a coordination node preallocates work and compares typed candidates;
- an authority gate checks an invariant and cannot be outvoted; and
- an immutable packet plus processing receipt is the only supported cross-node communication boundary.

The baseline also separated confidence from truth. Interpretation, planning, and relevance confidence may prioritize
work. A reasoning method must produce a witness, and a verifier must independently accept that witness before a strict
claim can be constructed. Session rollback, provider lifecycle cleanup, result validation, and package validation are
authority boundaries rather than low-confidence strategies.

**Decision.** Retain this five-role vocabulary and use it as the normalization target for later dataset-derived
hypotheses. The exact concrete node inventory is versioned separately so implementation growth does not rewrite this
conceptual baseline.
