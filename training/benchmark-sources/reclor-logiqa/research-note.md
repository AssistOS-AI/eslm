# ReClor and LogiQA categorical argument candidate experiment

The experiment deliberately attempted a small method instead of a general four-choice selector. The typed method knows only monadic categorical propositions, two proof obligations, semantic candidate identifiers, and explicit resource limits. For a necessary-conclusion task it asks whether each candidate follows from all premises. For a sufficient-premise task it adds one candidate premise and asks whether the declared conclusion follows. It selects a candidate only when exactly one candidate is entailed.

Entailment is decided by finite monadic constraint closure. `all S P` adds the inclusion S→P, `none S P` adds symmetric exclusion, `some S P` requires one object in both classes, and `some-not S P` requires one object in S and outside P. Positive membership propagates through inclusions; negative membership propagates backward through inclusions; exclusions propagate negative membership. To test a query, the method adds its categorical negation. A contradiction in a required object type is a proof of entailment. A consistent set of closed object types is a countermodel. The verifier does not trust the selector's Boolean: it checks that every proof edge is licensed by an input inclusion or exclusion and ends in an explicit positive/negative collision, or evaluates every premise and the falsified query directly in the returned object model.

The method itself contains no benchmark identity, source identifier, answer position, expected label, or English vocabulary. Tests completely rename term identifiers and candidate identifiers, reorder premises and candidates, reverse an inclusion as a meaning-changing contrast, preserve unrelated candidates, expose inconsistent bases and resource bounds, and statically inspect the core source for forbidden dispatch.

The language projection is intentionally narrower than the algorithm. It recognizes only explicit necessary-conclusion or sufficient-premise question operators and only complete English A/E/I/O-style propositions. It rejects an entire task if any premise or candidate is opaque. It also requires one explicit conclusion marker for a sufficient-premise argument. These constraints prevent the adapter from deleting evidence until a desired candidate becomes uniquely provable.

Complete train/development-visible execution found no source case satisfying all preconditions. ReClor recognized 305 training and 34 validation question operations, but every corresponding record failed complete premise compilation or an unambiguous conclusion boundary. English LogiQA recognized 160 training and 38 development operations. One training record reached candidate parsing, where an unsupported compound candidate correctly stopped the complete task. All other recognized records failed complete passage compilation. The method therefore made zero real-source attempts and produced no benchmark answer.

Core Guardian accepts the small typed algorithm as internally generic but rejects registration and promotion. The missing evidence is not a low score: it is absence of two independent complete source examples that reach the method through a sound projection. Broadening the parser by dropping opaque clauses, dropping opaque candidates, collapsing compounds into atoms, guessing discourse boundaries, or using overlap and position would invalidate the source task and the witness. The module remains an unregistered research candidate used only to measure strict projection coverage. No capability registry, engine dispatch, DS contract, HTML page, catalog entry, or public result was changed.
