# αNLI / ART source integration and development diagnosis

## Frozen source, rights, and complete retention

This integration uses the official repository associated with *Abductive Commonsense Reasoning* at Git revision `8ed901f038df77b7a4d0d8889255160d351d2b49` and the `anli.zip` archive linked by that revision. The exact archive contains the official train, development, and test records plus separate answer files. The adapter verifies every file by byte count and SHA-256 and streams every one of the 174,245 records through a closed five-field schema. No source row is removed because of file size, corpus size, duplicate context, textual anomaly, or current method coverage.

The repository's Apache-2.0 file governs the official code. Neither the pinned README nor the delivered archive states that Apache-2.0 also licenses the dataset, and the official `allenai/art` Hugging Face card identifies the dataset license as unknown. ESLM therefore applies a narrow local noncommercial-research and no-redistribution policy. Original source rows remain in the ignored cache. The committed manifest, inventory, and evaluation receipts contain only identities, aggregate counts, and ESLM-authored explanations.

The source has 169,654 train rows, 1,532 development rows, and 3,059 test rows. Train intentionally constructs many alternative pairs from 17,801 story contexts, so `story_id` is not a unique case key there. The inventory reports 151,853 repeated train story identifiers and derives task identities from the complete label-free visible tuple. It also reports 1,445 duplicate train tuples, 52 train rows whose two hypotheses are textually identical, 74 train rows containing embedded line breaks, 35 train rows containing the Unicode replacement character, and one such test row. These are retained source properties. The task projection collapses control whitespace before the bounded narrative compiler, but the frozen source bytes and anomaly counts remain available for review.

## Task meaning and oracle isolation

Each task supplies an initial observation, two alternative events, and a later observation. The preferred alternative is intended to be a plausible event between the observations. The adapter therefore emits the typed operation `select-narrative-bridge`, a before-event frame, two ordered candidate bridge frames, an after-event frame, and a candidate-ID output contract. It does not relabel the task as ordinary continuation selection: placing a candidate after the later observation would reverse the temporal structure and produce evidence for a different question.

Labels live in separate files. Development collection maps a label to the corresponding candidate identifier only in a private host scorer after the label-free task has been constructed. Changing a label leaves the visible task byte-for-byte unchanged. Source validation checks the test files' digest, schema, row count, label-file length, and label domain so the complete frozen release is accounted for. It does not expose a test loader, join a test label to a prediction, inspect per-item test outcomes, or execute the test split. The official test membership is fixed upstream and is recorded as a sealed fresh pool of 3,059 cases. Opening it requires an accepted witness-producing development method, a behavior freeze, regression evidence, and explicit approval.

## Complete development baseline

All 1,532 official development cases were sent to the unchanged engine under the direct symbolic profile. No Language Agent normalization was attempted or permitted. Every task returned `NO_APPLICABLE_METHOD` because the engine has no registered `select-narrative-bridge` operation. No candidate was selected, no answer was scored correct, and no witness exists. Accuracy over answered cases is therefore undefined. This is a complete coverage result—zero of 1,532 cases received an evidential answer—not a reported 0% accuracy over guessed labels.

The earliest observed failure is method selection. It would be misleading to assign exact counts to causal, temporal, goal, social, reference, or missing-knowledge subclusters after execution stopped before any such trace existed. Those downstream requirements are real features of the task contract, but quantifying them requires a future label-free semantic compiler and candidate method that records which typed precondition failed.

## Why no core method was added

The existing bounded narrative-continuation ranker evaluates a possible next event against a preceding sequence. αNLI asks whether a middle event connects both an earlier and a later observation. Applying the continuation method to the candidates after `obs2` would change the task. Applying shallow lexical overlap independently on both sides would still not establish enabling conditions, causal effects, goals, state transitions, reference continuity, contradiction, or real-world compatibility.

A generic future bridge method has a defensible contract: typed before and after events; candidate bridge event sequences; explicit participant roles, polarity, modality, time, preconditions, and effects; provenance-bearing causal, temporal, goal, social, and state evidence; bounded search; an explicit decision margin; and a replayable contribution witness. It must remain invariant under complete entity, predicate, state-value, relation-vocabulary, namespace, and surface renaming. Candidate-order permutation must permute the selected candidate rather than change its meaning. Reversing a causal edge, deleting an enabling condition, introducing a contradiction, or substituting an unrelated event must lower support or produce an explicit unknown.

Those preconditions do not exist for arbitrary ART prose in the current system, and current KB providers do not supply complete event knowledge for this source. Adding an engine operation now would therefore install a lexical or positional heuristic behind a method name rather than symbolic reasoning. Core Guardian defers the proposal. No capability descriptor, planner, language parser, engine dispatch, shared reasoning file, KB package, DS file, or HTML page changed in this track.

Rejected repairs include returning the development majority; assigning fixed meaning to negation, sentiment, overlap, length, or candidate position; using `story_id`, row order, hashes, source strings, or labels; and presenting ties as forced preferences. None survives the renamed nonce controls and meaning-changing contrasts required for a generic method.

## Next admissible cycle

A later cycle should first extend the language and knowledge layers with reviewable event roles, reference links, state preconditions and effects, temporal ordering, goals, causal support and attack, and provider provenance. Development-visible cases may then be clustered by the earliest failed typed precondition. A bridge selector can be proposed only after multiple independent clusters share one executable semantic cause and a KB-only representation would distort or duplicate the mechanism.

The candidate must pass fully renamed nonce tests, candidate-order permutations, irrelevant distractors, causal reversals, missing-enabler contrasts, participant-reference contrasts, contradictions, ties, deterministic replay, resource bounds, witness verification, Story Cloze regression, and the full project suite. Only after that behavior and its dependency hashes are frozen may the official test aggregate be opened once. Until then, the fresh score remains absent rather than fabricated.
