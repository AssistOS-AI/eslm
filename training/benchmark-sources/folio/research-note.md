# FOLIO v0.0 development integration

The adapter pins the official Yale-LILY/FOLIO repository at revision `5d7bb84c7edab3fb358e057d2807f19cf5cf5e2d`. The complete CC BY-SA 4.0 archive remains in the ignored cache. Its source-native JSONL files are streamed, hashed, checked against exact field sets and bounded types, and retained without row deletion. Empty annotations and natural-language/FOL premise-count mismatches in the original v0.0 data are counted as source anomalies rather than silently repaired.

The source exposes train and validation labels but no test file. The repository README explicitly describes the test set as unreleased. Both local labeled files are therefore development-visible. The label-free loaders return all 1,004 train inputs and all 204 validation inputs without labels; only the host scorer reads development labels. No fresh score is reported, because relabeling an already visible file as fresh would not create untouched evidence.

Four measurements remain separate because they answer different questions. All denominator-bearing measurements below cover the complete 204/204 development partition. No row is omitted when parsing or execution fails.

The official-formula track parses the supplied FOL annotations into a typed AST, grounds quantifiers over constants named in each case, and invokes generic symbolic entailment. Small grounded tasks use exhaustive finite enumeration. Tasks above the sixteen-atom exhaustive bound use the already accepted query-directed Tseitin-CNF and DPLL fallback with checked certificates or countermodels. The track predicts 161/204 labels correctly. Its statuses are 175 `SOLVED`, 5 `UNSUPPORTED_FORMULA`, and 24 `INCONSISTENT_CONTEXT`; its method counts are 146 finite-enumeration, 53 scalable-Boolean, and 5 not executed. This remains a named-domain diagnostic rather than unrestricted first-order validity.

The full-natural-language track requires every premise and the conclusion to compile before a case executes. It compiles 545/1,292 sentence slots and executes 9/204 complete cases, of which 4 are correct. Its case statuses are 9 `SOLVED`, 182 `UNSUPPORTED`, and 13 `AMBIGUOUS`. The complete-case score remains deliberately strict: producing one or several plausible ASTs does not count as understanding a case whose other sentences are unsupported or whose scope remains ambiguous.

The query-language diagnostic isolates conclusion understanding while retaining the official premise formulas as declared symbolic evidence. Its lexical resolver may use only predicate and constant vocabulary found in those premise formulas. It does not receive `conclusion-FOL` or the answer label. It compiles 108/204 conclusions, executes 98, and predicts 75 correctly: 36.76% over the full development partition and 76.53% among executed queries. This is not labeled direct end-to-end language understanding because official premise formulas provide the evidence theory.

The development-only semantic audit compares candidate formulas with official annotations after parsing. The annotation can confirm or reject a candidate but cannot repair the candidate or generate an answer. Of 1,279 parseable official sentence annotations, 541 candidates parse and 383 match exactly under bound-variable renaming. Conclusions match in 73/204 cases, and all formulas match in only 4 complete cases. This exposes wrong scope and argument structure that a parser-status count would otherwise hide.

This language iteration adds three bounded, generic constructions: unique relative/main-clause boundary selection with a shared quantified variable; a distinction between two named subjects sharing one predication and two independently parsed coordinated clauses; and an indefinite typed object introduced in a conditional antecedent and reused by an object pronoun in the consequent. Against the previous development receipt, sentence compilation rises from 534 to 545, exact sentence formulas from 370 to 383, query compilation from 106 to 108, query execution from 96 to 98, query correctness from 74 to 75, and exact query formulas from 72 to 73. The strict complete-case result remains 4/204. No result was selected or discarded to create these deltas.

Nonce and complete-renaming tests replace entity constants, unary classes, binary relations, object constants, and surface verbs together. Scope contrasts exchange relative and main predications and distinguish implication from biconditional. Coordination controls audit term assignments rather than accepting only a common outer conjunction. An existing premise-order control confirms that reordering the declared evidence does not change the query result. A forbidden-dispatch audit confirms that the generic language module contains no benchmark, dataset, row, answer, source-family, or example-specific vocabulary.

The Core Change Guardian therefore accepts the candidate only for adapter-guided development measurement. Runtime registration remains deferred: the pinned source provides no untouched language-evidence pool on which to test the required fresh-coverage condition. The deployed Stage A engine and registry were intentionally not invoked or changed in this iteration; the runtime-front-end receipt records `tested: 0`, a null rate, zero normalization attempts, and zero Language Agent invocations instead of presenting an unexecuted diagnostic as a 0% result.

The surviving language clusters are nested Boolean coordination, quantifier and relative scope beyond a uniquely supported boundary, binary argument attachment, definite-description and pronoun reference beyond the bounded object pattern, and predicates absent from the premise-declared vocabulary. The finite atom-capacity failure is closed by the existing scalable fallback. Twenty-four official-formula contexts and ten compiled query contexts remain inconsistent under the named-domain interpretation; the evaluator refuses explosion or label coercion. Repairs must remain generic and pass nonce, full entity/predicate/value renaming, source reordering, meaning-changing scope controls, exact formula audit, and regression verification.

The official repository points to a later quality-corrected v2 release hosted behind an authorization gate. This integration does not open that release, conflate it with v0.0, or infer its contents from the older archive. A later authorized v2 acquisition must be pinned as a separate source version. A genuine fresh claim requires an official untouched labeled split or evaluator and a dependency freeze taken before execution.
