# StepGame official-source integration note

## Source identity and complete retention

The selected source is the official corrected StepGame release at Hugging Face revision `6d859381dfd518cae3f073b268aaa323bf4dcf04`. Its dataset card identifies the March 2024 corrections and directs users to this release. The authors' Git repository is frozen independently at commit `5e6aff1563a6d7f46ee1f1aeff98b94e68c29005`; the repository supplies the MIT license and the inert Python template lists that define the sentence language. The adapter reads those lists as bounded text. It never imports or executes the Python generator.

All 155,000 rows and all 75,665,180 source bytes are retained under `training/.cache/benchmarks/stepgame`. Train, validation, and test remain separate source-native JSONL shards. Processing is line-streamed. A runtime task limit can bound one example, but no file, row, or valid fact is rejected because the dataset is large.

## Adapter boundary

Each accepted sentence becomes a typed relation fact with ordered subject and object identifiers. A question becomes a relation query. The source label remains in the host oracle and is joined only after the generic spatial-vector method returns a result. The adapter uses neither row identity nor label to select a relation. It invokes no Language Agent.

The official generator is not perfectly invertible. One declared template omits an entity placeholder. Other surface strings are generated by more than one template with different ordered implications. Those defects are observable source conditions, not invitations to guess from the label. The adapter records unmatched and ambiguous sentences and continues with every independently accepted fact. This yields 4,710 solved validation cases, all 4,710 exact, while 290 cases remain `UNKNOWN`. Every one of those 290 contains source damage; 234 other damaged cases are still solved because unaffected evidence is sufficient.

## Generic reasoning and proof behavior

The core method receives a declarative vector system, typed facts, a query, a composition policy, and a path-depth bound. It adds declared inverse edges, propagates coordinates only through the query-connected component, detects incompatible exact coordinate assignments, classifies the resulting sign vector through declared output metadata, and returns the ordered edge path used for the displacement. A separate verifier reconstructs the path and vector sum from the original task.

The Core Guardian controls rename entities, dimensions, relation identifiers, and values; reverse the query; reorder facts; inject disconnected distractors; contrast exact cancellation with opposed directions; and force the declared depth bound. Static tests reject benchmark identity and source direction vocabulary in the generic core. This method is therefore reusable typed constraint propagation rather than a StepGame answer table.

## Honest limit

The 94.2% number is a complete run over the 5,000-row official validation split, not the untouched 100,000-row test split. It measures exact classification after strict source-template projection. It is not evidence that malformed generator outputs can be recovered without extra authority. Recovering them would require a separately specified source repair rule with evidence independent of the hidden answer.
