# LogicSkills official-source integration note

## Exact source and license

This track is the LogicSkills benchmark introduced by Brian Rabern, Philipp Mondorf, and Barbara Plank in arXiv:2602.06533v2. The paper names the author repository at <https://github.com/brianrabern/LogicSkills>. Revision `1f23e684d6b1a465047f8b0d833d9b9b3388441a` is frozen as the source. No similarly named logic-skill collection and no unofficial mirror was used.

The full author archive is retained in the ignored immutable cache. The project `LICENSE` grants MIT terms for code. The author README explicitly assigns CC BY 4.0 to the question sets and JSONL benchmark data, and the author-supplied dataset card repeats `license: cc-by-4.0`. These separate license statements are preserved rather than treating the code license as the data license.

The complete archive contains generation code, full evaluator question structures, model outputs, evaluation outputs, and three normalized benchmark JSONL files. The source adapter uses the normalized author export because the author README identifies it as the minimal external benchmark representation. Every one of its 1,500 fixed evaluation rows is streamed through a task-dependent closed schema. The richer evaluator artifacts remain retained for later implementation of semantic scorers, but their Python code and source strings are never executed by ESLM.

## Lifecycle and oracle separation

LogicSkills publishes a fixed evaluation set rather than train and development splits, and its dataset card says the data is intended for evaluation and analysis rather than training. Before capability work, the adapter therefore freezes 1,200 public rows as development-visible and 300 as fresh. The partition is balanced across the five task-language strata and depends only on filename, source ID, task, and language. It does not inspect the prompt text, reference formula, or selected validity index.

For symbolization, the input prompt is visible and the canonical formula remains host-only; an official score requires logical equivalence, not exact text. For validity, the prompt is visible and the selected candidate index remains host-only. Countermodel records intentionally contain a null answer: correctness is not comparison to a reference string but verification that the proposed finite structure makes every premise true and the conclusion false. The adapter exposes that verification contract without inventing an oracle.

## Current development checkpoint

All 1,200 development tasks were passed to the current engine's typed-task boundary with zero Language Agent calls. The generic finite first-order model method constructed independently verified three-member countermodels for all 240 development-visible countermodel tasks. The other 960 symbolization and validity tasks returned `NO_APPLICABLE_METHOD` before scoring. The repository reports the 240/240 semantic countermodel track separately and does not manufacture one aggregate percentage across answered and unanswered output contracts.

The remaining generic families are controlled English and Carrollian language to two-variable first-order logic, validity over that fragment, and semantic equivalence for alternate first-order formulas. The countermodel method parses a compact function-free FOL argument into a typed AST, enumerates constant interpretations over the declared domain, grounds quantifiers, calls generic Tseitin/DPLL search, and independently evaluates the decoded interpretation against every premise and the conclusion. Its tests rename predicates and constants, reverse binary relations, and contrast valid with invalid arguments. It does not branch on LogicSkills identifiers, prompt strings, reference formulas, answer indices, or archived result vocabulary.

After the countermodel behavior and dependencies were frozen, the evaluator opened only the 60 fresh countermodel tasks and returned an aggregate. All 60 received independently verified three-member models; no Language Agent was called and no task text, identifier, returned model, or per-case outcome was retained. Fresh symbolization and validity inputs and their answer fields remain unopened. The result is a sealed countermodel-subtrack claim, not an overall LogicSkills score.

## Development-only symbolization candidate

The next iteration did not reopen or inspect any fresh member. It clustered the 960 development-visible gaps by the first failed stage. The 480 validity tasks still lack a sound complete method for the source's two-variable first-order fragment. Bounded failure to construct a countermodel is not promoted into validity, so that track retains 480 explicit `NO_APPLICABLE_METHOD` outcomes and no accuracy value. The 480 symbolization tasks instead expose a recurring language-composition gap: their prompt supplies a declarative symbol key, but no generic mechanism compiled the controlled sentence and those typed frames into a first-order formula.

The candidate module accepts a sentence plus unary or binary predicate frames and constant surfaces. Its control flow knows grammatical operators and typed placeholders, not source identifiers or expected formulas. It implements atomic frame resolution, named constants, every/all/no/some/not-all/only quantifiers, quantified relation objects, negation, conjunction, disjunction, conditionals, only-if, unless, and biconditionals. Every accepted content-bearing atom must resolve through exactly one supplied frame. Unsupported relative clauses, ambiguous coordination, unresolved inflection, and incomplete object phrases cause whole-sentence abstention; the compiler never drops an opaque span to create coverage.

On all 480 development symbolizations, the candidate emitted 288 formulas and abstained on 192. All 288 derivation witnesses replayed, and all 288 predictions matched the host-only reference under a sound conservative equivalence checker, giving 288/480 or 60% over the complete development symbolization denominator and 288/288 on attempted cases. English contributed 167/240 correct attempts and the Carroll nonce-language stratum 121/240, which demonstrates that the mechanism does not depend on the ordinary domain nouns. The comparison is a sound lower bound: the checker proves alpha-renaming, double-negation, associative and commutative Boolean structure, and two guarded quantifier-lifting equivalences, but it may reject other genuinely equivalent formulas.

Core Guardian accepts the module only as an unregistered development candidate. Complete renaming, lexicon reordering, a conditional-direction contrast, witness tampering, opaque-clause rejection, and resource bounds pass. Runtime registration remains deferred because the grammar is incomplete, the equivalence checker is incomplete, no fresh symbolization evidence was opened, and promotion would require synchronized method specifications, capability metadata, engine integration, documentation, and cross-source language regression. This iteration changes none of those shared surfaces and makes zero Language Agent calls.
