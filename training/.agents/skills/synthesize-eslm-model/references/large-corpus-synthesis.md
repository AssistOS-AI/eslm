# Large-corpus synthesis gate

Read this reference before working on a public knowledge graph, lexical database, event graph, document corpus, a source larger than 50 MB compressed, or a prepared source expected to exceed 100,000 records.

## Refuse premature full synthesis

Do not start exhaustive candidate generation unless the assignment provides or authorizes creation of:

1. an immutable source manifest with release or dated snapshot, bytes, digest, license, and attribution;
2. a deterministic stratified probe report;
3. a reviewed source-to-ESLM semantic mapping;
4. explicit time, space, domain, world, perspective, modality, polarity, and conflict handling for observed records;
5. a resource budget and profiling output path;
6. a streaming Node adapter design;
7. a sharding and query-selection design that does not require full runtime import or closure.

If any item is absent, produce the missing design or probe artifact in the assigned work directory and stop before full synthesis. Do not compensate by reading an arbitrary prefix, silently dropping unfamiliar records, or treating all relations as generic triples.

## Build the probe

Stream the source or a bounded frozen source artifact. Count all records that can be scanned within the approved probe budget. Select examples deterministically by stable hash within strata, not by source order. At minimum stratify by source record kind, relation, language, upstream dataset or contributor class, license, weight or rank, datatype, qualifier presence, time shape, spatial shape, text-length band, and parse result when those fields exist.

Give rare, rejected, malformed, ambiguous, negative, conflicting, cyclic, and oversized records explicit sample quotas. Report unknown relations, fields, datatypes, identifiers, units, scopes, and license mixtures. Estimate dictionary cardinality, direct claims, provenance rows, shard count, generated bytes, import memory, and worst posting density.

For a small source, scan the entire artifact and retain bounded examples. For a large source, state the streamed byte/record boundary and which counts are estimates. Never describe a partial prefix as a corpus-wide distribution.

## Review semantic mapping

For each observed stratum, record one outcome:

- mapped to an existing typed ESLM record and executor;
- mapped to a new reviewed typed record or executor;
- preserved as non-executable evidence text with source spans;
- quarantined with a precise diagnostic;
- rejected by an explicit profile policy.

Relation-specific inference is mandatory. State transitivity, direction, inverse behavior, inheritance, exception priority, modality, time behavior, world compatibility, and confidence interpretation separately. A source weight is not a calibrated probability. Missing evidence is not falsehood.

## Preserve contextual scope

Do not merge claims whose values match but whose scope differs. Preserve:

- valid time and source-record time;
- coordinate system, containment kind, or spatial precision;
- conceptual or scientific domain;
- actual, fictional, benchmark, simulation, or user-hypothetical world;
- canon, edition, document, or branch identity;
- speaker, character, source, or belief perspective;
- assertion, default, prediction, possibility, obligation, intention, or hypothesis modality;
- polarity, conflict, rank, and uncertainty.

A hypothetical assignment creates an immutable branch overlay. It must not rewrite the base world or promoted model.

## Profile every phase

Emit `eslm-profile-v1`-compatible stage records for source read, decompression, parsing, validation, normalization, deduplication, dictionary construction, relation mapping, anomaly handling, sharding, indexes, provenance, code emission, validation, cold import, and probe queries.

Report input/output bytes and records, accepted/rejected counts, throughput, shard and posting counts, CPU, wall time, RSS/heap/external-memory deltas, sampled peak memory when available, cache/spill behavior, and diagnostics. Highlight the largest wall-time, CPU, allocation, rejection, dictionary, shard, and posting contributors.

Stop when memory follows total decoded source size, throughput has an unexplained superlinear collapse, one shard becomes operationally dominant without semantic reason, validation duplicates the entire graph, or output cannot be queried without importing unrelated domains.

## Generate for query-directed execution

Use interned integer dictionaries, relation-and-scope shards, sorted integer postings, compact claim-to-source tables, and static manifest-declared imports. The small manifest must expose enough predicate, domain, world, time, entity-range, count, and dependency metadata for query planning before shard import.

Do not precompute full global closure. Generate rule indexes by head and premise predicates. Preserve the information needed for memoized top-down or semi-naive bounded evaluation over a relevant subgraph. Session and hypothetical overlays must invalidate only affected memo entries.

## Handoff

In addition to the normal skill handoff, provide:

1. probe coverage and every unaccounted stratum;
2. scope and relation mapping tables;
3. source/profile/shard inventories;
4. profiling report and top hotspots;
5. measured and projected resource curves;
6. query-selectivity evidence;
7. explicit gate verdict: `APPROVED_FOR_FULL_SYNTHESIS` or `BLOCKED_BEFORE_FULL_SYNTHESIS` with reasons.
