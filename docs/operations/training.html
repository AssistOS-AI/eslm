ESLM Documentation / Development / Agent-guided training

Frozen evidence, isolated Coding Agent workspaces, declarative candidates, and explicit promotion

Training is controlled program and knowledge construction separated from deployed inference. A host process prepares a bounded packet, copies exactly one self-contained skill into a fresh workspace, invokes Coding Agent as an ephemeral subprocess, and collects a declarative candidate plus audit evidence. Trusted host gates retain exclusive authority over repository changes and promotion.

Evidence visibility comes before synthesis

A training packet declares its format, split, leakage policy, source records, document records, benchmark cases when development-visible, canonical records supplied as context, and content hash. Test and hidden benchmark material is never placed in the packet. This rule applies even when revealing a held-out answer would make it easier to repair a failure. A learning cycle may inspect clustered development failures; final test evidence remains an independent measurement.

Sources are frozen before packet construction. The packet records exactly which bytes and records the agent could see. If a source changes, it produces a new hash and a new run identity. Candidate lineage therefore answers whether two builds used the same evidence rather than relying on a mutable URL or directory name.

The workspace contains one approved skill and train-visible evidence. Coding Agent produces only a candidate; trusted validation, evaluation, and a separate decision control promotion.

The subprocess boundary

The CLI command train run creates the workspace, writes PACKET.json and ASSIGNMENT.json, copies the selected skill to skill/, and runs codex exec with an ephemeral session and workspace-write sandbox. The prompt instructs the agent to remain inside the workspace and write only candidate data and reports. The runner stores bounded event and diagnostic logs plus an execution receipt containing command identity, timestamps, exit code, output hashes, and truncation flags.

A dry run performs all preparation and reports the exact invocation without launching Coding Agent. This is the normal way to review packet visibility and workspace composition. A real run inherits the environment required for Coding Agent authentication and configuration, but receipts do not serialize secret values. Agent output is parsed only as untrusted files after the process ends.

Candidate forms

A knowledge candidate contains canonical JSONL and a report. The Document-to-KB skill carries an exact portable copy of the host schema contract: field names such as canonicalKey, surface, denotes, predicate, and arguments are not interchangeable with similar schema names. Its validator checks record shapes, provenance, logical rule safety, predicate terms, denoted terms, term arguments, contexts, events, and retraction targets. The trusted host repeats those checks before kb compile writes JSON shards. A method candidate describes a reusable capability, preconditions, operators, expected proof form, budgets, and tests. A generic-core candidate includes the smallest proposed trusted-code change and must pass the core guardian. Each candidate records observations separately from hypotheses. Missing evidence is represented as a gap rather than completed with plausible content.

The skills are self-contained: their instructions, scripts, templates, and agent metadata travel together. Their verification scripts use only Node.js standard-library facilities. When a skill needs the current runtime’s NLP or reasoning behavior, the host supplies an approved tool or frozen analysis result; the isolated agent is not granted unrestricted access to the repository merely for convenience.

The host currently writes BASELINE_ANALYSIS.jsonl before isolation. It runs each embedded document or development-visible case through the Stage A frontend and records normalization, parsed query when present, task frame, selected plan, extracted session assertions and rules, unsupported spans, and unresolved subgoals. The agent treats this output as diagnostic evidence and checks it against source text; parser output is never promoted as source truth merely because it is machine-produced.

Promotion gates

Promotion requires schema validation; referential and logical validation; deterministic compilation; an independent package or core audit; positive examples; negative and contrastive controls; regression tests; resource measurements; split-safe evaluation; and a recorded decision. A candidate that improves one benchmark but breaks a previously declared capability is rejected or revised. A candidate that succeeds only because it contains test-specific constants is rejected even if aggregate accuracy rises.

For KB additions, promotion produces a versioned package and catalog update. For new methods, promotion updates the capability registry and trusted implementation with proof obligations. For generic core changes, promotion also updates the relevant DS and HTML explanations because it changes the system’s public meaning. Training workspaces and rejected candidates remain transient unless retained as explicit experiment evidence; deployed inference never reads a global executable artifact generated by training.

Leakage-resistant benchmark-guided learning

The learner begins from a failure cluster, not an isolated answer. It asks whether failures share a linguistic construction, missing predicate mapping, absent domain fact, missing inference method, context policy, or budget issue. It proposes the smallest layer-correct change and constructs held-out transformations: renamed entities, reversed relations, removed premises, distractors, and cases that must remain unknown. Only after these controls pass is the change measured on the development suite and unrelated regressions.

The current public work illustrates layer-correct changes. bAbI movement failures led to generic state history and a predecessor method tested with renamed entities; Task 16 led to a declarative package containing the source-visible property domain and induction policy rather than benchmark constants in the core. Entity Tracking led to a generic container-state operation with a label-free task adapter and host-only masked-span oracle. CLUTRR led to a generic typed relation executor plus a separately provenance-bearing kinship algebra; the executor is tested with renamed entities and relations and preserves structural ambiguity. EWoK led to provider-neutral semantic compatibility plus an authored world-relations ontology and independent ConceptNet evidence, not copied preferences. Story Cloze led to bounded narrative frames and a defeasible continuation selector whose development-visible policy is explicit. SimpleQA led to provider-neutral factoid parsing and exhaustive provider routing, while its answers still require independently sourced facts. Language Agent normalization cannot legitimately fill any reasoning or knowledge gap.

Development, fresh, and protected evidence

A benchmark-guided cycle begins by constructing any development/fresh partition without reading labels. The partition receipt binds source bytes, seed, grouping or stratum policy, and membership digest. Development failures may then be inspected, clustered, and used to propose core or KB changes. A fresh pool remains host-only until the proposed mechanism, package manifests, adapter policy, tests, and relevant source files are frozen by digest. The fresh evaluator emits aggregates and bounded stratum summaries rather than protected item text.

Opening the fresh aggregate ends that experiment's untouched-evidence phase. If any bound behavior changes, the receipt continues to describe only the earlier checkpoint. The same pool cannot become a repeated repair oracle while retaining a fresh claim. Protected EWoK rows and form-delivered Story Cloze rows remain ignored local data throughout; only authorized visible development evidence can enter a benchmark-guided packet, and benchmark answers never become KB records.

The 4,096-case smoke corpus protects accepted local-language and core capabilities after a change. Its 1,200 heuristic-language cases cover all 43 reviewed generator shapes and eight oracle levels; 2,896 core cases retain 26 direct, state, relation, preference, and typed-task templates. All use generated nonce vocabulary and run without agent assistance. Structural tags support coverage analysis, but the corpus neither copies public test sentences nor turns a passing software regression into a public benchmark score.

This process treats a benchmark as diagnostic evidence rather than a source of truth. Benchmark labels may help classify observable development behavior, but a domain claim still needs source provenance, and a generic capability still needs a domain-independent contract. Public probes keep the Language Agent disabled and count only cases that would qualify for normalization; a separate assisted experiment must freeze its model, policy, cache, prompts, and route metrics. Detailed packet, learning, and gate requirements are in DS004, with trust and security in DS009 and language-only assistance in DS013.
