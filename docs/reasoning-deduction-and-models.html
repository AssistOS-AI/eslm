Deduction, fixed points, SAT search, finite models, and counterexamples

ESLM has three exact deductive regimes. Safe Horn deduction constructs the least fixed point of a positive rule program over ground facts. Finite entailment enumerates every model of a small propositional theory and serves as a transparent reference. Scalable Boolean entailment compiles larger finite theories to CNF and performs query-directed DPLL search with independently replayable certificates. They answer related but distinct questions and produce different witnesses.

Safe Horn deduction

A fact is represented by a subject, predicate, and object. A rule contains a conjunction of triple patterns and one conclusion pattern. A variable is written as a bounded symbolic term such as ?x. Safety requires every head variable to be bound by positive body matches. This makes every emitted conclusion ground over the finite active domain already present in the facts.

facts:
  (gertrude, is_a, mouse)
  (mouse, afraid_of, wolf)

rule:
  (?x, is_a, ?class) ∧ (?class, afraid_of, ?object)
  → (?x, afraid_of, ?object)

deriveClosure indexes facts by subject, predicate, and object. For each rule body atom it chooses the smallest posting available under the current substitution, unifies constants and variables, and carries both the substitution and supporting facts to the next body atom. Every new ground conclusion is deduplicated by its triple signature and inserted into the indexes for the next round. Execution stops when a complete round adds nothing or the declared round bound is reached.

For positive Datalog-style programs, the mathematical target is the least fixed point of the immediate-consequence operator. The result is independent of input order, and every derived atom has a finite derivation. ESLM's implementation follows this structure but uses an explicit round budget. Its completeness statement is therefore “complete for the accepted positive safe rules within the declared round budget,” not unconditional Datalog completeness. Background reading includes Ceri, Gottlob, and Tanca's survey What You Always Wanted to Know About Datalog, and the reference overviews of Datalog, Horn clauses, and forward chaining.

The proof graph

A derived fact records the rule identifier, supporting fact identifiers, derivation depth, and combined provenance. Review does not stop at the final Boolean. A proof validator reconstructs each substitution, verifies that every support atom matches the instantiated body, checks that the instantiated head equals the derived atom, and follows leaves to accepted source records. If the answer is correct but one proof edge is invalid, the case fails.

Finite propositional entailment

decideFiniteEntailment accepts an abstract syntax tree whose nodes are atom, not, and, or, and implies. It validates the entire tree, collects and lexically sorts semantic atom identifiers, and rejects a request above the declared atom bound. For n atoms it enumerates the 2n truth assignments in deterministic mask order.

An assignment is a premise model when every strict premise evaluates to true. If any premise model falsifies the query, entailment is false and that assignment is returned as a finite countermodel. If every premise model satisfies the query, entailment is true and the witness reports the exhaustive assignment and premise-model counts. If no assignment satisfies all premises, ESLM returns INCONSISTENT_CONTEXT. It deliberately avoids classical explosion, because an inconsistent user context should not license an arbitrary application answer.

This is a decision procedure for the bounded propositional projection. Its time complexity is exponential in the number of atoms, before accounting for formula evaluation. The current implementation permits at most 20 atoms and commonly runs with a lower method or adapter bound. Crossing the bound retains the case and returns RESOURCE_LIMIT. Raising the number is not a scalability theory; query-directed relevance, SAT solving, or another declared method is needed for larger cases.

Grounded first-order inputs

A source adapter may compile a controlled finite-domain first-order form into propositional atoms, but it must state the grounding domain and preserve quantifier semantics. For example, ∀x. Bird(x) → Animal(x) over the declared domain {a,b} becomes two implications. An existential becomes a disjunction over that same complete domain. This is sound only when the domain closure is part of the source task. It does not justify treating arbitrary natural-language quantification or an unbounded ontology as finite propositional logic.

Constructing a finite first-order countermodel

A first-order countermodel is an interpretation M with a nonempty domain, a domain member assigned to every constant, and an n-ary relation assigned to every n-ary predicate, such that M satisfies all premises and falsifies the conclusion. ESLM's constructFiniteFirstOrderCountermodel implements this obligation for a declared finite domain and function-free formulas. It does not assume that differently named constants denote different members: for c constants and a domain of size d, it considers up to dc constant interpretations under an explicit semantic budget.

For each constant interpretation, quantifiers are grounded over every domain member. A universal becomes a conjunction; an existential becomes a disjunction. Every ground predicate tuple becomes a Boolean atom and the existing Tseitin/DPLL procedure searches the conjunction of all grounded premises and the negated grounded conclusion. A satisfying Boolean assignment is decoded into predicate extensions. The separate verifier then evaluates the original quantified AST recursively under the decoded structure. This second evaluation prevents a grounding, atom-decoding, or SAT integration defect from being accepted as a valid model.

The method is complete only for the declared domain when all constant interpretations and Boolean branches finish. Finding no model of size three does not prove validity over all structures. NO_COUNTERMODEL_IN_DECLARED_DOMAIN and RESOURCE_LIMIT preserve that distinction. Background theory includes model theory, finite model theory, the semantics of first-order logic, and the model-finding perspective summarized by Claessen and Sörensson's “New Techniques that Improve MACE-style Finite Model Finding.” ESLM currently uses grounding plus SAT rather than claiming the optimizations or language coverage of a mature finite-model finder.

Scalable Boolean entailment through Tseitin CNF and DPLL

decideBooleanEntailment preserves the formula semantics but avoids enumerating 2n complete assignments. A deterministic Tseitin transformation introduces one auxiliary variable for each non-atomic subformula and adds a constant number of clauses enforcing its relationship to its operands. The result is equisatisfiable with the original conjunction and grows linearly with formula size, although the SAT search remains exponential in the worst case.

The implementation uses the Davis–Putnam–Logemann–Loveland algorithm: repeatedly satisfy unit clauses, report a conflict when an unsatisfied clause has no unassigned literal, otherwise select one unresolved variable and explore both values. Variable selection is deterministic and based on unresolved-clause occurrence, not source vocabulary or insertion order. Search budgets separately bound semantic atoms, CNF variables, clauses, and nodes. A bound yields RESOURCE_LIMIT with accumulated resource counters, never a guessed non-entailment.

Why query-directed reduction remains sound

A relevance optimization can be unsound if it removes a disconnected inconsistency: under classical logic, an inconsistent full premise set changes the entailment relation even when the contradiction shares no query atom. ESLM therefore runs a satisfiability check over the complete premise CNF first. Only for a consistent full context does it compute the least transitive incidence closure from query atoms through premises that share those atoms. A premise outside that closure is propositionally independent of the query component.

The reduced search adds the negated query. If it is satisfiable, the returned assignment is merged with a complete-context model and then evaluated against every original premise; it must also falsify the query. If it is unsatisfiable, the result contains a tree whose leaves identify unit-propagation conflicts and whose internal nodes record both assignments of one split variable. The verifier recompiles the CNF and replays both branches rather than trusting a Boolean supplied by the solver. The implementation is a proof-producing DPLL procedure, not a CDCL solver: it has no learned clauses, conflict analysis, watched literals, restarts, or first-order unification.

Explicit inconsistency semantics

The general default remains INCONSISTENT_CONTEXT. Some formal task calculi deliberately adopt classical explosion. Such an adapter must select classical-explosion explicitly before execution; the result is labeled and carries the independently checked inconsistency certificate. The policy is semantic task metadata and cannot be inferred from a benchmark name, a row identifier, or the desired answer.

What the implementation does not yet provide

There is no general resolution prover, unification over function terms, equality calculus, unrestricted quantifier alternation, modal theorem prover, CDCL clause learning, or query-directed first-order relevance cone. ProofWriter logical-form success, PrOntoQA's finite grounding, and FOLIO formula execution must therefore remain separate from direct natural-language and unrestricted first-order claims. The theory of propositional logic, model checking, Boolean satisfiability, and automated theorem proving provides context; the operative boundary is the code and DS015.
