Executable Symbolic Language Model

A deterministic request-processing circuit with inspectable authority

ESLM turns bounded English requests into typed tasks, evidence, method results, and validated output. Processing nodes own each transformation. Strategies offer reviewed alternatives only where candidate comparison is meaningful. Authority gates accept or reject language, safety, schema, and proof obligations without being outvoted.

The complete processing map

The first view is the map, not a summary of it. Nested boxes reproduce the current catalog hierarchy. Every node card names its exact identity, role, implementation state, owner, typed packets, finite resources, authority boundary, outgoing conditions, and all strategies assigned to it. Use the controls to zoom or pan; expanding an exit list reveals normal, exceptional, rollback, control, resource, and authority edges.

How to read the map. A circuit groups responsibilities and may contain smaller circuits. Solid cards are processing responsibilities; colored badges distinguish sources, transformations, coordinators, non-voting authority gates, and sinks. A coordinator may compare candidates, but only a separately named gate can admit evidence, verify a witness, validate a package, commit session state, or authorize promotion. Strategy confidence ranks candidates within its declared meaning; it never becomes truth merely because more work or more branches were used. On a narrow screen the map remains at a readable internal width and pans inside this frame; Alt+←/→ also pans it.

Runtime planeA bounded request may become a validated result or an explicit typed inability.

Compiler planeA frozen, rights-cleared source may become an immutable declarative package after review gates.

Research planeInert episodes may become non-executable hypotheses for manual review; they have no runtime or promotion authority.

Successive zooms into the same map

Each view below selects a connected part of the complete map and keeps the catalog names. The diagrams simplify spatial layout only; the cards above remain the complete inventory and the logical processing chapter remains the detailed human-readable reference.

Zoom 1 · root circuit

Three planes share vocabulary but not authority

circuit:eslm:processing-graph contains the runtime, compiler, and research planes. The runtime consumes a request. The compiler consumes frozen source evidence and can emit only a validated declarative package. Research consumes authorized inert episodes and can emit only a manual-review proposal. A research hypothesis cannot jump sideways into runtime selection or compiler promotion, and catalog inclusion alone is not an execution receipt.

Zoom 2 · runtime request cycle

A request moves through five nested responsibilities

Ingress bounds the request and establishes English meaning. Request/session nodes freeze state, reserve work, identify request force, and create output obligations. Knowledge/evidence nodes focus the query, select exact package scope, retrieve a bounded frontier, and admit typed premises. Reasoning chooses and executes a method; independent verification checks its witness. Exceptional edges can enter the failure/result circuit earlier, but they must preserve the specific inability and cannot improvise an answer.

Zoom 3 · direct language and recovery

Parser authority surrounds proposal work

The work-policy gate reserves mandatory parser and safety work first. The English-likelihood gate can reject likely non-English input but never translate it. The direct parser remains the semantic authority, and the request-force gate distinguishes an instruction from an accidentally parseable assertion. Only an eligible failure enters node:runtime:language-proposal-coordinator. Its candidates still pass semantic preservation and parse-only reparse before the interpretation arbiter can select one or preserve ambiguity. The disclosed external Language Agent is another untrusted proposal source outside this deployed circuit, never an answer or proof authority.

Zoom 4 · evidence frontier

Routing establishes coverage before relevance ranks

Focus strategies name entities, predicates, roles, phrases, and metalinguistic topics. The package-scope gate resolves only host-selected packages; the route planner then chooses exact shards and the retriever returns provenance-bearing records plus coverage receipts. The completeness gate prevents a truncated frontier or cache miss from becoming logical absence. Relevance strategies may rank the returned frontier, but the separate evidence-admission gate must still validate premises before capability planning or method execution can use them.

Zoom 5 · coordinator interior

Parallel strategies share work, not authority

The language coordinator validates one immutable input and freezes a finite envelope for every eligible strategy in canonical identity order. Its asynchronous API may start funded independent branches before awaiting them; the deployed local-language path currently uses the sequential API. Each branch returns a typed candidate, a work account, a receipt, confidence:language-interpretation, and its declared correlation:language:… group. Resource spend and concurrency add no confidence. Dependent support collapses, independent validated evidence may contribute separately, and the resulting rank still cannot bypass semantic preservation or reparse.

Zoom 6 · grounded response construction

Admit claims, plan rhetoric, realize sentences, assemble a document

node:runtime:result-construction-coordinator freezes the output contract, eligible evidence, and per-strategy work order. node:runtime:claim-admission-gate accepts only typed, provenance-bound claims and records rejected or unsupported candidates. node:runtime:rhetorical-plan-builder orders obligations into sections through strategy:result:rhetorical-section-planner@1. node:runtime:sentence-realization-coordinator chooses among source-summary, lexical-definition, typed-fact, and defeasible-relation sentence strategies while preserving claim-to-evidence alignment. node:runtime:document-assembly-coordinator then chooses among claim fusion, comparison, coverage-gap, prose, sectioned-document, outline, and table assembly. These strategies realize admitted content; none can manufacture factual support.

Zoom 7 · validation, commit, and emission

A construction candidate still crosses non-voting gates

The witness-verification gate independently replays a method witness and is the only path here with verified answer authority. The grounded response subcircuit may construct already supported content or an explicit typed inability. The schema gate validates the closed result, contributor provenance, and support boundary. The session-commit gate preserves direct acceptance or query-local rollback, and only then does the runtime-result sink emit. On the inability path, separately budgeted failure grounding may attach related evidence only with answerSupported: false.
