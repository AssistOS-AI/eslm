Knowledge Bases / child-basic

Child-level common knowledge

child-basic is a deliberately small educational module: 8 entities, 12 direct facts, 9 rules, and 18 facts after standalone closure. Its purpose is to make ordinary category and mortality examples executable while keeping every premise inspectable.

What it contains

The persistent entities are Earth, Sun, Moon, Solar System, water, ice, tree, and rose. Direct facts classify these entities, locate the first three astronomical objects in the Solar System, and record colorless as the simplified visual property of water and ice. The rules encode man → human, woman → human, boy/girl → child → human, human/plant → living-being, and two consequences of being a living being: it can grow and will eventually die.

The module deliberately calls this elementary rather than complete common sense. It has no age, medicine, accidents, exceptions, explicit negative facts, or time estimate. “Eventually” is a symbolic endpoint used by the supported question form, not a prediction of when a person will die.

Tested commands

node src/cli.mjs ask "Jhon is a man. Is Jhon going to die?" --kb child-basic
node src/cli.mjs ask "Can Tree grow?" --kb child-basic
node src/cli.mjs ask "Where is Moon?" --kb child-basic
node src/cli.mjs ask "What color is water?" --kb child-basic

The first two answers are derived and include rule depth in JSON. The latter two are direct retrieval. Without --kb child-basic, the same Jhon question is still parsed but returns UNKNOWN because the promoted bAbI model has no mortality ontology.

Source and regeneration

The reviewed source is training/KBs/QUICK/source/child-basic.json. Generated code is under training/KBs/QUICK/model/child-basic/. Rebuild it with node src/cli.mjs kb build child-basic and validate it with node src/cli.mjs kb validate child-basic. The source is marked generated educational knowledge and is excluded from benchmark evidence.
