ESLM Documentation / Theory

Current ESLM theory

An ESLM is a compiled language-and-knowledge program. It maps a supported natural-language utterance to an explicit semantic query, executes that query against generated symbolic structures, verifies the evidence, and constructs a response. Its competence is the combined competence of the stable language core and the generated model modules.

1. The representation has distinct layers

Surface text, semantic meaning, stored knowledge, and the final sentence are different objects. Keeping them separate makes errors diagnosable and allows each layer to use the most appropriate representation.

Purpose of this diagram. It shows linguistic compilation. Language analysis normalizes spelling and matches a construction. The semantic query states the intent, predicate, known arguments, requested answer slot, language, and uncertainty policy. Entity and relation identifiers remove accidental wording differences before reasoning begins.

Purpose of this diagram. It shows meaning execution. Generated indexes locate candidate facts. Rules derive only consequences licensed by their premises. Verification requires direct or derived support, so failure to find evidence produces UNKNOWN rather than an invented negative fact.

Purpose of this diagram. It shows response generation. The semantic value is selected before wording. Realization chooses entity labels, an answer construction, list order, epistemic wording, and punctuation. It cannot add facts that are absent from the verified value.

Concrete execution: a held-out bAbI episode

Consider “Mice are afraid of wolves. Gertrude is a mouse. What is Gertrude afraid of?”. The promoted model stores none of these episode-specific claims. It stores constructions and morphology that let the runtime compile the first sentence into a temporary rule and the second into a temporary classification.

  1. splitEpisode separates two statements from the final question.
  2. The statement compiler singularizes mice and wolves, producing (?x, is_a, mouse) → (?x, afraid_of, wolf).
  3. It creates temporary entity gertrude and fact (gertrude, is_a, mouse).
  4. parseQuestion produces { subject: "gertrude", predicate: "afraid_of", target: "value" }.
  5. deriveClosure binds ?x=gertrude and derives (gertrude, afraid_of, wolf) with the rule and classification as proof.
  6. realize returns “Gertrude is afraid of wolf.” while the JSON value remains ["wolf"].

Retrieval alone cannot produce this answer. The result depends on episode segmentation, class morphology, rule compilation, entity identity, unification, answer-slot selection, and deterministic English realization. The same operation succeeds on all 1,000 held-out Task 15 cases; no story answer is stored in the promoted model.

2. Language understanding is bounded compilation

The language core does not claim unrestricted human parsing. It recognizes a declared set of constructions and tolerates controlled surface variation. A construction is useful only when it binds words to typed semantic slots. For example, “Is Mars a planet?” and “Jhon is a man” use the same is_a predicate in question and assertion positions, while “What is Gertrude afraid of?” leaves the value of afraid_of open.

Normalization retains the original input and records every correction. Declared spelling variants are preferred over edit distance. Approximate correction is limited to a controlled vocabulary and must not merge known entities. If several analyses remain plausible, the correct result is AMBIGUOUS or NEEDS_CLARIFICATION, not an arbitrary guess.

Discourse state is explicit input to compilation. The current runtime carries one last-resolved entity for simple pronouns. Richer salience, ellipsis, corrections, and competing referents require future typed discourse modules; they are not hidden inside a chat transcript.

3. The generated code is the learned model

The stable runtime contains algorithms that should transfer between corpora: tokenization, construction matching, query execution, unification, provenance, induction thresholds, abduction mechanics, and realization mechanics. The promoted model contains corpus-conditioned constructions and morphology from bAbI. QUICK contains ordinary entities, facts and rules. WordNet contains sense-aware lemma/taxonomy indexes, while ATOMIC contains relation-directed event continuations. Every module is selected explicitly outside interactive defaults.

Purpose of this diagram. It shows that neither half is a complete model. The core without generated knowledge has algorithms but little content. Generated tables without the core cannot interpret questions or execute rules. Runtime behavior is their deterministic composition.

Generated modules compress repeated structure with stable IDs, canonical predicates, posting lists, shared rules, and reusable constructions. Compression is valid only when claims, qualifications, exceptions, and provenance remain reconstructible. Shorter source that loses semantics is not a better model.

4. Reasoning is proof-producing execution

A fact contains a subject, predicate, object or scalar value, and source provenance. A rule contains positive triple premises and one triple conclusion. Unification binds variables consistently; derived facts record the rule and supporting fact IDs. Duplicate signatures and a round budget guarantee termination for the current rule language.

Deduction produces ordinary supported facts and records proof depth. Induction is deliberately separated: it may propose an allowlisted capability when at least three class members meet a configured coverage threshold, and returns INDUCTIVE with observed support rather than pretending to prove a universal. Abduction reverses only rules explicitly marked abductive and only when the queried observation is itself supported; it returns ranked hypotheses under ABDUCTIVE, never asserted causes.

The inference result is epistemic as well as semantic. ANSWERED means a direct or deductive value has support. INDUCTIVE marks a thresholded generalization. ABDUCTIVE marks possible explanations. UNKNOWN means the query is representable but evidence is insufficient. UNSUPPORTED means no safe construction or executor represents the request. AMBIGUOUS means multiple analyses survive. These outcomes are part of model competence, not error-message decoration.

5. Task Calculus describes executable work

Task Calculus supplies eight semantic operation families: OBSERVE, STRUCTURE, RELATE, REDUCE, DERIVE, CONSTRUCT, VERIFY, and EFFECT. They classify the work performed by training, inference, and evaluation circuits. They do not replace grammar or knowledge representation.

Purpose of this diagram. It shows the central runtime macro, not the entire operator vocabulary. The input is structured into a query, entities are related to indexed knowledge, consequences are derived, and support is verified. Response realization is a subsequent CONSTRUCT operation.

Control operators such as THEN, ALL, CHOOSE, EACH, UNTIL, BEAM, MEMO, and COMPENSATE describe how operations compose. Only controls with implemented executors may appear in an executable circuit. A missing capability remains explicit; runtime never delegates it to an undeclared external model.

For the Gertrude episode, STRUCTURE segments statements and compiles typed triples; RELATE resolves the individual against the temporary world; DERIVE instantiates the fear rule; VERIFY requires the classification and rule in the proof; and CONSTRUCT realizes the semantic value. OBSERVE reads the supplied episode and promoted morphology. REDUCE narrows predicate and subject postings. No EFFECT occurs because inference does not modify a generated module.

6. Training is evidence-bounded program synthesis

Purpose of this diagram. It shows the complete authority boundary. The packet contains only agent-visible training evidence and its hashes. The coding agent generates a candidate model in an isolated directory. Validation checks capabilities, schema, references, indexes, provenance, and representative training-only probes before review.

The agent groups repeated evidence into symbols and executable modules. Direct assertions remain distinct from deterministic consequences and tentative induction. A rule requires repeated support or an explicit source rule. Hidden evaluation labels never enter synthesis. A failed benchmark cannot be copied into the model while retaining the same held-out claim.

7. The theory is falsifiable

The approach is useful only if generated modules generalize beyond source wording. Evaluation therefore varies spelling, paraphrase, unseen entity names, distractors, relation direction, composition depth, temporal length, ambiguity, and missing evidence. It also measures model bytes, synthesis cost, import time, query latency, trace correctness, and abstention.

The hypothesis weakens if model source grows approximately one branch per example, if small paraphrases destroy coverage, if hidden labels are required, if proof traces do not match the actual support, or if an evidence-matched external model is consistently better without losing verification, replay, or efficiency.

8. Current implementation boundary

The implemented system covers short English factual queries, controlled spelling tolerance, one-step discourse, session learning, indexed facts, bounded deduction, thresholded induction, guarded abduction, explicit provenance, deterministic realization, batch automation and a 1,000-case Task 15 result. QUICK supplies 62 direct facts and 14 rules; WordNet supplies 107,519 synsets and lexical taxonomy; ATOMIC supplies 940,427 train-derived defeasible tuples. Contextual sense disambiguation, general event-role binding, explicit negation, calibrated defaults/exceptions, conflict representation, narrative schemas, temporal worlds and broad factual coverage remain research work.
