Qualified reasoning through defaults, induction, and abduction

Incomplete worlds require conclusions weaker than theoremhood. ESLM separates three such operations: configured induction generalizes a recurring property, guarded abduction proposes premises that could explain an observation, and preferred entailment asks what holds in every best finite model under explicit default priorities.

Evidence and an explicit policy jointly produce hypotheses or preferred models. The result records alternatives, counterevidence, and the weaker epistemic status; it is never inserted as an unqualified source fact.

Why non-monotonicity matters

Strict deduction is monotonic: adding premises cannot invalidate an already entailed conclusion. A default such as “birds normally fly” behaves differently because evidence that an individual is a penguin can defeat the earlier conclusion. Raymond Reiter formalized this family in A Logic for Default Reasoning. Kraus, Lehmann, and Magidor developed a preferential account in Nonmonotonic Reasoning, Preferential Models and Cumulative Logics. ESLM implements neither formalism wholesale; it implements one finite prioritized preferred-model policy and names that difference.

Configured induction

The induction executor first groups explicit is_a membership facts by class. For each predicate allowed by the KB policy, it counts distinct class members supporting each value. Coverage is supportCount / populationCount. A candidate survives only when both minSupport and minCoverage hold. A selection mode can retain all qualifying values or select the value supported by the latest relevant observation under a declared source-local convention.

policy = {
  predicate: "surface_color",
  minSupport: 3,
  minCoverage: 0.75,
  selection: "all"
}

The resulting record contains the class, predicate, value, population, supporting members, counterexample count, selection policy, and confidence ratio. It is marked reasoning: induction. This method does not infer that arbitrary classes share observed properties, and the core does not contain a special branch for “color.” The predicate and value domain are package data. Alpha-renaming the predicate and all values must preserve the computation.

Guarded abduction

Abduction asks for a hypothesis that, together with a rule, would account for an observation. ESLM considers only rules explicitly marked abductive: true. It unifies the observed query with the rule head, instantiates the body, separates already supported from missing premises, and scores a bounded candidate from the supported-to-total premise ratio. The witness retains the observation, rule source, substitution, supported facts, and proposed premises.

This implements a narrow form of abductive reasoning. It does not search arbitrary causal graphs, invent unseen entities, or assert the highest-scoring explanation. A result says “this premise would explain the observation under this reviewed rule,” not “this premise occurred.” Competing explanations remain visible.

Skeptical preferred entailment

The preferred-model method receives strict premises, defaults of the form antecedent/consequent/priority, and a query. It enumerates every strict-premise model. For each priority level from highest to lowest, it counts defaults whose antecedent is true and consequent false. These counts form a penalty vector. Lexicographic comparison makes one violation at a higher priority dominate any number of violations at lower priorities.

All models with the minimum vector are retained. If every preferred model satisfies the query, it is skeptically true. If none does, it is skeptically false. If preferred models disagree, the result is UNDERDETERMINED. Source order cannot break the tie. The witness records priority order, best penalty, preferred-model count, and representative supporting or defeating assignments.

This design is useful because its policy is explicit and executable. It is also limited. Specificity is not automatically inferred, default priorities must come from reviewed metadata, and the algorithm remains exponential in the bounded atom set. Rational closure, Reiter extensions, argumentation semantics, probabilistic defaults, and answer-set programming would require distinct methods and comparison tests. See the overview of non-monotonic logic and default logic for the wider field.

Isolated typed-evidence comparison

compareTypedEvidence is an implemented but deliberately unregistered research primitive. Its input contains two through thirty-two opaque alternatives, at most 2,048 evidence records, and a policy with an integer minimum margin and optional integer weights for the causal, contradiction, default, goal, participant, state, and temporal families. Every evidence record names one alternative, support or attack direction, bounded strength, semantic family, and provenance triple {origin, relation, sourceRef}. The comparator never derives those records; their semantic validity is a precondition owned by a source compiler or KB provider.

For each record e, the signed contribution is strength(e) × familyWeight(e), positive for support and negative for attack. Alternative scores are sums of their contributions. Evidence and alternative order are normalized before ranking. No evidence, an exact tie, or a best-versus-second margin below policy returns UNKNOWN. Otherwise the result is DEFEASIBLE and contains the selected opaque identifier, ranked signed contributions, evidence count, required and observed margins, and a SHA-256 digest of normalized evidence. verifyTypedEvidenceComparison recomputes the complete result and rejects a changed ranking, value, margin, provenance digest, or witness kind.

deriveFramePairEvidence is a narrower experimental producer. It can emit state or causal support for exact typed content and predicate overlap, contradiction attacks when overlapping frames reverse polarity, and optional participant-continuity support. These relations are useful structural signals but do not establish real-world causes, goals, norms, defaults, or event consequences. Complete Defeasible NLI and αNLI development experiments showed that overlap alone is below or near chance on answered binary cases. The producer is therefore not registered in the runtime and its outputs are not promoted into a KB. A future provider must supply independently grounded semantic relations before the comparator can become an operational method.

Review criteria

A default or induction patch fails review if it becomes strict in the result, learns priority from answer frequency, changes under insertion order, suppresses equally preferred alternatives, or ignores counterevidence. An abductive patch fails if it returns a hypothesis without an authorized rule, treats possibility as truth, or uses the expected answer to rank explanations. The normative details are in DS015.
