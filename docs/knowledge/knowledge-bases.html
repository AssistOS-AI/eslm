Canonical records, deterministic packages, catalogs, routing, and trust

Knowledge packages occupy the data plane of ESLM's processing graph. They carry inert canonical terms, claims, rules, contexts, policies, indexes, and provenance. Trusted compiler, catalog, routing, retrieval, and projection nodes validate and transform that data; a package never supplies a processing strategy, executable path, or authority gate.

The logical processing architecture explains where focus, retrieval, evidence assessment, reasoning, and verification consume this data. This chapter zooms into the canonical record and package contracts. Physical file locations appear only in the package-layout reference below.

The canonical record model

The record vocabulary includes source and provenance records; contexts; terms and lexemes; assertions; rules; mappings; and, as later capabilities require them, events, temporal relations, modalities, trust statements, defaults, exceptions, and method-support metadata. Each record has a stable identifier and a declared type. References use identifiers rather than embedding executable expressions. Canonical JSONL is convenient for streaming, review, diffs, and deterministic recompilation.

Provenance is part of meaning. An assertion identifies the provenance records supporting it. Provenance points to a frozen source, document location, extraction method, and confidence or trust information where available. A rule identifies why it is licensed and its scope. A record without required provenance is invalid even if its content happens to be true.

Compilation is a security and reproducibility boundary

Validation checks record shapes, references, provenance, and rule safety before deterministic JSON is written. Registration then rechecks the immutable package, one bounded shard at a time, before catalog admission.

Validation occurs at several levels. Record validation rejects an unknown type or malformed field. Graph validation rejects dangling identifiers and missing provenance. Logical validation rejects unsafe rules and unsupported operator shapes. Generic package registration accepts only the manifest, shard directory, real segments/ directory, and declared regular segment files. It verifies checksums, byte and record counts, record namespaces, the complete local cross-shard reference graph, and per-record structural limits. Its receipt reports bounded identity/reference entries and UTF-8 bytes together with observed JSON maxima. A build report records counts and source hashes but cannot substitute for these checks.

Compilation does not “improve” source claims by inventing missing facts. It normalizes, indexes, and partitions accepted records. Source-specific adapters may preserve compact formats when converting a huge resource into the full canonical form would add unacceptable size or latency, but those formats remain declarative and their semantics are documented and tested.

The processing-node strategy architecture preserves the same boundary while making source and runtime techniques selectable. A package may declare exact compatibility with a reviewed strategy identity in a schema-owned field, but it cannot register an executor, provide an import path, alter an arbiter, increase a resource budget, or disable validation. The host profile remains authoritative. Compiler-side source strategies can specialize decoding, extraction, identity resolution, and standardization for manuals, ontologies, lexical resources, event graphs, or tables, but every route still produces untrusted canonical candidates before the shared validators and explicit promotion gate. See Processing-node strategies for the registry and compiler-stage contract.

The small quick package follows the complete canonical path and is used for deterministic smoke tests. Its canonical data includes provenance, terms, lexemes, facts, a context, and safe rules. The babi-v1.2-language package uses the same path for three records: one provenance record, one color-domain constraint, and one explicit color-induction policy. clutrr-kinship-algebra also uses the generic compiler; its constraint record declares relation classes, endpoint features, reciprocal inverses, and compositions interpreted by trusted code. Open English WordNet, ATOMIC, GeoNames, and ConceptNet are rebuilt from cached immutable archives into provider-specific JSON shards. world-relations-1.0 compiles one reviewed declarative ontology document. Every payload remains JSON data rather than executable program code.

Catalogs and composition

A generic catalog entry binds a logical KB identifier and stable semantic version to the exact manifest, shard directory, canonical-source and compiler identities, package digest, namespace, trust level, and dependency resolutions accepted at registration. Re-registering byte-identical package content is idempotent; another package with the same KB ID or namespace cannot replace it. Selection is explicit through CLI options or runtime configuration. Composing packages preserves each source's authority through attached provenance and context. The next projector gate adds context inheritance and a general trust-conflict policy; load order never substitutes for either one.

The runtime first orders selected immutable package projections by manifest identity. It preserves canonical order inside each package, builds stable manifest and index arrays, and sorts returned values and evidence. Reversing the CLI package list therefore does not reverse the answer or select different provenance. Two projected facts are duplicates only when subject, predicate, object-versus-value kind, polarity, epistemic status, confidence, validity, and context are all equal. Exact duplicates combine every package identity and provenance reference; a qualifier difference keeps two reviewable claims. Session observations are appended afterward in episode order, so an explicitly declared latest-support or latest-member induction policy still sees the real conversation chronology.

The base core has no domain assertions. Selecting quick supplies its small development vocabulary. Selecting babi-v1.2-language supplies the training-visible Task 16 color domain and source-local induction controls but no benchmark answer. Selecting clutrr-kinship-algebra supplies a relation policy but no family graph or classification label. Selecting oewn-2025 supplies lexical senses, glosses, and relations. Selecting atomic-2020 supplies defeasible event-centered commonsense tuples. geonames-2026 supplies frozen country and populated-place facts. conceptnet-5.7.0-en supplies typed everyday relation edges. world-relations-1.0 supplies reviewed construction-to-frame and compatibility policy. These resources answer different kinds of questions and must not be presented as one homogeneous truth store.

The bAbI package demonstrates why policy sometimes belongs with source semantics rather than hard-coded in the core. The core knows how to compute a class-property induction candidate, coverage, confidence, and selection. It does not assume that colors are inductive, which values are in scope, or how the benchmark resolves competing observations. Those choices are declared by the package, remain provenance-bearing and defeasible, and disappear when the package is not selected.

Query-directed loading

The loader derives conservative routing keys from the normalized query. A WordNet definition request routes by lemma and then loads the synset shards named by the lemma index. An ATOMIC question routes by normalized event key. GeoNames first resolves a normalized country name in its compact country index or a place name in a letter bucket, then opens only the stable identifier buckets required for all matching places. ConceptNet combines relation, direction, and normalized concept prefix; forward and reverse indexes are distinct so an inverse query does not require scanning unrelated edges. Generic canonical packages may route by entity, predicate, lexical form, or declared index. Each selected shard is checked against the manifest before decoding.

The cache bounds resident shard data according to the runtime memory plan. It records hits, misses, loads, evictions, and bytes. Eager mode remains useful for small packages and controlled measurements; lazy mode is the normal path for large sources. Tests compare eager and lazy semantic answers on randomized samples so performance work cannot silently change meaning. A memory target changes loading and retention, never the logical source inventory: valid source rows remain in the frozen archive. If a build layout is too large, the compiler streams or emits finer shards. If a reviewed compiler profile does not yet interpret a language or relation family, the probe records that coverage gap explicitly so a later package version can widen the projection from the same source.

How the three new public knowledge paths differ

GeoNames is factual and mostly exact. A country property or place-country relation is returned as SOLVED from a frozen source record, with ambiguity when the same normalized place name identifies several records. ATOMIC tuple answers are always DEFEASIBLE. ConceptNet is relational and heterogeneous: relations marked defeasible-edge, such as purpose, capability, location, property, causation, and motivation, return DEFEASIBLE; reviewed strict relations return SOLVED. Weights remain evidence rather than universal laws. If strict and defeasible providers agree on a value, merging retains DEFEASIBLE. World Relations is authored semantic policy rather than a public fact dump. Combining these sources retains the origin and strength of each premise.

Compilation preserves those differences. GeoNames validates the country table and ZIP member schema before building indexes. ConceptNet performs a full streaming probe over the complete frozen archive, projects English endpoints and relations through an explicit semantic profile, reports valid rows outside that profile, deduplicates equal normalized edges, and keeps compact source references instead of retaining the decoded archive in memory. This projection boundary exists because only reviewed relation meanings can enter executable reasoning, not because the source is too large; physical size is handled by relation-and-prefix shards. World Relations validates a bounded ontology schema and construction budget, then copies only the validated declarative object into its package. Eager and lazy modes are compared where both exist, and package validation checks every referenced shard hash.

Separation between benchmark caches, adapters, and KBs

BLiMP, bAbI, CLUTRR, Entity Tracking, EWoK, Story Cloze, and SimpleQA artifacts use an ignored immutable-source cache for reproducible adapters and probes. Their labels remain in host-only oracles according to split policy. A benchmark archive does not become runtime knowledge merely because it is local, and a cached test answer must never be compiled into a package. The exact cache location is an operator concern documented in the CLI reference.

Entity Tracking is an especially clear boundary. Its adapter validates a source row, removes the masked span from the visible task, and calls the generic container-state executor. The expected span is joined only by the scorer. No Entity Tracking package is loaded, because the task supplies its complete temporary world and asks the runtime to execute state transitions. Conversely, the bAbI language package is legitimate KB data because it declares reusable source-level vocabulary and induction semantics without storing case answers.

Separation between normalization cache and knowledge

The Language Agent normalizer uses a separate ignored cache keyed by original-input digest, exact model, reasoning effort, prompt policy, response protocol, validator version, and normalization policy. An entry stores untrusted normalized language, validation evidence, and a bounded process receipt. It cannot be registered as a KB, cannot satisfy a factual query, and cannot acquire direct-symbolic attribution. Reusing it avoids an external call but still records the assisted language route.

What a reviewer verifies

For an extraction change, compare frozen source hash, split visibility, assignment packet, candidate records, rejected evidence, and extraction coverage. For a compiler change, compile the same records twice and compare bytes and manifests, then exercise malformed paths, hashes, references, rules, and constraint policies. For a runtime change, verify catalog allowlisting, eager/lazy equivalence, cache budgets, provenance in answers, and deliberate gaps for absent content. For a benchmark integration, verify that source caches, visible tasks, host-only oracles, and promoted KB data remain separate artifacts.
