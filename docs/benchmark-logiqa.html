LogiQA: expert-authored deductive reading comprehension

LogiQA contains examination-style passages, questions, and four physical answer slots in English and Chinese. It requires a reader to recover constraints and argument structure from prose, then prove which candidate satisfies the question. ESLM currently validates and isolates the source correctly but has no registered method authorized to choose an answer.

Complete English development execution

The pinned source contains 17,356 physical records: 8,678 semantic cases in English and the parallel 8,678 in Chinese. For each language there are 7,376 train, 651 development, and 651 test records. All six source files are retained. Train and development are streamed record by record; the two test files remain unopened and are identified only by bytes and digests.

The latest profile executes English only. All 651 English development tasks reached the capability registry and all returned NO_APPLICABLE_METHOD. The dashboard therefore presents full task coverage with no score, not a misleading 0%. The 651 Chinese development cases remain preserved and validated outside this profile; they are not discarded or counted as failures. No Language Agent call occurred.

Physical answer slots and anomalies

Each source record occupies eight physical lines: a separator, one answer letter, passage, question, and four answer slots. Some visible answer strings have swapped, missing, lower-case, full-width, or punctuation-variant A/B/C/D prefixes. The official README defines the physical lines as the alternatives, so the adapter records prefixes as presentation anomalies and never lets them reorder the slots or alter label semantics. The host-only oracle joins the answer letter only after predictions exist.

What must be implemented

Like ReClor, LogiQA needs a reusable compiler from prose to quantified, conditional, ordering, exclusivity, and argumentative constraints. The method must represent the question's modality, test each candidate under the same theory, and return a proof, countermodel, or explicit unresolved status. It must pass candidate permutation, full vocabulary renaming, premise-order, and meaning-changing contrast tests before the sealed test files may be opened. Translation of the Chinese track is a separate measured language route and cannot substitute for this reasoning method.

The implemented research candidate covers a narrower, mathematically explicit fragment: monadic categorical propositions and necessary-conclusion or sufficient-premise selection. It proves a qualifying option by contradiction and supplies a finite countermodel for every nonqualifying option. The executor itself is generic and passes nonce renaming, candidate permutation, semantic reversal, and independent witness replay.

It is not registered because the strict English projection found no complete development-visible LogiQA task inside that fragment. Recognizable question operators still led to relational, conditional, cardinality, ordering, or compound-candidate semantics. One training case reached candidate parsing, but at least one option remained outside the fragment; executing only the parsed options would change uniqueness. The safe next step is to add those semantic families with their own proof contracts, then require multiple independent complete source cases before reconsidering promotion.

Source and rights

The exact official repository revision appears in the source registry. The repository provides data and citation but no dataset LICENSE, so ESLM retains a local academic-research cache and does not redistribute rows pending clarification. Cite Jian Liu, Leyang Cui, Hanmeng Liu, Dandan Huang, Yile Wang, and Yue Zhang, LogiQA: A Challenge Dataset for Machine Reading Comprehension with Logical Reasoning, IJCAI 2020.
