ZebraLogic: finite-domain constraints, complete assignments, and uniqueness

ZebraLogic presents logic-grid puzzles whose clues constrain which value from each domain occupies each ordered position. ESLM's public-clue track compiles those clues into a finite-domain constraint problem and accepts an answer only when the complete assignment satisfies every clue and a second search proves that no different assignment exists.

Current measurements: Read the generated ZebraLogic row on the evaluation dashboard or inspect the raw v2 report. Public-clue completion, parse failures, and receipt currentness are not hardcoded here.

The output is constructive. Solving, direct clue replay, and the blocked-assignment uniqueness check are separate stages.

Constraint semantics

For every value and position, the adapter creates a Boolean proposition saying that the value occupies that position. Exactly-one clauses enforce that every value occupies one position and every position receives one value from each domain. A direct-position clue selects one position; an exclusion clue removes one; same-position clues equate positions across domains; left, right, adjacency, direct-left, and exact-distance clues constrain ordered position pairs. Unknown wording is a parse failure. It is never ignored, guessed from a row identifier, or replaced with an answer-derived condition.

The generic scalable Boolean method knows variables, clauses, assignments, and conflicts, but no ZebraLogic field names or clue words. After it finds an assignment, an independent interpreter evaluates every typed clue directly. The verifier then adds one clause that blocks the entire assignment and reruns the solver. An unsatisfiability certificate for that blocked system establishes uniqueness. This is the finite-domain constraint satisfaction model; the search layer uses the documented DPLL procedure.

Source and partition boundary

The pinned public release contains 1,000 grid puzzles and 3,259 multiple-choice rows. All 4,259 rows are retained; none is rejected because of file or dataset size. The public grid assignments are redacted and the multiple-choice rows omit their answers. The 1,000 public grid puzzles were partitioned by their declared row-by-column size before text inspection: eight development members and thirty-two sealed members in each of twenty-five size strata, producing 200 development and 800 fresh puzzles.

A protected execution may begin only after the adapter, parser, solver dependencies, verifier, tests, source identity, and partition are frozen. It returns aggregates only: no protected clue, identifier, assignment, certificate, or per-case outcome may become tuning input. The report owns the executed count, completion count, failure statuses, Language Agent policy, and checkpoint classification.

Evidence scope of public-clue completion

Public-clue CSP completion says whether ESLM constructed and verified the unique solution implied by visible clues. It does not compare cells against the private official assignments. Therefore it is symbolic-method evidence, but it is not ZebraLogic leaderboard accuracy or cell accuracy. The dashboard labels completion separately and leaves correctness metrics null when the oracle is unavailable.

Official-label comparison requires access to ZebraLogicBench-private. An authorized operator must accept its terms, authenticate locally, and reacquire the pinned private revision recorded in the source manifest. The public and private dataset cards declare no dataset license; local research cache is retained, while redistribution requires clarification from the publisher.

Source and claim record

The public dataset revision, ZeroEval code revision, artifact identities, exact split commitment, and aggregate-only receipt are recorded in the source registry and secondary machine-readable manifests. The benchmark paper is ZebraLogic: On the Scaling Limits of LLMs for Logical Reasoning. The paper describes the generator, but neither it, the dataset card, nor the pinned evaluation repository exposes the generator implementation; documentation does not claim otherwise.
