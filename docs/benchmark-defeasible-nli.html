Defeasible NLI: whether new information strengthens or weakens an inference

Defeasible NLI does not ask whether a hypothesis follows deductively. It starts with a plausible premise-to-hypothesis inference, adds an update, and asks whether that update makes the inference more or less plausible. The correct symbolic target is a comparison between two defeasible support states, not a hard-coded word classifier.

Current measurements: Read the generated Defeasible NLI row on the evaluation dashboard or inspect the raw v2 report. This page retains official source eligibility and scoring semantics, not mutable execution totals.

Source and official eligibility

The official release combines three upstream families: ATOMIC event inferences, SNLI premise–hypothesis pairs, and Social Chemistry situations and norms. ESLM pins one immutable release, streams all nine train/development/test files, validates closed family-specific schemas, and retains all 245,720 rows. No row is rejected because of source or file size.

The release marks some proposed updates as impossible. Those rows remain frozen and countable, but the paper protocol excludes them from classification scoring. The official development split has 16,008 source rows: 14,968 are eligible and 1,040 are marked impossible. An execution report must distinguish that source eligibility denominator from the number actually tested. The official test split remains outside the public loader.

Typed task and oracle boundary

The adapter preserves the premise or social situation, hypothesis, update, source family, and requested comparison as visible input. UpdateType, impossible status, impossible reason, and worker metadata do not enter the task seen by a candidate method. The host joins the strengthener/weakener oracle only after a prediction exists. Schema validation also preserves the differences among the three families rather than flattening ATOMIC relations, SNLI pairs, and social norms into one untyped string.

How to score inability on this forced-choice task

Each eligible update requires an in-domain strengthener or weakener prediction. If a non-empty evaluated pool receives no predictions, end-to-end accuracy and attempt coverage are both 0%, while selective accuracy is null. NO_APPLICABLE_METHOD diagnoses why a case was not attempted; it does not remove the case from the fixed denominator or imply that the opposite label was selected.

The missing work begins before ranking. Arbitrary prose must become event roles, causal and physical effects, social or normative defaults, exceptions, and signed evidence with source provenance. Only then can a generic method compute preferred models or support sets before and after the update and compare them. Implementing a lexical sentiment rule or memorizing frequent update phrases would skip the semantic boundary and fail the required full-renaming tests.

A standalone comparator can accept explicit provenance-bearing support and attack records, apply declared family weights, verify its witness, and abstain on missing evidence, ties, or insufficient margins. An adapter-local overlap projection is only an experiment until it demonstrates adequate end-to-end accuracy and generality. The generated report, not this page, records any executed experimental coverage and outcome.

Required generic candidate

A valid candidate must define a typed base theory Γ, an update Δ, a query hypothesis h, and a source-declared default policy. It must compute support for h under Γ and under Γ∪{Δ}, preserve conflicts rather than overwrite them, and return a witness naming the defaults activated, defeated, or newly contradicted. “Strengthener” requires a declared improvement in the preferred-support order; “weakener” requires a declared decrease. Ties and incomparable revisions require an explicit abstention status.

Acceptance requires nonce event and norm vocabularies, complete participant renaming, premise/update reordering where semantics permits it, polarity and causal-direction contrasts, provider-order invariance, and an independent witness verifier. The defaults and abduction chapter explains the currently implemented preferred-model and guarded-abduction foundations; neither yet constitutes this full update-comparison method.
