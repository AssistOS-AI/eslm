ESLM Documentation / Datasets

Evaluation suites and diagnostic datasets

bAbI, BLiMP, CLUTRR, and similar suites ask controlled questions with known answers. They expose parser and reasoning failures but are not automatically persistent world knowledge. WordNet and ATOMIC are now built as separate source KBs; filtered ConceptNet and bounded GeoNames remain next, while Wikidata is future and thematic only.

Why this distinction matters

Training a KB directly on a public benchmark's answers makes later performance on that benchmark difficult or impossible to interpret. ESLM may inspect an official train split to synthesize a task compiler, while the test split stays hidden. When an evaluation was derived from a source graph that ESLM has ingested—for example, a commonsense benchmark built from ConceptNet—the report must mark that exposure and cannot present the result as independent factual generalization.

The real knowledge sources page describes persistent corpus-derived modules. This page records evaluation adapters, split isolation, and controlled executor exercises.

Every row has 10,000 train cases and 1,000 test cases. Prepared JSONL is larger than raw text because it preserves context, question, semantic answer, support-line identifiers, supporting sentences, split, and stable case ID. The public files are cached locally and ignored by Git. Exact integrity hashes remain in machine-readable manifests rather than cluttering this explanatory page.

“Prepared” means that the official text was parsed and isolated into train and test artifacts; it does not mean that ESLM learned the task. Tasks 15 and 16 passed later learning, promotion, and evaluation gates; Tasks 2 and 3 did not. The public benchmark ledger is the authoritative human-readable record of which suites were actually run.

Task 15: basic deduction — completed

A train episode contains class rules, individual classifications, and fear questions. Example: “Mice are afraid of wolves. Gertrude is a mouse. What is Gertrude afraid of?” The agent found 40,000 classification statements and 40,000 universal-rule observations. It generated three constructions and four irregular class forms, not a table of answers.

The promoted model was produced by one primary coding agent, validated, and run on 1,000 held-out cases. It answered all 1,000 semantic values correctly. The task tests only one-step class-rule deduction in controlled English.

node src/cli.mjs dataset status --dataset babi-15-en-10k-v1.2
npm run benchmark

Task 2: two supporting facts — prepared

Stories move people between locations and let them pick up or drop objects. A question such as “Where is the football?” may require the object's ownership event and the owner's later movement. The needed model is an event-state executor: location updates, possession updates, transfer of an object's effective location with its carrier, and distractor resistance.

The 10,000 train and 1,000 test cases are parsed into separate files. A 20-chunk ledger and four-worker assignment plan exist. No coding-agent worker result, reduced evidence graph, candidate model, promotion, or test score exists yet.

node src/cli.mjs dataset status --dataset babi-2-en-10k-v1.2

Task 3: three supporting facts — prepared

This task asks for a previous object location, for example “Where was the football before the bathroom?”. Correct execution must retain ordered state versions rather than only the final location. A typical proof combines object pickup, movement to one place, and later movement to another place.

The raw train file is substantially larger because episodes carry longer histories. Its 10,000 train cases are in 20 chunks and have a four-worker plan. ESLM does not yet have the temporal state-version executor required to synthesize a valid model, so no evaluation has run.

node src/cli.mjs dataset status --dataset babi-3-en-10k-v1.2

Task 16: basic induction — completed

A train episode may classify Lily and Bernhard as frogs, state that both are green, classify Greg as a swan, and show another green swan. The question “What color is Greg?” requires inferring a class-level color pattern from other members and applying it to Greg. This differs from the current optional core induction query because the benchmark expects an ordinary answer under its own evidence rules.

The benchmark-guided cycle began at 0/200 working and 0/1,000 fresh cases because typed property statements were unsupported. A first latest-member candidate reached 196/200 and 996/1,000 but failed proof audit and was rejected. The accepted candidate retains typed colors, complete membership supports, conflicts and configured latest-member ranking. It passed 200/200 working, 1,000/1,000 fresh, 1,000/1,000 aggregate-only official test cases, 52/52 prior regressions and three ordering/nonce metamorphic cases.

node src/cli.mjs dataset status --dataset babi-16-en-10k-v1.2
