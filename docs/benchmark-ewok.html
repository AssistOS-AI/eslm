EWoK: world-knowledge plausibility preferences

EWoK asks whether a target statement is more plausible in one context than in an alternative context. Its domains include physical, spatial, material, quantitative, social, and agent knowledge. The task probes whether the system can connect ordinary relations and properties rather than merely parse the target sentence.

Current measurements: Read the generated EWoK rows on the evaluation dashboard or inspect the raw v2 report. Development and one-shot receipt outcomes are not copied into this protocol page.

The same target is evaluated against both contexts through the same symbolic compatibility method. The evaluator observes only which context receives the higher score.

How ESLM represents the comparison

The adapter constructs two context-target comparisons without exposing the preferred context to the runtime. Provider-neutral compatibility code derives signed evidence from typed proposition frames, relation direction, polarity, implications, changes, comparisons, affordances, and declarative world knowledge. world-relations-1.0 supplies reviewed semantic constructions and ConceptNet may supply independent relational evidence. Neither package contains protected EWoK rows or expected choices.

ESLM protocol and evidence regime

Each retained source item yields two correlated directional decisions. Both decisions stay in the same split group and statistical unit so a reversal of one source item cannot leak across development and protected evidence. The source receipt records explicit exclusions and the full eligible inventory. The generated execution row records which partition was actually scored, its behavior digest, and whether a one-shot receipt is current or historical.

This is ESLM's deterministic scalar-preference diagnostic. It is not the benchmark's official language-model probability protocol, so its percentage must not be placed on an official leaderboard as if the procedures were equivalent.

Correct, reversed, tied, and “ties fail”

Correct means the expected context received a strictly higher compatibility score for the target. Reversed means the alternative context received the higher score. Tied means both contexts received the same score, usually because the ontology or evidence providers could not distinguish them. Ties fail means equal scores receive no point under forced preference scoring. A high tie count diagnoses missing discriminating knowledge or a missing semantic construction; it is not evidence that the parser rejected the text.

How to interpret development and fresh rows

A development score shows only how the declared ontology and providers behave on visible examples. A one-shot fresh score describes the exact frozen behavior digest that was evaluated; it does not automatically transfer to later code. Once its oracle is opened, that partition cannot be used repeatedly for repairs while retaining the word “fresh.” The dashboard's checkpoint label tells the reader whether a receipt still describes the current implementation.
