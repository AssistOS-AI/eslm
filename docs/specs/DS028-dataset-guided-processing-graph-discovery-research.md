# DS028 Dataset-Guided Processing-Graph Discovery Research

## Introduction

ESLM needs a repeatable way to discover missing processing-node types, alternative node strategies, authority gates,
protocol fields, and placements in the typed request graph. Public task, preference, reasoning, and interaction datasets
contain useful evidence about recurring obligations and failure boundaries, but they do not define the architecture and
must never become executable control flow. This specification establishes a legally reviewable, contamination-aware,
bounded research program that turns frozen training-visible evidence into falsifiable architectural hypotheses.

The repository now contains the research-side source registry, inert episode schema, pre-analysis discovery plans,
bounded streaming analyzer, correlation-aware hypothesis coordinator, source-local projections, machine analyses,
human consolidation reviews, closed discovery-cycle receipts, and the maintenance skill needed to execute this
program. It does not contain a learned controller, an RL policy, automatic promotion, or a claim that the resulting
hypotheses are necessary architecture. The intended promoted output remains deterministic symbolic machinery that
passes the existing parser, schema, reasoning, witness, safety, and promotion gates. A dataset row, reward,
trajectory, model response, or discovered cluster never becomes runtime truth merely because it is frequent or highly
rated. DS029 owns the concrete processing-circuit catalog against which every hypothesis is consolidated.

## Core Content

### Research question and non-goals

The program asks which stable typed responsibility is missing from the current graph, which existing node needs another
implementation strategy, where an authoritative check belongs, which named envelope is underspecified, and which edge
or resource boundary makes failures inspectable. It studies reusable task structure across renamed domains rather than
copying successful answers or action sequences.

The program does not train an executable policy, imitate a model trajectory, optimize against a protected evaluator,
compile conversations into domain truth, or let source-selected code run. It does not infer that majority preference is
factual correctness, that a successful final answer validates every intermediate step, or that one benchmark's tool
schema belongs in the generic core. “RL dataset” describes upstream evidence shape; it does not grant a reinforcement-
learning component authority inside ESLM.

### Five authority lanes

Research bytes and outputs remain in five lanes with explicit, one-way promotion gates:

1. **Immutable source registry and raw cache.** A DS016 manifest freezes official origin, revision, delivered files,
   digests, access terms, component licenses, citation, redistribution boundary, and removal obligations. Raw bytes are
   untrusted and inert. Project-owned readers parse them without executing upstream loaders, scripts, environments,
   serialized objects, templates, or commands.
2. **Analysis and training projection.** Only rights-cleared, training-visible fields enter the research projection.
   Projection losses, excluded components, safety transformations, and source links remain explicit. A research
   analysis or isolated Coding Agent sees only that bounded projection and cannot mutate the source registry.
3. **Benchmark and test visibility.** Development, regression, fresh, shadow, gated, and test pools retain DS017
   isolation. Hidden labels and protected rows never enter clustering, hypothesis generation, prompt packets, examples,
   or generic-core proposals. A source used for discovery cannot later be described as unseen evaluation evidence for
   the same behavior.
4. **Knowledge extraction.** A source proposition may enter a KB candidate only through a separately authorized DS005,
   DS014, DS016, and DS018–DS021 pipeline. Task instructions, model answers, preferences, rewards, tool calls, and
   trajectory outcomes are not facts by default. Architecture research does not silently construct runtime knowledge.
5. **Generic-core proposal.** A node, gate, strategy, edge, or protocol-field hypothesis is an untrusted design
   candidate. It receives no executor or default profile until manual contract review, deterministic implementation,
   independent gates, metamorphic tests, ablation, transfer evidence, and explicit promotion succeed.

No cache key, directory move, aggregate vote, or agent output crosses these lanes. Every crossing produces a typed
receipt that names the source scope, visibility, transformation, reviewer authority, and resulting artifact identity.

### Frozen source and rights registry

Every research source receives a registry entry before acquisition or analysis. In addition to the DS016 manifest, the
entry records each component's rights independently: task definitions, instances, model outputs, human ratings,
attachments, web snapshots, environment state, tool documentation, evaluator code, and labels may have different
owners and terms. Repository-level licensing is not assumed to cover embedded upstream datasets. A source revision is
re-reviewed when its files, license, access gate, hosted card, or upstream lineage changes.

The current ingress contract is `eslm-rl-dataset-source-manifest-v2`. It content-binds delivered source,
split-authority, license, and metadata files; records the immutable acquisition and cache policy; and carries a
source identity file plus component-local identity and supporting-file references. The referenced identity bytes,
media type, and digest must equal the corresponding source or component identity; supporting files remain distinct
inputs, such as a frozen split-membership authority, rather than being hidden inside an aggregate assertion. It carries a
revision-bound repository-policy rights review with explicit limitations. A label such as `pilot-approved` or
`approved` is insufficient by itself. The source-admission node validates the complete manifest before it constructs
the narrower research registry, and live status repeats that validation so current rights govern historical receipts.

The registry assigns one of `pilot-approved`, `next-candidate`, `evaluation-only`, `rights-review`, `excluded`, or
`tombstoned`. `pilot-approved` still authorizes only the exact declared projection. A tombstone records the removed
digest, reason, affected projections, derived hypotheses, purge receipt, and whether already published aggregate
evidence must be withdrawn. Raw, projected, and derived caches are content-addressed separately; deletion from one
does not pretend the others never existed.

Acquisition and decoding run under byte, file, nesting, row, field, and elapsed-work limits. Archives are checked for
path traversal, decompression expansion, symlink escape, duplicate names, and incompatible media. Dataset-provided
programs, serialized callables, browser traces, macros, package manifests, and environment actions remain data and are
never executed by a research reader.

### Inert research episode

The normalized analysis unit is the closed `eslm-research-episode-v1` envelope. It contains high-level fields for:

- immutable source, component, revision, split, license, rights, and projection identities;
- an episode identity used only for joins and deduplication, never as a semantic feature;
- the visible request, initial symbolic state, ordered observations, declared capability vocabulary, and environmental
  constraints;
- typed action candidates, selected action kind and inert arguments, partial-order dependencies, and observed state
  deltas without an executable command or import path;
- intermediate and final outcomes, success criteria visible to the training split, typed human or automatic feedback,
  competing candidates, ratings, and disagreement;
- provenance spans back to the frozen source, truth status, epistemic status, safety and privacy tags, and every
  projection loss or redaction; and
- a closed work receipt for bytes, rows, tokens, graph elements, clusters, comparisons, candidates, and completeness.

The envelope preserves absence and uncertainty. Missing state is not an empty state; an unobserved action result is not
failure; a preference is not truth; a model-generated rationale is not a proof; and an upstream reward is not an ESLM
confidence. Source-native identifiers are retained for audit but excluded from generic feature vectors and generated
implementation conditions.

### Visibility, contamination, and privacy

Source splits are frozen before projection. Only training-visible rows may support discovery. Development-visible rows
may diagnose a promoted prototype but are then permanently marked exposed for that behavior. Fresh, test, shadow,
leaderboard, gated-evaluation, and protected AppWorld-style material cannot support hypothesis induction, thresholds,
examples, prompts, or failure patches.

Contamination checks group near duplicates by normalized request, source family, template, task generator, document,
website, action graph, answer structure, and provenance lineage. Exact and locality-sensitive fingerprints are aids to
review, not proof of independence. Splits use group-level isolation, leave-task-family and leave-source transfer, nonce
renaming, argument permutation, changed action order, meaning-preserving metamorphoses, meaning-changing contrasts,
and fresh project-authored cases. A source-to-source overlap ledger identifies inherited upstream components such as
MATH problems embedded in another release.

PII, credentials, contact data, unsafe operational instructions, copyrighted website snapshots, and user-contributed
content receive source-specific handling before any analysis or agent packet. Redaction produces a new projection with
a loss record; it never edits the frozen source. If safe and lawful projection would destroy the structure needed for
the research question, that component is excluded rather than weakly anonymized and overclaimed.

### Deterministic projection pipeline

The target pipeline performs the following bounded transformations:

1. validate source and component manifests, rights, split visibility, and cache identity;
2. stream source-native records through project-owned schema readers;
3. inventory valid, malformed, excluded, protected, duplicate, and oversized rows with exact reconciliation;
4. map visible request, state, observation, action, feedback, and outcome fields into inert episode types;
5. derive structural features such as operation signatures, capability preconditions, state-delta kinds, dependency
   edges, error locations, output obligations, and witness availability;
6. remove source identifiers and lexical constants from generic discovery features while retaining audit provenance;
7. emit immutable projected shards, indexes, projection-loss reports, and a membership digest; and
8. compare canonical episodes with compiled shards under DS019 equivalence before analysis begins.

The full frozen source is retained when rights permit. Budgets may change sharding, sampling for a probe, or analysis
scheduling; they cannot silently delete valid rows from the declared projection. An incomplete analysis reports the
unvisited frontier and cannot make absence claims about unvisited data.

### Bulk clustering and multi-method discovery ensemble

Bulk analysis streams immutable projected shards and reduces them into bounded structural summaries before comparing
episodes; it does not load the entire source graph or all pair combinations into memory. Partition keys, merge order,
sampling for exploratory probes, spill files, cluster membership, and unvisited work are deterministic and recorded.
No single clustering method determines the architecture. Several correlation-grouped, deterministic research
strategies produce typed hypotheses and calibrated evidence:

- **task-frame induction** groups requests by ordered operations, artifact contracts, constraints, dependencies,
  answer domains, and required capabilities;
- **trajectory-signature mining** compares action kinds, argument roles, state deltas, observations, retries,
  backtracking, termination, and outcome structure without replaying actions;
- **partial-order and frequent-subgraph analysis** looks for recurring dependency motifs that survive harmless action
  reorderings and domain renaming;
- **change-point and phase-boundary detection** locates transitions between interpretation, planning, evidence
  acquisition, execution, verification, repair, and construction;
- **earliest-error analysis** contrasts successful and failed trajectories at the first divergent typed obligation,
  unavailable capability, invalid state transition, rejected witness, or output-shape violation;
- **paired preference and disagreement analysis** separates factual, procedural, safety, style, completeness, and
  presentation feedback instead of collapsing them into one scalar reward;
- **contrastive and counterfactual analysis** changes one precondition, constraint, argument, observation, or outcome
  and checks which proposed boundary should change;
- **metamorphic recurrence analysis** requires a motif to survive nonce entities, predicate renaming, paraphrase,
  irrelevant evidence, changed ordering, and meaning-changing negative controls; and
- **cross-source recurrence analysis** asks whether independently licensed sources expose the same typed
  responsibility with different vocabulary, domains, and collection procedures.

Exact feature bucketing, deterministic hierarchical grouping, bounded density grouping, sequence mining, and graph
motif enumeration may all propose clusters when their distances and stopping rules are recorded. Their outputs are
candidate evidence. A coordination node may combine comparable support, opposition, coverage, stability, and
independence using correlation groups and explicit confidence. An authority gate never votes, and cluster popularity
never establishes semantic correctness or architectural necessity.

### Four-artifact discovery-cycle protocol

One bounded discovery cycle is represented by four different artifacts in a fixed order. Later artifacts bind earlier
ones; they do not rewrite or retroactively authorize them.

1. **Approved pre-analysis plan — `eslm-rl-dataset-discovery-plan-v1`.** Before projected episodes are opened, the
   plan freezes one falsifiable question and null hypothesis, exact source revisions and projection memberships,
   declared and admitted rows per visibility class, the baseline graph digest, complete discovery-technique identity
   set, and finite work policy. Its only positive authority is
   `analysisAdmission: reviewed-training-projections-only`; answer, runtime, proof, and promotion authority are
   `none`. It contains no observed work, technique receipt, vote, hypothesis, or consolidation outcome.
2. **Machine analysis — `eslm-processing-graph-research-analysis-v5`.** The analyzer binds the current scientific
   implementation ledger, complete source-registry snapshot, exact input membership and per-episode evidence ledger,
   baseline catalog and topology, feature schema, work policy, coverage, technique receipts, hypotheses, omissions,
   completeness, and a recommendation-only handoff. The analysis reports what deterministic techniques observed. It
   does not perform human consolidation and grants no answer, runtime, proof, catalog, or promotion authority.
3. **Human consolidation review — `eslm-processing-graph-consolidation-review-v1`.** A repository-maintainer review
   under DS028 and DS029 maps actual machine-hypothesis identities into source-neutral reviewed candidates and records
   one retain, merge, reject, or defer decision for each reviewed candidate. The review distinguishes a new
   responsibility from a strategy, edge, packet field, gate, or nested circuit and names the simpler existing owner
   where a merge is sufficient. It is input to sealing the research cycle, not permission to execute or promote a
   candidate.
4. **Post-analysis cycle — `eslm-rl-dataset-discovery-cycle-v3`.** The sealed cycle binds the canonical plan digest
   and the exact analysis receipt, copies the analysis-derived split accounting, reviewed mapping, and decisions, and
   lists every machine hypothesis not yet reviewed. Every split row names the source revision, component, native split,
   visibility, declared rows, admitted availability, received visits, selection, and analysis. Non-training rows stay
   declared but have zero availability, visits, selection, and analysis. Each machine hypothesis is accounted for
   exactly once as reviewed or unreviewed. The cycle is
   `complete` only when the bound analysis is complete and the unreviewed set is empty; otherwise it is `incomplete`.
   Its decision scope is `research-consolidation-only`, while answer, runtime, proof, and promotion authority remain
   `none`.

The plan is the only analysis-admission artifact. The analysis is the only authority for machine work and
completeness. The review is the only human interpretation input. The cycle is the only closed consolidation receipt.
None of the four changes the DS029 catalog, strategy profile, deployed runtime, KB truth, benchmark result, or
promotion state.

### Hypothesis types and graph placement

Every closed discovery-cycle hypothesis has exactly one primary receipt type: `processing-node`, `coordination-node`,
`authority-gate`, `strategy`, `edge`, `packet-field`, or `nested-circuit`. This receipt vocabulary is more detailed
than the five DS029 catalog node kinds: a coordination-node hypothesis proposes a voting processing responsibility,
while packet-field, edge, and nested-circuit hypotheses propose contract or topology changes rather than catalog nodes.

- A **processing-node hypothesis** names a stable typed responsibility, input and output envelopes, authority, side
  effects, failure vocabulary, resource dimensions, and why existing nodes cannot own it coherently.
- A **coordination-node hypothesis** is a processing-node hypothesis whose stable responsibility includes bounded
  strategy comparison. It must justify why an existing coordinator cannot own the alternatives and never inherits
  gate, answer, proof, or promotion authority from its votes.
- An **authority-gate hypothesis** names the invariant it checks, authoritative evidence, accept/reject/gap outcomes,
  and why no confidence vote may bypass it. Schema, safety, proof, semantic-preservation, and result-validation gates
  are typical candidates.
- A **strategy hypothesis** is an alternative implementation of an existing selectable node. It keeps the node's
  semantic contract and declares preconditions, confidence kind, witness, budgets, abstention, and correlation group.
- An **edge hypothesis** identifies a typed dependency or exceptional transition and states whether it carries data,
  authority, control, rollback, or resource state.
- A **packet-field hypothesis** adds information required at a named protocol boundary and identifies its producer,
  consumers, validation, privacy, lifecycle, and absence meaning.
- A **nested-circuit hypothesis** proposes a named inspectable subgraph behind one stable external packet contract. It
  cannot conceal an executor, merge authority planes, or bypass the node and gate contracts inside it.

Placement is derived from data dependencies and authority, not visual convenience. The proposal names the earliest
point where all required inputs exist, the latest point before an irreversible or answer-authorizing effect, the
incoming and outgoing envelopes, normal and exceptional edges, rollback boundary, and resource owner. A new node is
rejected when it is only a decorative wrapper, source-specific rename, hidden benchmark solver, or mixture of
interpretation, retrieval, proof, and presentation responsibilities.

### From hypothesis to non-default implementation

Promotion follows thirteen visible stages:

1. freeze source revision, component rights, access terms, citation, and split visibility;
2. run a deterministic stratified source probe and exact inventory reconciliation;
3. audit the research projection, privacy handling, information loss, and inert episode schema;
4. freeze baseline graph, strategy selection, work policy, methods, packages, tests, and execution receipts;
5. generate competing hypotheses with several independent discovery techniques and correlation accounting;
6. map each hypothesis to the DS027 node/strategy/gate vocabulary and a precise graph placement;
7. perform manual contract review for inputs, outputs, authority, exceptional paths, resources, and source neutrality;
8. implement the smallest deterministic version as an exact, statically registered, non-default strategy or node;
9. add renamed, nonce, metamorphic, meaning-changing, safety, rollback, and budget tests;
10. run leave-one-technique-out and leave-one-feature-out ablations plus earliest-failure comparison against baseline;
11. validate on a rights-cleared, protected cross-source transfer pool that was not used for discovery or calibration;
12. pass core-change, security, provenance, witness, resource, and documentation audits with no benchmark identifiers
    or source constants in generic execution; and
13. obtain an explicit maintainer-reviewed DS promotion decision and matching receipt that pin descriptor,
    implementation, arbiter, policies, evidence identity, and retirement conditions. The receipt records the decision;
    it does not create promotion authority. Rejection preserves the falsification evidence and does not silently tune
    the same pool.

An isolated Coding Agent may help summarize training-visible clusters or draft a proposal, but its output enters at
stage five as untrusted candidate text. It cannot see protected pools, modify the host, implement a default route, or
approve its own hypothesis.

### Falsification, ablation, transfer, and retirement

A hypothesis fails when its effect disappears after identifier removal, is explained by one source family, depends on
answer text or source order, duplicates an existing responsibility, weakens an authority gate, changes semantics under
harmless metamorphosis, overfits one task vocabulary, consumes unbounded resources, or adds no measurable benefit over
a simpler baseline. Improvement on training-visible rows alone is insufficient.

Ablation reports applicability, candidate generation, selected outputs, abstentions, work, earliest failure, witness
validity, rollback, and downstream result effects. It compares node removal, strategy removal, feature removal,
alternative placement, budget reduction, and correlation-group collapse. Cross-dataset validation requires a distinct
source lineage and grouped protected pool; “another split of the same inherited dataset” is not independent transfer.

Promoted strategies remain reversible. Retirement begins when current evidence shows redundancy, unsoundness,
unmaintained source assumptions, dominated cost, rights withdrawal, or conflict with a stronger contract. The exact
profile is versioned; removing one identity requires replay of compatibility, metamorphic, benchmark, and result
receipts. Historical reports retain the retired identity rather than being rewritten.

### Receipts and resource budgets

Every machine analysis emits a closed v4 receipt containing source and projection digests, visibility class, rights
state, analysis identity and version, a canonical ledger of the research and processing-graph implementation, the
exact baseline catalog and topology digests, seed, feature schema, correlation groups, work policy, byte and row
scope, per-source and per-component available/received/selected/analyzed coverage, technique and hypothesis counts,
omissions, incomplete frontier, and candidate graph placements. Aggregate support links to episode provenance without
publishing protected rows. Reviewer decisions belong only to the separately identified consolidation review and the
bound v2 cycle. A structurally valid historical analysis or cycle may still be stale; current status additionally
requires its source, projection, implementation, plan, analysis, and baseline-graph identities to match the live
governance chain.

Budgets independently bound source bytes, decompressed bytes, files, rows, tokens, projected fields, graph nodes and
edges, pair comparisons, cluster candidates, motif size, hypothesis count, Coding Agent packets, wall-clock work, and
retained cache bytes. Preallocated strategy budgets prevent one technique from starving alternatives. Exhaustion
returns an incomplete receipt and never converts “not visited” into “not present.” Memory policy controls retained
projection shards; research work policy controls analysis; runtime work and memory policies remain untouched.

### Stage admission and row accounting

Scale advances through six separately reviewed stages: metadata review, stratified probe, complete small component,
sharded development, large-corpus execution, and protected transfer. Passing a validator at one stage does not admit
the next. Before large-corpus execution, a source-specific readiness packet must establish exact reconciliation,
stable projection loss, deterministic replay and shard equivalence, tested projection-input restart, bounded peak memory, approved
rights and tested removal, frozen lineage and protected isolation, and named stop conditions. Its scale plan must name
the exact stage `large-corpus`; `sharded-development`, a prefix match, or an arbitrary non-empty stage cannot authorize
the large runner. A failing or unsigned readiness packet leaves the source at sharded development even if every
current projection shard was visited.

Readiness booleans and copied memory numbers are not execution evidence. Admission requires a byte-identified
`eslm-rl-large-source-preflight-v1` receipt produced by the reviewed preflight command. The gate rehashes that producer
script and its complete repository-local static import closure, and binds its exact argument shape, current scientific
implementation ledger, baseline catalog, source manifest and
approved pre-analysis discovery plan, source and validation-split identities, projection manifest and every shard identity, checkpoint
boundary, and removal obligations. Two child processes run complete analyses. A third serializes a closed projection
input checkpoint containing the exact prefix-shard JSONL bytes, membership, and prefix/suffix partition, then exits. A
fourth process rehashes and validates that checkpoint, consumes its prefix exactly once without reopening prefix shard
files, reads the untouched suffix shards, and runs the same complete analysis. All three analysis receipt digests must
agree. This is `inputStreamResumeTested`: restart of the projection input stream across process termination, not
serialized or continued internal analyzer state. The parent records actual exit codes and observes each child's peak
resident memory through Linux `/proc/PID/status`; child self-reporting is not admission evidence. The receipt also
reconciles every projected training episode while reporting the named
development population and proving zero development and protected visitation. Readiness repeats the measured peak,
ceiling, shard count, episode count, and preflight file digest; any mismatch, script drift, implementation drift,
source drift, projection drift, any transitive preflight-module drift, non-zero exit, memory excess, incomplete purge drill, or contamination blocks the
large runner. The preflight grants no answer, runtime, proof, catalog, or promotion authority.

Plan bindings expose two non-interchangeable identities. `discoveryPlanArtifactDigest` hashes the exact plan file
bytes used by admission and replay. `discoveryPlanContentDigest` hashes the validated canonical JSON content and
therefore remains comparable across harmless serialization changes. Checkpoint, preflight, readiness, and live status
carry both; a match on only one cannot authorize execution.

Manifest split rows count frozen source-native membership. Before execution, the discovery plan records those rows as
`sourceScopes[].splits[].rowsDeclared` and separately records projected episodes admitted to analysis as
`rowsAdmitted`. Non-training scopes always admit zero rows. After execution, the discovery cycle records actual
`rowsAvailable` and `rowsVisited`; those values must reconcile with the plan's admitted projection rather than grant
their own admission. Cycle aggregate row work equals the projected training-visible scope;
source bytes, typed actions, dependencies, events, and comparisons remain separate dimensions and must not be relabeled
as episode rows. An incomplete stage preserves the exact unvisited projected frontier and cannot support absence.

### Current measured checkpoint

The first source cycle intentionally progressed from two small components to one larger conversational source instead
of beginning with the largest available corpus. The frozen HelpSteer2 training ratings contain 20,324 rows and project
to 10,161 prompt-group episodes. The frozen GSM8K `train_socratic` component contains and projects 7,473 training
episodes. Their complete small-pilot analysis covers 17,634 episodes, 69,467 typed actions, and 41,670 typed
dependencies under a 16,717,552-byte compressed source scope. It retains 14 exploratory or contested hypotheses and
authorizes none of them for runtime use.

OASST1 is the first large-source checkpoint. Its current split membership freezes 10,364 trees and 88,838 messages:
9,846 trees and 84,437 messages are training-visible, while 518 trees and 4,401 messages are development-visible and
unavailable to discovery. The reviewed English, non-synthetic, non-deleted, zero-PII training projection admits 2,220
trees representing 22,373 messages into 16 content-validated shards and records 7,626 excluded training trees. Message
text, message and user identities, excluded training trees, and every development tree remain outside research
episodes. Development membership is nevertheless named and hashed so zero availability and zero visitation can be
audited rather than inferred from its absence.

The source-local diagnostic, complete replay, content-bound preflight, readiness gate, analysis-v5 receipt, human
review, cycle-v3 receipt, and bounded combined analysis must all be regenerated after a split, projection, scientific
implementation, approved plan, or baseline-graph change. An older receipt remains historical evidence for its exact
membership but becomes `superseded`; it cannot authorize the current 16-shard projection or describe current
scientific behavior. The approved three-source plan admits 19,854 projected episodes before its independent work-policy
frontier. A bounded selection may still stop at `max-episodes`; in that case it must preserve the exact unvisited
membership and forbid absence claims. Final source-local and combined visited work, events, votes, hypotheses, peak
memory, receipt digests, cycle completeness, and stop state belong in their validated artifacts and the v2
research-status output rather than hand-copied prose.

The completed small-pilot consolidation made no runtime-node promotion. Task-frame proposals mapped to the existing
request-plan coordinator; quality-axis proposals consolidated as strategies of result construction rather than
separate nodes; action dependencies remained a packet-field hypothesis; and phase transitions remained an edge
hypothesis. The next gate is a complete or independently justified bounded cross-source frontier followed by ablation
and protected transfer. The human ledger preserves these merge and rejection decisions, and the machine receipts
preserve exact work and incompleteness.

Current machine publication uses `eslm-processing-graph-research-analysis-v5`, and current post-analysis
consolidation uses `eslm-rl-dataset-discovery-cycle-v3`. Every analysis binds its complete scientific implementation
ledger, exact registry and input membership, evidence ledger, and exact catalog and topology digests; every cycle binds
one approved plan and that exact analysis. `research graph status` validates published historical artifacts and
separately recomputes current manifest, cache, source-admission, plan, registry, preflight, and readiness governance.
The status result, not a filename or this specification, is the authority for whether each stored execution is
current, blocked, withdrawn, historical, or superseded. A legacy analysis or cycle artifact can remain interpretable
historical evidence but cannot satisfy the current analysis-v5 and cycle-v3 bundle contract.

and redistribution boundaries are resolved and frozen.

### Multi-year milestones

**Foundation milestone.** The source registry, inert episode schema, rights and visibility gates, streaming projection,
exact accounting, bounded multi-method analyzer, and baseline receipts are implemented and measured on three source
families. The milestone remains in progress until the cross-source frontier is complete or its sampling claim is
independently justified and the retained hypotheses receive ablation and transfer evidence. Success still means
reproducible research and zero runtime or benchmark contamination, not a new default capability.

**Task-structure milestone.** Compare task-frame, sequence, partial-order, change-point, earliest-error, preference,
and metamorphic discovery on independently grouped sources. Produce reviewed processing-node, coordination-node,
authority-gate, strategy, edge, packet-field, and nested-circuit hypotheses with explicit rejection evidence.

**Processing-graph milestone.** Implement a small set of non-default generic hypotheses, connect them through named
envelopes and common resource receipts, and demonstrate cross-source ablation and protected transfer. The goal is a
more complete typed DAG, not an opaque controller.

**Compositional handling milestone.** Extend discovery to long multi-obligation requests, tool-like capability plans,
stateful interaction, verification, repair, and claim-shaped construction. Measure whether independently verified
symbolic nodes can reproduce increasingly broad task-handling patterns associated with language-model systems while
retaining deterministic replay, explicit inability, provenance, and finite resource authority.

**Sustained research milestone.** Maintain fresh sources, leave-family transfer, retirement studies, and independent
human architectural review over multiple years. Progress is reported per processing layer and authority boundary;
there is no percentage-of-general-intelligence score and no claim of unrestricted language understanding.

### Implementation consequences

The first implementation must add only research-side manifests, schemas, readers, projections, receipts, and tests.
It must not alter the deployed runtime, default strategy profile, benchmark denominators, KB packages, or public result
claims. Each source reader must be source-local and inert; each discovered mechanism must later enter through the
ordinary DS027 descriptor, stage, resource, test, and promotion contracts. Documentation must distinguish candidate
portfolio, acquired bytes, projected episodes, analyzed evidence, implemented non-default hypotheses, and promoted
runtime behavior.

## Decisions & Questions

### Question #1: Why discover architecture from datasets instead of designing only from current runtime failures?

Response: Diverse task and trajectory sources expose recurring responsibilities, state changes, feedback types, and
failure boundaries that a small authored suite may omit. They provide hypothesis evidence, while manual contracts,
metamorphic falsification, independent gates, and protected transfer retain architectural authority.

### Question #2: May a successful trajectory be compiled into an executable policy?

Response: No. Actions remain inert typed observations. The program extracts reusable task and dependency hypotheses;
only a separately implemented, statically trusted, deterministic strategy can execute, and it must pass the full
promotion lifecycle without source-specific control flow.

### Question #3: When does a recurring motif justify a new processing node rather than a strategy?

Response: A node is justified only when the motif defines a stable responsibility with distinct typed inputs, outputs,
authority, failures, and resources that cannot be owned coherently by an existing node. Alternative algorithms under
the same semantic responsibility are strategies. Decorative wrappers and source-family labels are rejected.

### Question #4: Can preference or reward data authorize an answer or proof gate?

Response: No. It may identify output-quality, procedural, safety, or coordination hypotheses after typed separation.
Truth and proof remain governed by premises, method semantics, witnesses, and non-voting authority gates.

### Question #5: How is dataset licensing kept separate from repository licensing?

Response: Each delivered component receives a DS016 manifest and source-specific rights decision. ESLM's MIT license
does not relicense source rows, embedded datasets, web content, user conversations, attachments, ratings, or protected
evaluators. Unclear component rights stop projection of that component.

### Question #6: What evidence is strong enough for promotion?

Response: The proposal must survive source-neutral contract review, nonce and metamorphic controls, budget and rollback
tests, ablation against simpler baselines, an independent protected source lineage, security and core-change audit, and
an explicit versioned DS promotion decision by repository maintainers with a matching receipt. Neither a discovery
vote, analyzer handoff, ledger entry, proposal sink, nor receipt can promote itself. Training-visible improvement alone
is not sufficient.

### Question #7: May a source serve both discovery and evaluation?

Response: Only with permanently separated group-level pools and honest evidence labels. Any row, family, template, or
inherited component exposed to discovery is development evidence for that behavior and cannot later support an unseen
generalization claim.

### Question #8: What happens when rights or source access changes after hypotheses were derived?

Response: The registry tombstones the affected source, purges caches according to the terms, identifies every derived
projection and hypothesis, and re-evaluates whether aggregate evidence and promoted behavior still have independent
support. Historical provenance is retained only to the extent legally permitted.

### Question #9: Why is a separate execution preflight required before large-corpus readiness?

Response: A readiness JSON file can repeat desired booleans and a memory ceiling without proving that the current code
completed, restored its frozen projection input across process restart, reproduced, stayed below the ceiling,
respected split isolation, or exercised removal. The
preflight performs those operations in independently measured child processes and freezes their content identities.
The readiness gate then binds that evidence to one exact source, projection, implementation, and producer script. This
keeps resource and contamination evidence replayable while preventing a successful sharded-development receipt from
self-promoting to `large-corpus` authority.

### Question #10: Why are the discovery plan and discovery cycle separate receipts?

Response: Admission must be decidable before analysis starts. The plan therefore freezes source scopes, projection
membership, baseline graph, techniques, and work budgets without observed results. Analysis v4 then records machine
work, and the separate human review interprets its exact machine-hypothesis identities. Cycle v2 binds the plan's
canonical content digest, the exact analysis receipt, and that review. If one post-analysis object supplied its own
admission evidence, successful output could retroactively authorize the inputs and budget that produced it.
Checkpoint, preflight, readiness, and execution gates consequently bind both the plan's exact bytes and canonical
content; the cycle can report reviewed execution but cannot authorize it.

## Conclusion

Dataset-guided graph discovery gives ESLM a disciplined path from diverse task evidence to clearer processing nodes,
authority gates, strategies, protocols, and placements. Frozen rights, inert episodes, split isolation, multi-method
hypotheses, independent verification, ablation, transfer, and explicit promotion ensure that public datasets broaden
the research horizon without becoming executable policy, hidden benchmark knowledge, or runtime truth.
