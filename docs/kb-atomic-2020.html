ATOMIC 2020 event commonsense

atomic-2020 compiles the complete official train split into executable event-to-relation postings. It answers questions about plausible intentions, prerequisites, effects, reactions, desires, obstacles and event order. These outputs are defeasible candidates: ATOMIC describes what may typically happen, not what must happen in every world.

Run it

node src/cli.mjs ask "Why might apologize?" --kb atomic-2020
node src/cli.mjs ask "What might happen after PersonX apologizes profusely?" --kb atomic-2020
node src/cli.mjs ask "How might PersonX feel after PersonX apologizes profusely?" --kb atomic-2020
node src/cli.mjs ask "What could prevent PersonX apologizes to PersonX's boss?" --kb atomic-2020

Exact normalized events are retrieved directly. If exact lookup fails, a bounded lexical matcher may select a nearby compiled event only when token overlap reaches its threshold; the response reports the matched source event and match score. Up to eight candidates are realized, each with the original train-line provenance.

Build, validate and profile

node src/cli.mjs kb build atomic-2020
node src/cli.mjs kb validate atomic-2020
node scripts/test-source-kbs.mjs --cases 100

The official archive is cached at training/.cache/corpora/atomic-2020/. The source manifest, build report and generated modules live under training/KBs/atomic-2020/. The recorded full stream-and-build run took about 4.5 seconds and added roughly 493 MB RSS. An isolated cold import took about 0.76 seconds and added about 284 MB RSS.

Known limits

The current matcher is lexical rather than a complete semantic event parser. Person roles are preserved in source text but are not yet bound into a general event calculus. Candidate order follows stored relation order rather than calibrated probability. Answers therefore say “possible” and never convert a continuation into a categorical fact. The combined WordNet and ATOMIC test used about 592 MB additional RSS, motivating lazy shard import before larger sources are added.
