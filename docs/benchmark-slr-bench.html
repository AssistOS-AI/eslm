SLR-Bench: synthesizing symbolic rules that generalize

SLR-Bench is an inductive program-synthesis task. A case supplies demonstrations and asks for a rule that explains them. The required result is not a class label and not a plausible prose answer: it is an executable symbolic hypothesis whose consequences must cover the positive examples and exclude the negative examples under the benchmark's declared semantics.

Research object and source identity

The primary reference is Lukas Helff et al., “SLR: Automated Synthesis for Scalable Logical Reasoning,” ACL 2026. ESLM uses the official AIML-TUDA/SLR-Bench v1-All dataset at the immutable revision recorded on the sources page. The dataset is CC BY 4.0. The authors' generator repository is MIT and is frozen independently because generator code and dataset bytes have different identities and licenses.

The complete release contains 19,253 cases across twenty curriculum levels: 18,053 train, 200 validation, and 1,000 test. ESLM retains all five source-native Parquet shards. A dependency-free projection preserves every row in 79 deterministic JSONL shards totaling 1,261,211,442 bytes. Sharding changes physical access, not the semantic denominator: concatenating the prepared shards in declared order reproduces frozen split hashes, and no valid case is rejected because a file or dataset is large.

What rule synthesis means

In the intended positive fragment, a candidate resembles a safe Horn or Datalog rule such as reachable(X,Z) :- edge(X,Y), reachable(Y,Z). Variables in the head must be range-restricted by the body, predicate arity is fixed, and evaluation computes a least fixed point rather than executing arbitrary host code. This connects the task to inductive logic programming, Datalog, and least-fixed-point semantics for positive recursive programs. The benchmark extends the curriculum beyond plain relational joins into recursion, ordering, arithmetic constraints, and aggregation, so a correct implementation must state which operator fragment it supports and how each operator affects monotonicity and termination.

A general synthesizer searches a hypothesis space defined by predicate signatures, admissible literals, variable introduction, recursion policy, and operator modes. It can organize that search by increasing description length, typed refinement operators, or constraint solving. Whatever search strategy is chosen, acceptance is semantic. Two alpha-renamed or body-reordered rules may be equivalent; two textually similar rules may differ because one reverses an argument, omits a guard, changes a comparison boundary, or permits an unsafe variable.

Independent candidate validation

Let B be background facts, H the proposed rule set, P the required positive atoms, and N the forbidden negative atoms. For a positive monotone fragment, the verifier computes the least fixed point lfp(TB∪H) of the immediate-consequence operator. It accepts only if every member of P is in that closure and no member of N is in it. Recursion requires termination controls over a finite Herbrand base. Arithmetic and aggregation require typed domains, explicit overflow and empty-set behavior, stratification where negation or aggregates are present, and a declared completeness boundary.

The official evaluator uses a validation program and a Prolog process. ESLM does not execute either the dataset program or a proposed corpus string. The source adapter tokenizes every supplied validation statement and admits only inert ground facts into an AST; directives, rules, variables, queries, operators, and unknown tokens fail closed in that field. Across the frozen release, 13,999,345 ground facts passed this structural parser and zero corpus programs were executed. The ESLM verifier evaluates its own inert rule AST against those ground facts and independently replays the coverage and exclusion evidence.

The implemented finite conjunctive method

method:core:finite-conjunctive-rule-induction receives typed positive and negative examples, not source rows or expected rules. Each example has a designated root and N-ary facts whose arguments are explicitly typed as renameable entities or constant values. Starting from the smallest positive example, the method enumerates connected fact subsets in increasing body length. It replaces entities by canonical variables, preserves typed values as constants, canonicalizes literal and variable order, and removes alpha-equivalent duplicates.

A hypothesis is solved only when relational join evaluation finds a root-preserving binding for every positive example and exhaustively finds no binding for every negative example. The witness records one supporting fact per body literal and the complete variable binding for each positive case, plus a completed no-match receipt for every negative. Verification reruns canonical induction and every join. The method is sound and bounded-complete for connected positive conjunctive rules inside the declared variable, body, candidate, and match-step limits. It deliberately does not pretend that this fragment includes negation, inequality, quantifiers, aggregation, extrema, arithmetic, or recursive induction.

Task, oracle, and lifecycle boundaries

The runtime-visible task contains the prompt, curriculum metadata, problem-size metadata, and a typed rule-output contract. The ground-truth rule, validation program, shortcut fields, and symbolic support remain host-only oracle material. Numeric source identifiers repeat across splits and are therefore never semantic dispatch inputs. Train is available through a streaming, label-isolating interface; validation is development evidence; the official test split is fresh and cannot be opened through the public pool loader.

The latest complete development run submitted all 200 official validation tasks—ten from each of twenty levels—to the finite conjunctive method. It produced 126 validation-exact rules, and all 126 witnesses replayed. Ten cases returned UNKNOWN after the declared conjunctive space was exhausted. Sixty-four returned RESOURCE_LIMIT after candidate or match-search bounds were reached. All 200 cases remain in the denominator: the result is 126/200, or 63%, not 126/126. Levels 1–5 are each 10/10. Language Agent calls and corpus-program executions were zero, and the 1,000-case official test split remains sealed.

Inspection of source-visible rule-family metadata after prediction found no self-recursive target rule in any of the 18,053 training rows or 200 validation rows. The current result therefore says nothing about recursive induction, even though the broader benchmark research program discusses recursion. This is a source-evidence boundary, not permission to fabricate recursive cases or claim that recursion has been solved.

Implementation gate

The finite conjunctive fragment has passed full entity, predicate, value, and ordering renames; a disconnected lookalike contrast; an isomorphic positive/negative non-identifiability control; witness tampering; and a static audit for benchmark names, source IDs, source constants, and expected answers. The next implementation work is not a larger source-size allowance. It is query-directed search and separately specified operator families for quantification, negation, inequality, arithmetic, aggregation, and extrema. Recursive induction requires an independent development corpus containing observable recursive targets. The scorer, broader core behavior, tests, source manifest, and dependency hashes must be frozen before the official test split is opened once.
