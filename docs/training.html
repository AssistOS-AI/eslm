ESLM Documentation / Training

Program synthesis over benchmarks and real knowledge

Training is program synthesis. A coding agent designs executable semantics, schemas, rules, sharding, and indexes from authorized evidence. Deterministic Node.js adapters then validate and compile complete sources into reviewable ESM modules. The runtime uses only the promoted code and never calls the agent.

Two inputs with different jobs

Evaluation datasets and knowledge corpora must not share one ambiguous pipeline. A benchmark such as bAbI supplies controlled episodes and a hidden oracle; its generated model should retain reusable language and execution patterns but not episode answers. A knowledge corpus such as WordNet or ConceptNet supplies persistent senses, facts, typed relations, defaults, and provenance; its generated profiles are the evidence used to answer later user questions.

Large-corpus architecture gate

No WordNet, ConceptNet, Wikidata, ATOMIC, GeoNames, DBpedia, or Wikipedia run may begin by feeding the full dump to an agent. The repository first creates a deterministic stratified probe, accounts for schema surprises, maps time/space/domain/world/perspective scope, measures projected resources, and reviews a streaming shard design. The synthesis skill now refuses full work above the large-corpus threshold when those artifacts are absent.

The current small runtime still imports complete arrays and computes closure at startup. Posting insertion and premise selection have been improved, and opt-in profiling is implemented, but query-directed shard loading and overlay-local reasoning remain mandatory before K1 promotion. The scalability review lists the exact gate and failure conditions.

node src/cli.mjs train prepare \
  --input training/input/example.jsonl \

Query profiles report engine initialization and semantic stages. Training preparation writes a .profile.json sidecar. Source adapters must extend this with decompression, parsing throughput, accepted and rejected records, dictionaries, deduplication, shards, postings, provenance, generated bytes, validation, import, cache use, and peak memory.

Acquisition and cache

dataset fetch downloads the frozen bAbI v1.2 archive into the shared local cache. Its integrity digest is stored in src/datasets.mjs; a matching archive is reused and a mismatch is rejected. Each dataset command extracts only the selected task's train and test files. Tasks 2, 3, 15, and 16 are currently cached and prepared. Public data paths are ignored by Git, so running the experiment does not silently redistribute the dataset.

npm run dataset:fetch
node src/cli.mjs dataset status --dataset babi-15-en-10k-v1.2

The current archive is 11,745,123 bytes. The extracted Task 15 train and test files are 877,358 and 87,769 bytes. The cache manifest records the source URL, archive digest, extracted-file paths, byte counts, and digests.

Split isolation and chunk preparation

npm run dataset:prepare

The adapter parses numbered bAbI lines into independent cases containing context, question, semantic answer, supporting line IDs, and supporting sentences. Train records are additionally wrapped as document records for coding-agent analysis. Each chunk has a SHA-256 digest. Repreparing with the same archive, adapter, and chunk size yields the same semantic files and hashes.

Train-only analysis

node src/cli.mjs dataset analyze --dataset babi-15-en-10k-v1.2

This command reads only the prepared train split. It counts names, classes, universal rule signatures, membership statements, answer distribution, support depth, and unsupported sentences. It proposes the reusable structures that the coding agent should verify. In the completed run, every one of the 80,000 context statements matched either a class assertion or a universal fear rule.

Deterministic analysis does not replace the coding agent. It provides auditable observations and reduces repeated scanning. The agent decides module boundaries, distinguishes stable runtime algorithms from corpus-conditioned tables, reviews counterexamples, and produces the candidate source.

Resumable chunk ledger

node training/.agents/skills/synthesize-eslm-model/scripts/prepare-chunk-ledger.mjs \
  training/datasets/babi-15-en-10k-v1.2/prepared/manifest.json \
  training/work/babi-15/chunk-ledger.json

The repository-owned synthesis skill is self-contained. Its v1 ledger generator resolves and verifies every train chunk without reading the test split and creates entries with status, observations, emitted symbol IDs, unresolved records, and timing fields. It does not yet implement atomic worker claims, leases, or result submission. The newer parallel protocol therefore uses immutable worker assignments and private result files followed by one deterministic reducer; the shared ledger is not treated as a concurrency coordinator.

Recorded Task 15 limitation. The promoted model was produced by one primary coding agent over the full prepared train split. The v1 ledger verified the 20 chunk hashes but was not updated as a completion journal; its entries remain pending. Therefore the run record cites full-train analysis and candidate validation, not nonexistent per-worker receipts. This is now explicit in training-run.json.

Evidence is aggregated by semantic signature across chunks. A pattern cannot become a rule merely because it dominated one chunk. For episodic benchmarks, the skill explicitly prohibits promoting story facts and answers. It generates parsers, construction metadata, morphology, rule schemas, state transitions, and indexes that can operate on new episodes.

Sequential or parallel coding agents

The same skill now defines both modes. In sequential mode, one coding agent processes the immutable chunk inventory and performs global aggregation. In parallel mode, a coordinator creates disjoint assignments, forks or invokes workers, and gives each worker only its assignment and train chunks. Workers write independent JSON analyses; they never edit the shared ledger, candidate, promoted model, or another worker's result.

node training/.agents/skills/synthesize-eslm-model/scripts/prepare-parallel-assignments.mjs \
  training/work/babi-15/chunk-ledger.json \
  training/work/babi-15/parallel-plan \
  4

# Fork one coding agent for each assignments/worker-NNN.json.
# Each writes results/worker-NNN.json using the skill's worker schema.

node training/.agents/skills/synthesize-eslm-model/scripts/reduce-parallel-results.mjs \
  training/work/babi-15/parallel-plan/plan.json \
  training/work/babi-15/parallel-plan/results \
  training/work/babi-15/parallel-plan/reduced.json

A demonstration plan now partitions the 20 Task 15 chunks across four workers, five chunks each, with plan digest e1623bc6…2c95. It has zero worker results and no reduction because it was created after the promoted single-agent run. A future Task 16 run can use this protocol from the start.

Static disjoint assignments avoid shared-file races and clock-dependent leases. The reducer rejects missing, duplicate, unassigned, hash-mismatched, or hidden-test-referencing output and sorts evidence canonically. Because forked agents in this workspace still share filesystem visibility, test isolation remains a procedural constraint here. A stronger experiment can run external workers with one read-only train assignment and one write-only result directory.

Candidate generation and validation

The completed Task 15 candidate contains seven modules totaling 1,743 bytes. It promotes three constructions and four irregular class forms. Its entity, fact, and rule arrays are empty because those values vary per episode. Both the skill-local and project validator passed before the candidate was recorded as promoted.

Rebuilding after a capability change

A runtime change can invalidate assumptions made by an older generated model. Every model therefore records a format, train digest, evidence regime, and synthesis report. When new constructions, epistemic fields, rule forms, event semantics, or index contracts are introduced, the workflow creates a new candidate from the frozen train chunks, reruns both validators, runs train-only probes, and only then evaluates the untouched test split.

training/model/training-run.json is the durable run registry for the promoted model. It distinguishes source acquisition, preparation, coding-agent synthesis, validation, promotion, held-out evaluation, external comparison, prepared diagnostic datasets, and the next knowledge milestone. The homepage reads these facts conceptually and must be updated with every promoted run.

Adding the first real knowledge source

A new corpus receives a catalog entry with a fixed release or dated snapshot, official source, license and attribution requirements, source size, adapter version, relation inventory, profile definitions, and local artifact state. corpus status reports those stages independently from dataset status.

The Open English WordNet 2025 probe has parsed the complete official archive and published exact source-shape counts, but it has deliberately emitted no model. Its next artifact is a sense-aware dictionary and a small noun.animal plus noun.Tops shard prototype with ambiguity, taxonomy, negative-query, cold-import, and memory tests. ATOMIC follows after participant-bound event semantics work, then filtered ConceptNet and bounded GeoNames. Wikidata is future and thematic only. Task 16 remains a useful induction diagnostic, not the main path toward a useful world model.

Current hand-authored modules are regression fixtures

Files under training/KBs/QUICK/source/ currently exercise modular loading, merge conflicts, rule closure, exceptions, and CLI selection. They are authored fixtures rather than learned public knowledge and are excluded from research-training claims. They remain temporarily useful while the WordNet adapter establishes the source-derived model format.

The current sources generate 12 direct facts and 9 rules for child-basic, 21 facts and 5 rules for animals, and 35 facts for space-geography. They are marked benchmarkEligible: false. Their role is software regression only; future public-corpus modules use source-record provenance and their own profile manifests.
