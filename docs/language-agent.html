External Language Agent: translation into ESLM controlled language

The Language Agent extends operator-side compatibility beyond direct parser coverage by translating or conservatively simplifying one utterance. Host-owned gates keep it strictly linguistic: answers, facts, proof state, option selection, and symbolic reasoning remain inside their authoritative components. The deployed runtime stays independent of the service.

Direct parsing and deterministic local heuristics receive the first attempts. Only an explicitly enabled external route can follow their final UNPARSED result. External text becomes usable after host-owned validation and a new run through the unchanged parser, KB providers, planner, and reasoner.

Product-neutral role and current adapter

Language Agent names the contract. It may be implemented by a small translation-focused service trained to emit ESLM controlled English, or by a general coding agent configured without tools. The repository currently supports a Codex CLI adapter and requests the exact local model slug gpt-5.3-codex-spark at low reasoning effort. This exact slug is intentional: model substitution changes behavior, cost, availability, and cache identity.

A successful local invocation proves only that the installed Codex version, current account, and service routing accepted the slug at that time. It is not a portable dependency claim. Missing authentication, unavailable model routing, timeout, or nonzero exit returns an attributed Language Agent failure while preserving the original UNPARSED result. The default CLI remains buildable, testable, and usable offline; tests exercise the external contract through stub executables.

Opt-in operator profile and deployment boundary

EslmRuntime is deterministic, dependency-free, offline, and has no child-process path. The attended CLI uses that local behavior by default, including deterministic heuristic approximation. An operator may explicitly enable LanguageAgentAssistedRuntime for a disclosed external translation attempt. Tests, public direct probes, regression smoke, confidential input, and deployed-style reproduction retain the offline profile.

Trigger and bounded feedback loop

The wrapper receives a request only after direct parsing and the local heuristic ensemble leave terminal status UNPARSED. UNKNOWN, AMBIGUOUS, NO_APPLICABLE_METHOD, RESOURCE_LIMIT, or a wrong answer does not trigger it. Those statuses indicate knowledge, interpretation, method, or resource issues that translation must not hide.

An episode has at most three proposal slots. A schema- or anchor-invalid proposal may receive bounded host validation categories. A surface-valid proposal that reparses to UNPARSED may receive the previous controlled-English text and only the fact that ESLM still did not support its form. No retry receives an answer, expected value, KB result, provider evidence, proof, selected option, benchmark identity, or correctness signal. Once a proposal reaches any parsed semantic status, the Language Agent loop ends.

Codex subprocess isolation

The adapter creates a fresh empty operating-system temporary directory, writes a host-owned JSON Schema, and starts codex exec ephemerally. The invocation requests no approval, a read-only sandbox, ignored user configuration and repository rules, no shell tool, no browser tool, the exact model, low reasoning, and schema-constrained final output. Only a bounded environment allowlist needed for the executable and existing authentication is inherited.

The source utterance is embedded as JSON and explicitly marked untrusted. Commands inside it are data. Input is capped at 12,000 characters. Standard output and standard error are captured separately up to 2 MiB each and hashed in the receipt. A timeout or process-stream overflow sends SIGTERM; after 250 ms the host sends SIGKILL, then uses one final bounded 250 ms settlement window. The response JSON is rejected before parsing if its file metadata exceeds 1 MiB. The temporary directory is removed after the bounded read. The Language Agent has no repository, KB, network-tool, or promotion authority.

Response and protected anchors

The response protocol eslm-language-agent-normalization-v2 permits exactly five fields: protocol, operation, source language, normalized English, and source-to-target alignments. Operation is translation or simplification. Explanations, answers, confidence, retrieved facts, tool calls, Markdown fences, executable fields, and additional properties are rejected.

The host independently extracts numbers, answer markers, quotations, likely names, question force, interrogative type, negation, quantifiers, modality, conditionals, temporal operators, conjunction, disjunction, comparisons, and directed relations. Every protected source occurrence needs one exact-substring alignment to one unused compatible target occurrence, and the complete typed identity multisets must match. This catches direction and strength changes that a count-only check misses: left cannot become right, above cannot become below, and a universal quantifier cannot become existential. Operator detection is construction-sensitive: Romanian mai in mai mare decât is comparative, while Ce mai faci? is an idiomatic check-in and must not be rejected merely because it contains the same spelling.

English simplification has an additional conservation gate: after protected anchors are removed, both its normalized open-class-content multiset and its reviewed function-word multiset must equal the source multisets. Romanian translation uses an intentionally narrow, auditable profile. Non-function content remains literal or uses an occurrence-level alignment from the reviewed Romanian-to-English equivalence map; other language tags are rejected. The map includes tested forms such as unde → where, camera → room, and the reviewed Ce mai faci? → How are you? idiom. Every admitted mapping therefore has a concrete validation rule and regression control.

This validation is conservative, not a proof of semantic equivalence. Long-distance scope, implicit negation, lexicalized modality, unreviewed idioms, presupposition, coreference, and relations outside the typed allowlist may remain undetected. When preservation cannot be established, the host returns UNVERIFIED_NORMALIZATION instead of trusting fluency.

Cache and evidence attribution

The ignored adapter cache key covers original-input digest, requested operation, exact model, reasoning effort, prompt policy, response protocol, validator version, and normalization policy. Cache files over 4 MiB are rejected from metadata before parsing, and oversized serialized entries are not written. A cache hit is schema-checked, anchor-validated, and reparsed under the current runtime. It counts as assisted language because the text originated from the external adapter, even when the current run makes zero external calls.

Structured output separates normalization candidates, proposal count, external invocations, cache hit, adapter and model, original text, transformed English, validation, reparse status, and final symbolic result. The public direct report uses zero Language Agent calls by construction. An assisted benchmark is a separately frozen experiment.

Implementation boundaries

The stable codex-normalizer.mjs facade coordinates proposals and receipts. Protocol constants and schema, anchor extraction, semantic validation, and bounded subprocess/cache I/O live in separate cohesive language modules. None is imported by EslmRuntime; only the operator wrapper and CLI reach this adapter. This keeps semantic review separate from process review and keeps every normalizer source module below the 500-line threshold defined by DS001.
