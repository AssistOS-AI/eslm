ESLM Documentation / Development / Evidence overview

Development evidence without one misleading score

ESLM keeps three development ledgers because they answer different questions. Knowledge-base status says what information can be loaded. Benchmark status says what behavior was actually executed and scored. Reinforcement-learning dataset status says what task structure has been studied for possible future processing nodes and strategies.

Knowledge-base statusCurrent packages, what each contributes, and the next useful ingestion targets. Benchmark statusInternal checks, public executions, result freshness, measured quality, and candidate evaluations. RL dataset statusAcquisition, structural projection, analysis maturity, source candidates, and distance from runtime use.

The three claims must stay separate

QuestionEvidence that answers it
What can the runtime know?A validated package and its declared projection show which records and policies are available. A package count does not show that a query used them or that an answer is correct.
What can the system do?An execution receipt names the tested cases, route, scorer, witness policy, result checkpoint, and failures. A catalog entry or downloaded source is not an execution.
What architecture might be missing?Rights-cleared training projections can reveal repeated operations, dependencies, feedback axes, and failure boundaries. These are research hypotheses until a separate implementation, ablation, transfer test, and promotion decision succeed.

A practical reading order

  1. Open the relevant status page and read its plain-language “current” and “next” sections.
  2. For a numerical claim, follow the link to the generated receipt and check whether the result is current, historical, invalid, or unavailable.
  3. For implementation details, continue to the dedicated knowledge, benchmark, or graph-research chapter.
  4. For a normative guarantee, use the linked DS specification; HTML explains the contract but does not replace it.

Commands that reproduce the three views

node src/cli.mjs kb list
node src/cli.mjs benchmark status
node src/cli.mjs research graph status

npm run kb:validate
npm run benchmark
npm run benchmark:receipts:audit

The status commands inspect existing catalogs and receipts. They do not silently acquire sources, rerun costly public evaluations, promote research hypotheses, or make an old result current.
