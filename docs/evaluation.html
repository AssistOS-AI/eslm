ESLM Documentation / Evaluation and gates

Capability evidence, split isolation, negative controls, regressions, and falsifiable claims

Evaluation asks what capability a result supports and under which evidence regime. It does not treat one aggregate benchmark score as a description of the whole system. Each report binds a suite, split policy, runtime version, KB versions, memory policy, semantic scorer, diagnostics, and resource measurements.

Levels of evidence

Unit tests establish local contracts such as record validation, rule safety, deterministic IDs, and path rejection. Integration tests establish that the frontend, planner, KB loader, inference engine, and result protocol work together. Capability suites vary language form and logical structure while holding the intended operation stable. Source-KB tests sample real package indexes and compare eager and lazy behavior. Benchmarks measure externally recognizable tasks but remain interpreted through the capability taxonomy.

A claim must name its level. Passing an authored smoke KB is implementation evidence, not broad world-knowledge evidence. Answering sampled WordNet definitions is source-adapter evidence, not general question answering. Solving a bAbI task can support a narrow relation or deduction claim only when controls show that the system did not memorize entity names, position, or answer frequency.

The queue stage is not the same as an architecture stage. Source acquisition and schema analysis can start early, while an official run waits for the reusable parser, task frame, capability, proof or witness validator, and regression controls that the family requires. This distinction allows real data work to progress without claiming that cached bytes are implemented reasoning.

Packages present during evaluation

The package catalog currently validates eight packages, and evaluation records which ones a run actually uses. quick@1.0.0 is an authored development fixture. babi-v1.2-language@1.0.0 declares only the source-visible property vocabulary and defeasible induction policy. clutrr-kinship-algebra@1.0.0 declares relation classes, endpoint refinements, inverses, and compositions but contains no graph or answer. oewn-2025@2025 supplies lexical definitions, senses, and bounded taxonomy paths. atomic-2020@2020.2 supplies defeasible event and social candidates from its train split. geonames-2026@2026-08-11 supplies frozen country and populated-place facts. conceptnet-5.7.0-en@5.7.0 supplies reviewed English relation edges with relation-specific semantics. world-relations-1.0@1.0.0 supplies construction, polarity, inverse, implication, and affordance policy for semantic compatibility. None becomes benchmark evidence merely by validating.

Package validity and benchmark correctness remain orthogonal. A package can pass schema, hash, compilation, loading, and provenance checks without solving a benchmark. Conversely, an adapter can solve a closed-context state task without loading a broad world-knowledge package. Reports therefore retain usedKbVersions rather than inferring knowledge use from the catalog.

Normalization candidates are not Language Agent invocations

DS013 defines the requested special-analysis percentage as normalizationAttempts / totalCases, with one important trigger: only a direct UNPARSED result may become an attempt. UNKNOWN, ambiguity, missing knowledge, missing method, contradiction, and resource limits do not authorize a rewrite. A wrong answer is not automatically a language failure, and an elaborate sentence is not automatically a candidate.

The published probe report records both normalization candidates and actual Language Agent invocations for every executed family. A direct UNPARSED outcome is only a candidate; a live or cached assisted track must record the actual attempt separately. For an inaccessible family there is no source denominator, so displaying zero would make a false measurement claim.

The ordinary operator CLI now enables the assisted wrapper by default, but the published probe command and canonical evaluation scripts explicitly select --no-external-language-agent. In an intentionally assisted frozen-suite run, a candidate becomes an actual attempt only after the direct result is UNPARSED. A cache hit remains a Language-Agent-normalized language route because Language Agent originally produced the rewrite, while externalInvocationRate separately measures live subprocess use. Language Agent receives visible language only, never an answer key, KB search result, or reasoning trace that exposes the expected answer. The host validates protected anchors, reparses the result through ESLM, and rejects the rewrite when preservation or parsing cannot be established.

Licenses and protected-source operation

The ESLM source repository is MIT-licensed. That license covers this project's code; it does not replace the licenses or access terms attached to third-party data. Because this work is non-commercial research, the project may use sources such as CLUTRR under their non-commercial terms, and it may use other research datasets whose licenses permit the intended activity. Source manifests still retain each dataset's own license, attribution, redistribution, and access conditions. In particular, a locally authorized source may remain excluded from the public Git repository.

EWoK: the operator has accepted the official terms, and the repository holds the official protected paper-analysis and configuration archives only in its ignored cache. The adapter verifies both archives and the extracted inventory/filter artifacts, reconstructs the declared exclusions, and keeps preference labels outside visible cases and reports. The runtime compares each target with each context through provider-neutral signed semantic compatibility. world-relations-1.0 supplies reviewed frames and implications; ConceptNet can supply independent relation evidence. Neither contains a protected row. This project explicitly acknowledges that EWoK materials are used for evaluation and may guide ESLM improvement. The result remains a scalar symbolic diagnostic rather than the official language-model probability protocol.

Story Cloze: the operator completed the official form workflow and supplied the delivered Winter 2018 validation and test links. Both artifacts live only in ignored local cache and pass byte-size, digest, identifier, sentence, candidate, and schema validation. Validation includes a host-only correct-ending oracle; the delivered test CSV has no answer column and therefore requires the external official evaluator. The adapter exposes a label-free select-narrative-continuation task. The runtime compiles bounded event frames and ranks candidates using structural features plus ATOMIC, ConceptNet, and world-relations evidence. Its development-visible weights and margin are explicit adapter policy with provenance. The selected value is defeasible and an insufficient margin abstains. The required Sharma et al. 2018 and Mostafazadeh et al. 2016 citations and delivered-set distinction are recorded on the sources and citations page.

SimpleQA: no further dataset authentication is needed. The official CSV is already cached, hash-verified, schema-validated, sampled, and executable. The current report separates direct UNPARSED cases from parsed UNKNOWN cases: the first class requires generic broad-interrogative parsing, while the second requires independently licensed encyclopedic KB coverage. The official reference evaluator uses a semantic model grader with CORRECT, INCORRECT, and NOT_ATTEMPTED; using that exact style of official score would additionally require a separately frozen external-grader configuration and credentials. It is not required to continue improving ESLM, and it must remain separate from the deterministic exact-match diagnostic.

Split isolation

Training-visible records may be read by a synthesis subprocess. Development-visible cases may be clustered for diagnosis and iterative proposals. Test and hidden cases are evaluated only by trusted local tools after candidate construction. Packet manifests and execution receipts make this boundary auditable. If leakage occurs, the affected score is invalid regardless of whether the resulting rule looks general.

The probe protocols apply that rule explicitly. bAbI development work uses official training cases and source-local policy derived only from training-visible conventions. BLiMP publishes no official training/test division, so every inspected pair becomes development evidence. CLUTRR rows selected from public evaluation files are classified as development-visible once their failures guide implementation. Entity Tracking uses a development artifact. EWoK and Story Cloze use label-blind partition receipts when a separate fresh pool is constructed. SimpleQA questions are evaluation-visible while their answers remain in the host oracle; deterministic exact match remains a diagnostic rather than the official semantic-grader protocol. An inspected row cannot later become fresh or shadow evidence without a new experiment and replacement pool.

A fresh run has a stricter lifecycle than a recurring development probe. Membership is selected without labels and sealed by digest. Before the oracle is opened, the adapter policy, selected package manifests, reasoning modules, and regression boundary are frozen by digest. Only aggregate outcomes and bounded strata leave the evaluator. If any frozen behavioral dependency changes afterward, that receipt remains evidence for the earlier checkpoint only; the same rows cannot be repeatedly consulted as a repair loop while retaining the word “fresh.”

Semantic scoring and diagnostics

The scorer compares normalized semantic values, not punctuation or terminal phrasing. It also records status correctness, expected abstention, proof requirements, provenance presence, and resource behavior. Exact-match text can remain a secondary metric for a benchmark that requires it, but a semantically correct result should not fail solely because a realizer chose “Yes.” instead of “yes”. Conversely, a plausible string with no valid derivation must not pass a symbolic capability gate.

Every failed case retains the actual result object or a bounded diagnostic projection of it. Failure categories distinguish parsing, binding, missing knowledge, missing method, invalid derivation, trust conflict, output mismatch, timeout, memory pressure, and infrastructure error. The classification directs work to the correct layer.

The adapter remains part of the scoring contract. BLiMP compares two deterministic scalar scores and treats a tie as failure. bAbI compares semantic values after executing the visible story. CLUTRR compares a typed relation label after algebra-declared inverse and composition reasoning; a runtime ambiguity remains a failed forced-label prediction. Entity Tracking compares the final unordered contents required by its masked span without accepting extra entities. EWoK requires the expected context to score strictly above the alternative for the same target. Story Cloze requires the host-isolated candidate identifier selected by the defeasible ranker, and an abstention fails forced-choice scoring. SimpleQA currently applies normalized exact match only as a local diagnostic; it does not imitate or claim equivalence with the benchmark's semantic grader. These distinctions explain why percentages from different rows cannot be averaged into one ESLM accuracy.

Contrastive and negative controls

Positive examples are paired with cases that rename entities, reverse directional relations, negate or remove premises, insert distractors, vary word order within the supported grammar, cross contexts, and request an unavailable capability. A rule learned from “mice fear wolves” must generalize through the variable binding and must stop applying if the type premise disappears. A lexical answer must change when the lemma changes. An abductive hypothesis must not become an asserted fact.

Unknown and abstention cases are first-class. If the package has no evidence, returning a structured unresolved subgoal is correct behavior. Evaluation therefore measures unsupported-answer rate and provenance completeness in addition to solved accuracy.

External comparisons

Comparisons with neural or hosted systems use frozen exported inputs and imported prediction files. The report names the external model, execution date, decoding policy when known, prompt or adapter, and unavailable metadata. ESLM’s offline property does not make its scores automatically superior; it changes the interpretation of reproducibility, provenance, and operational cost. Comparisons should present capability slices and resource regimes rather than one unqualified ranking.

Falsification criteria

The program is weakened if symbolic traces cannot predict failure, if package provenance cannot be followed to frozen evidence, if benchmark improvements require item-specific rules, if query-directed loading changes answers relative to eager loading, if agent outputs bypass promotion gates, or if broader language requires abandoning the explicit task and result contracts. Such outcomes must be reported as limitations or design failures, not hidden by aggregate success.
