Evaluation and failure attribution

Evaluation measures semantic correctness, language coverage, proof quality, abstention, and efficiency separately. A single aggregate accuracy cannot reveal whether the parser, evidence, rule engine, or realizer failed.

Implementation verification

Purpose. This diagram describes npm test. Tests cover normalization, parsing, direct facts, derivation, discourse, unknown evidence, model indexes, CLI path resolution, training split isolation, and external prediction exchange. These fixtures verify code contracts; they are not scientific datasets.

Capability evaluation

Purpose. This diagram shows the internal evaluation path. The oracle compares canonical semantic values or explicit statuses. Tags allow results to be separated by direct retrieval, spelling tolerance, rule execution, paraphrase, discourse, ambiguity, and abstention.

Failure attribution

Purpose. The trace identifies the earliest causal failure. A parse miss must not be repaired by adding the expected answer as a fact. Missing knowledge must not create a grammar rule. A reasoning error with correct premises targets rule execution. This classification keeps model synthesis scientifically meaningful.

Hidden evaluation boundary

Purpose. Hidden labels are introduced only after the candidate is frozen. A random split is insufficient when sources, templates, stories, or relation compositions repeat. Splits should group by source, construction family, entity vocabulary, domain, and composition depth.

Evaluating optional knowledge modules

An evaluation may explicitly pass --kb child-basic or another selection. The JSON report then records the merged model ID, selected KB IDs, and comparable: false. This is appropriate for KB-specific regression suites, but it must not overwrite the interpretation of the clean bAbI result. Educational KB tests currently live in tests/kbs.test.mjs and verify exact counts, opt-in behavior, exception handling, and cross-module closure.

Metrics beyond Task 15

The general reporting contract includes answer accuracy, construction coverage, retrieval recall, reasoning accuracy conditional on parsing, proof fidelity, realization fidelity, abstention precision and recall, robustness delta, composition-depth curves, model size, latency, and replayability. A suite reports only metrics for which it has a valid oracle. Task 16 must add induction calibration and factual-versus-inductive separation; deeper bAbI tasks must report accuracy by support depth.
