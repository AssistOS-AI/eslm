ESLM Documentation / CLI tutorial

Use ESLM interactively or from automation

The same eslm executable supports a conversation prompt, one JSON answer, JSONL batch processing, KB management, source builds, evaluation and reports. Runtime questions remain offline and deterministic. Commands work from the repository root and from the training/ directory.

Start an interactive conversation

npm exec -- eslm
# equivalent:
node src/cli.mjs

Interactive mode loads installed public sources—currently oewn-2025 and atomic-2020—but excludes QUICK. QUICK contains authored fixtures for tests and tutorials, so loading it silently would make ordinary answers look more knowledgeable than the source-derived system. Type /help at any time. A real terminal colors status, command names, load state, warnings, and answers; redirected output remains plain.

ESLM is ready. Public knowledge: oewn-2025, atomic-2020.
eslm> /help
eslm> /kbs
eslm> /examples
eslm> Define dog
dog has 8 compiled senses: ...
eslm> Socrates is a man. Is Socrates a man?
Yes.
eslm> /trace

/examples prints the complete generated short catalog rather than requiring hidden example IDs. The current catalog has 134 cases. Entries that depend on QUICK say works with quick; they will not falsely appear available after QUICK has been unloaded.

Interactive commands

The two normal load targets are Open English WordNet 2025 and ATOMIC 2020. QUICK remains visible and explicitly loadable as a fixture. You do not need to memorize canonical IDs: commands match a full name, a distinctive title or role word, a wildcard such as *net*, or a conservative close spelling such as wordnt. Ambiguous words produce a useful diagnostic instead of loading an arbitrary source.

CommandEffect
/helpPrints every interactive command and examples of session facts.
/kbsShows whether QUICK, WordNet and ATOMIC are ready or loaded, their exact counts and their evidence role.
/load all or /load WORDSLoads every public KB or the unique name/title/wildcard/approximate match. QUICK is loaded only when named.
/unload WORDS or /unload allRemoves matching modules without deleting session facts.
/modelExplains the active generated core, source-derived KBs, fixture KBs, session facts, benchmark comparability, and current memory strategy in readable text.
/memory or /memory N|auto|eager|lazyShows cache use or rebuilds public providers with a soft MiB target or explicit loading strategy.
/examplesShows every tested working, deliberately unknown, and unsupported group. No hidden ID or filter is required.
/trace / /profileExplains the latest provenance or optional stage measurements in readable text rather than dumping JSON.
/clearClears session entities, facts, rules and discourse state.
/quit / /exitEnds the session.

Load and unload examples

eslm> /unload all
Loaded: (base model only).
eslm> Define dog
I do not know how to handle that kind of question yet. Try /examples to see the question families I can execute.
eslm> /load wordnet
Loaded knowledge: oewn-2025.
eslm> Define dog
dog has 8 compiled senses: ...
eslm> /load social commonsense
Loaded knowledge: oewn-2025, atomic-2020.
eslm> /load quick
Loaded knowledge: oewn-2025, atomic-2020, quick.

ready means generated code exists locally. loaded means its evidence is active in the current engine. This distinction is also visible in every JSON answer through model.knowledgeBases.

Ask one question and receive JSON

node src/cli.mjs ask "Jhon is a man. Is Jhon going to die?" --kb quick
node src/cli.mjs ask "Define dog" --kb oewn-2025
node src/cli.mjs ask "Is a dog an animal?" --kb oewn-2025
node src/cli.mjs ask "Why might apologize?" --kb atomic-2020
node src/cli.mjs ask "What might happen after PersonX apologizes profusely?" --kb atomic-2020

Noninteractive commands do not load optional KBs by default. This makes automation and benchmarks explicit. The JSON includes status, answer, semantic query, values, provenance, reasoning method, learned session items, context and active model metadata.

Control memory without paying lazy-loading cost unnecessarily

node src/cli.mjs                         # public KBs eager by default
node src/cli.mjs --memory-mb 512         # WordNet eager, ATOMIC normally lazy
node src/cli.mjs --memory-mb 256         # both public KBs normally lazy
node src/cli.mjs --memory-policy lazy    # force shard mode for diagnostics
node src/cli.mjs --color never           # disable terminal colors

The memory number is a soft whole-process RSS target. ESLM reserves space for Node, the base model, active queries, and session state, then compares the remainder with measured eager expansion rather than file size. With no target it prefers complete eager models because that path is faster and simpler. A constrained plan retains only bounded shard objects and reports cache hits, misses, evictions, and oversized query shards through /memory and model.memory. Use an operating-system or container limit when a hard ceiling is required.

Process a file

node src/cli.mjs run --input tests/fixtures/questions.txt
node src/cli.mjs run --input questions.jsonl --output answers.jsonl --kb quick,oewn-2025

Plain text uses one question per non-empty line. JSONL accepts text or input plus an optional id. Output is always one JSON record per input, which is suitable for shell pipelines and deterministic evaluators.

Inspect, build and validate knowledge

node src/cli.mjs kb list
node src/cli.mjs kb show quick
node src/cli.mjs kb show oewn-2025
node src/cli.mjs kb show atomic-2020
node src/cli.mjs kb build oewn-2025
node src/cli.mjs kb build atomic-2020
node src/cli.mjs kb validate all
npm run test:kbs:random

Downloaded archives are reused from ignored training/.cache/. Builds write source manifests, reports and generated ESM under training/KBs/. The random command runs 700 reproducible source-backed cases and publishes docs/results/latest-kb-random-tests.json.

Datasets, evaluation and benchmarks

node src/cli.mjs dataset catalog
node src/cli.mjs dataset status --dataset babi-15-en-10k-v1.2
node src/cli.mjs dataset fetch --dataset babi-15-en-10k-v1.2
node src/cli.mjs dataset prepare --dataset babi-15-en-10k-v1.2

node src/cli.mjs evaluate --suite training/datasets/babi-15-en-10k-v1.2/prepared/test.jsonl --publish
node src/cli.mjs benchmark run --suite training/datasets/babi-15-en-10k-v1.2/prepared/test.jsonl --publish

bAbI and other benchmark inputs live under ignored training/datasets/; shared archives live under training/.cache/datasets/. Evaluation is separate from public-corpus KB testing. Adding --kb changes the evidence regime and must be recorded in the report.

npm run benchmark:conversation

This second command runs the generated 1,000-case long-input regression suite and refreshes its compact HTML report. It is an internal/source-exposed stress test, not a public benchmark or an LLM comparison.

Diagnose failures and performance

node src/cli.mjs ask "QUESTION" --profile
npm run profile:scale
npm run docs:check
npm test

UNKNOWN means the question was represented but no supporting evidence was found. UNSUPPORTED means no compiled construction/provider handled it. AMBIGUOUS preserves multiple analyses. ATOMIC answers explicitly state that candidates are defeasible. These are semantic outcomes, not generic error messages.
