ESLM Documentation / CLI Tutorial

Using the ESLM command line

One Node.js command exposes interactive conversation, one-shot and file input, knowledge-corpus status, public-dataset preparation, candidate validation, evaluation, and external prediction scoring. The conversation examples below use the promoted bAbI Task 15 compiler or explicitly named regression fixtures and are executed by the test suite.

Install nothing beyond Node.js

ESLM requires Node.js 22 or newer and has no runtime dependency. From the repository root, verify the environment and implementation:

node --version
npm test

The package exposes eslm through npm exec -- eslm, but every example also shows the direct entry point so the executed file remains obvious.

Start an interactive session

node src/cli.mjs

A complete bAbI-style episode may be entered on one line. The first sentence compiles to a temporary universal rule, the second to a temporary class fact, and the final sentence to a query:

ESLM ready. Ask a question; use /trace, /profile, /help, or /quit.
eslm> Mice are afraid of wolves. Gertrude is a mouse. What is Gertrude afraid of?
Gertrude is afraid of wolf.

The same information can be taught across turns because the CLI passes the explicit returned session context into the next call:

eslm> Cats are afraid of sheep.
I learned 1 session item.
eslm> Jessica is a cat.
I learned 1 session item.
eslm> What is Jessica afraid of?
Jessica is afraid of sheep.

Session items disappear at /quit. They never alter files under training/model/. Use /trace after an answer to display the rule ID, supporting fact, source identifiers, and reasoning method.

Run one request for automation

node src/cli.mjs ask \
  "Sheep are afraid of mice. Emily is a sheep. What is Emily afraid of?"

The command emits JSON rather than terminal-only prose. Important fields include status, answer, query, values, reasoning, provenance, learned, learnedRules, and the updated context. For this example, values is ["mouse"], the method is deduction at depth 1, and provenance refers to the temporary rule and Emily's classification.

Distinguish unknown knowledge from unsupported language

node src/cli.mjs ask "Dana is a sparrow. Can Dana fly?"
node src/cli.mjs ask "Write a poem about mice."

The first request compiles successfully but has no flight evidence, so its status is UNKNOWN. The second request has no supported construction or text-generation executor, so its status is UNSUPPORTED. Automation should inspect these statuses rather than infer failure from English wording.

Load a knowledge module

node src/cli.mjs kb list
node src/cli.mjs kb show child-basic

node src/cli.mjs ask \
  "Jhon is a man. Is Jhon going to die?" \
  --kb child-basic

node src/cli.mjs ask "Can Penguin swim?" --kb animals
node src/cli.mjs ask "What color is Mars?" --kb space-geography
node src/cli.mjs chat --kb all

--kb accepts one ID, a comma-separated list, or all. The option works with interactive chat, ask, run, evaluation, and benchmark commands. Every answer includes model.id, model.knowledgeBases, and model.benchmarkComparable; selecting a fixture sets the last field to false. Evaluation and benchmark reports carry the same evidence boundary. The current three KBs are hand-authored regression fixtures, not evidence of public-corpus training.

kb list reports exact entities, direct facts, derived facts, rules, constructions, and examples. The current all-module configuration has 36 unique entities, 62 direct facts, 14 rules, and 116 executable facts after closure. Read Knowledge Bases before combining modules, because their rules can compose.

Rebuild generated KB code

node src/cli.mjs kb build child-basic
node src/cli.mjs kb validate child-basic
node src/cli.mjs kb build all
node src/cli.mjs kb validate all

The build command reads the reviewed sources in training/KBs/QUICK/source/ and regenerates seven ESM files per domain under training/KBs/QUICK/model/. Validation imports each artifact, rejects ambient capabilities, checks every entity reference and rule, and recomputes every posting list. These commands are deterministic Node.js program synthesis; no LLM is called at runtime.

Run from the training directory

cd training
node ../src/cli.mjs ask \
  "Wolves are afraid of cats. Winona is a wolf. What is Winona afraid of?"
cd ..

Model and project paths are resolved from the repository location, not the current shell directory. tests/cli.test.mjs executes this path.

Inspect the real knowledge-training queue

node src/cli.mjs corpus catalog
node src/cli.mjs corpus status
node src/cli.mjs corpus status \
  --corpus oewn-2025,atomic-2020
node src/cli.mjs corpus probe \
  --corpus oewn-2025 \
  --archive /path/to/english-wordnet-2025-json.zip

corpus catalog describes persistent knowledge sources in implementation priority order, including official artifacts, observed scale, license, semantic role, relation inventory, planned profiles, and implementation stage. corpus status separately checks whether the source, probe, prepared manifest, and generated model actually exist locally. The WordNet probe is complete; its source cache, prepared model, and generated KB remain false.

corpus probe currently accepts only oewn-2025. It parses and profiles a local official archive, updates the training probe artifact and documentation report, and emits no KB. Fetch and build actions are not exposed yet. Each source receives those actions only after its format, frozen release, attribution, validation, and inference contract have an implemented Node adapter. See Real Knowledge Sources for the staged plan.

Profile a query or training preparation

node src/cli.mjs ask \
  "Mice are afraid of wolves. Gertrude is a mouse. What is Gertrude afraid of?" \
  --profile

node src/cli.mjs train prepare \
  --input INPUT.jsonl \
  --output training/work/profiled-packet.json \
  --profile

The one-shot response gains an eslm-profile-v1 object containing engine initialization and query stages. It records wall time, CPU, RSS, heap and external-memory deltas, stage status, and basic work counts. Interactive chat started with --profile exposes the last report through /profile. Training preparation persists the same information beside the packet as OUTPUT.profile.json.

Profiling is a diagnosis surface and does not change semantic values or provenance. Individual memory deltas may be negative after garbage collection; corpus builds will additionally sample peak memory. Read Scale and Context for the complete training and query counter contract.

npm run profile:scale

This reproducible synthetic profile measures current index construction at 1,000, 10,000, and 100,000 facts and a simple closure through 10,000 facts. It writes docs/results/latest-core-scale.json. The report identifies itself as a primitive profile, not a corpus benchmark.

Process a text or JSON Lines file

node src/cli.mjs run \
  --input tests/fixtures/questions.txt \
  --output training/work/answers.jsonl

A plain-text input treats each nonempty line as one independent episode. A JSON Lines input may supply id and text. Each output line contains the input ID plus the complete engine response. Batch cases do not share conversation context unless a future explicit episode protocol requests it.

Cache and prepare bAbI Task 15

npm run dataset:fetch
npm run dataset:prepare
node src/cli.mjs dataset analyze --dataset babi-15-en-10k-v1.2
node src/cli.mjs dataset status --dataset babi-15-en-10k-v1.2

fetch downloads only when the verified archive is absent, checks its recorded integrity digest, and extracts the selected task's two raw files. prepare creates 20 train chunks of 500 cases and one test file. analyze reads only the train split and reports construction, morphology, rule-signature, answer-distribution, and unsupported-statement statistics. Public files live under the ignored training/datasets/ cache.

Use node src/cli.mjs dataset catalog to see exact ingestible IDs and stage fields. Tasks 2, 3, and 16 are cached and generically prepared, but their candidate synthesis, promotion, and held-out evaluation have not occurred. These remain controlled executor diagnostics rather than the main knowledge-training queue.

Prepare resumable coding-agent synthesis

node training/.agents/skills/synthesize-eslm-model/scripts/prepare-chunk-ledger.mjs \
  training/datasets/babi-15-en-10k-v1.2/prepared/manifest.json \
  training/work/babi-15/chunk-ledger.json

The v1 command verifies each train chunk and writes a ledger whose entries start pending. It does not claim work, lease chunks, accept worker submissions, or prove completion. Parallel synthesis instead uses immutable disjoint assignment files, one private result per worker, and a deterministic reducer. The promoted Task 15 run used one coding agent over the complete train split; its ledger entries still remain pending. The test path remains forbidden and episode-specific answers must not enter the persistent model.

Validate a candidate and the promoted model

node training/.agents/skills/synthesize-eslm-model/scripts/validate-candidate.mjs \
  training/candidates/babi-15-en-10k-v1.2

node src/cli.mjs train validate \
  --model training/candidates/babi-15-en-10k-v1.2

node src/cli.mjs train validate

The first validator is carried entirely by the portable skill. The second applies repository model invariants. The final command validates the promoted default. Promotion remains a reviewed effect rather than an automatic consequence of passing visible checks.

Reproduce the public evaluation

npm run evaluate
npm run benchmark

Both commands currently use the 1,000 prepared bAbI Task 15 test cases. Evaluation writes docs/results/latest-evaluation.json and HTML; benchmark execution writes the corresponding benchmark files with protocol and machine-recorded split identity. The latest recorded result is 1,000/1,000. The duplication is temporary: evaluation exposes detailed engine outcomes, while benchmark reporting is the comparison contract.

Export the exact cases for an external LLM

node src/cli.mjs benchmark export \
  --suite training/datasets/babi-15-en-10k-v1.2/prepared/test.jsonl \
  --output training/work/babi-15/external-input.json

node src/cli.mjs benchmark score-predictions \
  --suite training/datasets/babi-15-en-10k-v1.2/prepared/test.jsonl \
  --input training/work/babi-15/external-predictions.jsonl \
  --model-name MODEL_NAME

Export removes oracle answers but preserves context and question. A separate runner may call an external model and write predictions. ESLM's scorer evaluates those predictions against the same local cases and records their exact machine identity. No external comparison has been run yet.

Inspect published reference results

node src/cli.mjs benchmark references

This prints curated paper-reported results with their primary source and comparability classification. These are contextual baselines, not locally reproduced predictions. They become a direct comparison only if the dataset hash, split, preprocessing, evidence regime, and oracle match or the original prediction file can be rescored locally.

Run the complete repository check

npm run check

After the public dataset has been fetched and prepared, this command runs unit and CLI tests, the 1,000-case evaluation, the 1,000-case benchmark, DS matrix generation, documentation checks, and promoted-model validation. The training page explains the synthesis boundary, while evaluation explains what the perfect Task 15 result does and does not demonstrate.
