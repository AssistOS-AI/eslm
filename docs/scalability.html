ESLM Documentation / Scalability and context

Measured scale boundary after the first real KB builds

WordNet and ATOMIC compile and answer real source-backed questions. Their eager combined test expands to roughly 0.6 GB additional RSS, so ESLM now keeps that fast path when memory is ample and switches to bounded query-selected shard caches when the user declares a smaller target. Remaining scale work concerns streaming compilation, compact indexes, query-directed reasoning, and explicit time, space, domain, world, and perspective.

The first reproducible corrective profile used simple synthetic is_a data after the posting and premise-index changes. In the latest local report, index construction took about 0.7 ms for 1,000 facts, 4.9 ms for 10,000, and 41.0 ms for 100,000; a one-premise rule closed 10,000 direct facts into 15,000 facts in about 38.2 ms. Run npm run profile:scale to replace the report. These numbers show only that the corrected primitive no longer has the obvious posting-copy bottleneck. They are not a release benchmark: real relation density, multi-premise joins, provenance, ESM parsing, and scope indexes remain unmeasured.

Profiling is part of the experiment

eslm-profile-v1 records stage order, wall time, user and system CPU, RSS, heap and external-memory deltas, status, and work counts. Memory deltas can be negative when garbage collection occurs; large-run reports therefore also need sampled peak memory. Normal queries omit profiling. Release, scale, training, and validation runs must enable it.

node src/cli.mjs ask \
  "Mice are afraid of wolves. Gertrude is a mouse. What is Gertrude afraid of?" \
  --profile

node src/cli.mjs train prepare \
  --input INPUT.jsonl \
  --output training/work/packet.json \
  --profile

The query report already separates engine closure and index construction from session compilation, normalization, parsing, session closure, query index work, answer retrieval, and realization. The training report separates input reading, record validation, canonicalization, type counts, source hashing, and packet writing and persists a .profile.json sidecar. Corpus adapters must add decompression, relation mapping, deduplication, dictionary construction, anomalies, sharding, index emission, validation, cold import, and probe-query stages.

A probe precedes every adapter

The first pass over a corpus is a diagnostic probe, not training. It inventories the schema and takes deterministic stratified samples by relation, record kind, language, upstream source, license, weight or rank, datatype, qualifier presence, time shape, spatial shape, and parse result. It gives extra space to rare and rejected strata. Taking the first thousand lines is insufficient because source files are commonly grouped by language, relation, or entity.

The probe report must identify unknown relations and datatypes, malformed and oversized values, alias collisions, negative assertions, cycles, conflicts, source mixtures, license mixtures, qualifiers, time intervals, coordinates, units, and estimated output/index size. For WordNet's moderate archive the probe may scan the complete source while retaining only bounded examples. ATOMIC, ConceptNet, and GeoNames require bounded memory and stable per-stratum sampling. Any future thematic Wikidata probe has the same requirement and a separately approved domain boundary.

What the WordNet probe actually found

The first complete WordNet probe scanned 107,519 synsets and 185,129 lexical senses in under three seconds on the recorded machine. Its principal stages were archive inventory and hashing, synset inventory, lexical-entry inventory, and a second reference-validation pass. The latest report records the exact run-dependent deltas; RSS grew by more than 200 MB and heap by roughly 150 MB. These are not sampled peaks, but they already show that retaining global ID and ambiguity sets dominates the tiny compressed archive and must not become the design for ATOMIC, ConceptNet, or GeoNames.

The probe found 25,805 ambiguous normalized members, including 75 synsets for “break” and 70 for “cut”. It also found homograph-suffixed part-of-speech keys and external Wikidata IDs shaped like string arrays. Those observations invalidated unique aliases and shape-only relation inference. The compiler emitted a sense-aware KB and DS021 now provides selective shard access. Contextual sense choice remains open.

What the complete builds measured

WordNet generated 38 modules and 23,771,871 bytes in about 1.34 seconds, with about 281 MB RSS growth during compilation. ATOMIC streamed 1,076,880 train rows, generated 17 modules and about 32.96 MB in about 4.66 seconds, with about 491 MB RSS growth. The 700-case combined test passed every sampled query but uses roughly 0.6 GB additional RSS. The build throughput is healthy; eager object allocation at import is the limiting stage.

Generated storage and query planning

The scalable model uses integer dictionaries for source IDs, entities or senses, predicates, scalar types, worlds, domains, and repeated strings. Facts are immutable rows in relation-and-scope shards. Postings contain sorted integer claim IDs. Provenance uses compact claim-to-source tables and separate derivation records rather than repeating source strings in every object.

For current public KBs the runtime computes one of a fixed set of lemma, synset, or event buckets. It reads the compiler-generated module as a restricted Object.freeze(JSON_VALUE) envelope and parses the JSON payload without evaluating it. This permits real eviction, unlike dynamic ESM import whose registry retains modules for the process lifetime. Corpus and user strings never become paths. Future sources still need richer manifest metadata for predicates, worlds, domains, time coverage, entity ranges, counts, and dependencies.

The planner uses recorded resident-memory estimates—about 349 MiB for eager WordNet and 284 MiB for eager ATOMIC—not their much smaller disk sizes. With no target it selects eager mode. With --memory-mb, it reserves 96 MiB for the process and chooses eager providers only while they fit, assigning the rest bounded caches. The target is explicitly soft; hard containment requires an OS or container control.

Time, space, domain, and worlds

Time is not a predicate suffix. A claim distinguishes source-record time, ingestion time, and valid time. Valid time may be an instant, interval, recurring condition, event order, or unknown. “Current” is evaluated against an explicit query/evaluation time and frozen source snapshot. Historical statements remain available instead of being overwritten.

Space separates administrative containment, physical part-whole, coordinates and reference systems, topology, relative direction, distance, and event location. A disputed boundary or approximate coordinate retains its source and precision. Spatial rules declare their coordinate system and whether composition is valid.

Conceptual domains form a versioned hierarchy covering lexical semantics and fields such as biology, medicine, physics, chemistry, astronomy, geography, history, social behavior, and literature. Domains select terminology, units, executors, and shards; they are not truth weights. Cross-domain claims retain multiple domain IDs.

Every contextual claim belongs to a world. Actual-world sources use world:actual. Each fictional universe, work, canon, or edition has a distinct world. A benchmark story and a user's thought experiment create ephemeral worlds. Beliefs and reports add perspective, so a character may believe something false without changing the fictional world's state.

A hypothetical question creates an immutable branch from a named base world, adds assumptions, and runs scoped reasoning. Contradicting the base does not rewrite it. The answer states whether it is deductive under assumptions, defeasible, abductive, or unknown. Real background knowledge enters a fictional or hypothetical world only through a declared bridge policy.

A gate fails when peak memory follows complete source size, a query loads unrelated domains, alias ambiguity is rejected at build time, a small overlay triggers whole-model closure, an unexplained superlinear hotspot appears, or the probe discovers an unrepresented stratum. The failure produces an architecture change and a new probe; it does not justify silently dropping the difficult records.
