The promoted core and generated knowledge modules

The default graph rooted at training/model/manifest.mjs was generated from 10,000 bAbI Task 15 train episodes and contains reusable language and reasoning policy, not story answers. QUICK adds a small v1 fact/rule graph. WordNet and ATOMIC add source-specific generated providers that preserve lexical senses and defeasible event relations.

Why the persistent fact tables are empty

Each bAbI case defines a new world. A name such as Gertrude may have a different class in another episode, and a class such as mice may fear a different class. Promoting any of those story facts globally would leak train worlds into unrelated test worlds. The correct compiled representation is therefore a small episode compiler: it recognizes the recurring constructions, creates temporary entities, facts, and rules from the supplied story, answers the question, and discards the world.

Recorded run evidence

The generated modules total 1,743 bytes. synthesis-report.json records coverage and limitations, while training-run.json records acquisition, deterministic preparation, full-train analysis by one coding agent, candidate validation, promotion, and the held-out result. Integrity digests remain in those machine-readable artifacts rather than being repeated on this page.

The v1 ledger verified the 20 prepared chunk files but was not used as a completion journal; every ledger entry remains pending. The full-train analysis and candidate validation support the recorded synthesis, not nonexistent per-chunk or parallel-worker receipts.

The training run reports 40,000 individual classifications, 40,000 universal-rule observations over 12 class-pair signatures, and zero unsupported statements. The answer distribution was measured during train-only analysis but not placed in generated code. Test hash and accuracy are attached only after candidate handoff.

Runtime composition

modelWithSession merges the promoted frozen arrays with an explicit session overlay. For Task 15, each universal statement adds one rule and each individual statement adds one fact. deriveClosure runs over that combined view. The promoted object stays unchanged, so separate benchmark cases cannot contaminate one another.

The generated top-level QUICK manifest contains their merged graph. WordNet instead contains lemma and synset shards; ATOMIC contains event shards. The all-module closure is not the sum of standalone closures. Predicates are shared intentionally, so animals can prove that a penguin is a living being and child-basic can then apply its living-being rules. Every cross-module consequence records both rule and fact provenance. The merged manifest lists active KB IDs and marks the artifact non-comparable to the default public run.

Validation

The skill-local validator rejects forbidden ambient capabilities and checks the imported model shape. The project validator checks model format, entities, facts, rules, reasoning thresholds, alias uniqueness, and equality between canonical facts and generated postings. Empty indexes are valid only because canonical persistent facts are also empty. Candidate and promoted validation both passed for the recorded run.
