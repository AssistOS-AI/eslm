ESLM Documentation / Reasoning

Deduction, induction, and abduction

ESLM uses different output statuses for logically supported conclusions, data-driven generalizations, and possible explanations. This is not cosmetic labeling: each method runs a different algorithm, accepts a different query contract, and exposes different evidence.

The deduction measured by bAbI Task 15

The promoted model recognizes a universal statement, an individual classification, and a question about the resulting property. Consider the complete episode:

Mice are afraid of wolves.
Gertrude is a mouse.
What is Gertrude afraid of?

The first statement becomes a temporary rule. The generated morphology table maps plural mice to mouse and wolves to wolf. The second statement creates a temporary fact. The question resolves Gertrude and requests the value of afraid_of.

rule session:r0
  when: [?entity, is_a, mouse]
  then: [?entity, afraid_of, wolf]

fact session:f0
  [gertrude, is_a, mouse]

query
  [gertrude, afraid_of, ?value]

deriveClosure binds ?entity=gertrude, derives (gertrude, afraid_of, wolf), records the rule and supporting fact, and assigns deduction depth 1. The realizer returns “Gertrude is afraid of wolf.” The exact benchmark scorer compares the semantic value wolf, not the sentence wording. The public test contains 1,000 such held-out episodes and the current run answers all 1,000 correctly.

Bounded multi-step deduction

The same forward-chaining executor can compose rule conclusions into later premises. Its model policy currently permits at most eight rounds, while duplicate triple signatures stop cyclic rules from generating the same result repeatedly. Derived facts record their immediate supports, flattened source provenance, rule identifier, and depth.

The optional child-basic knowledge module and an isolated unit fixture both check the mortality example with these three conceptual steps:

man(?x)          → human(?x)
human(?x)        → living-being(?x)
living-being(?x) → will_die(?x, eventually)

Given “Jhon is a man”, the executor produces the eventual-death relation at depth 3. The promoted bAbI model deliberately does not include these world-knowledge rules, so its default answer to the same question is UNKNOWN. Adding --kb child-basic supplies them and returns ANSWERED. The parser and executor work in both configurations; selected knowledge determines whether a proof exists.

node src/cli.mjs ask "Jhon is a man. Is Jhon going to die?"
# status: UNKNOWN

node src/cli.mjs ask "Jhon is a man. Is Jhon going to die?" --kb child-basic
# status: ANSWERED, reasoning.depth: 3

Thresholded induction

Induction proposes a regularity from repeated examples; it does not prove a conclusion. The current algorithm considers only predicates allowlisted by the model. It groups entities by is_a class, counts how many known class members share a candidate predicate and value, and requires both a minimum support count and minimum observed coverage. The promoted policy requires three supports and coverage of at least 0.70.

In the unit fixture, four entities are sparrows and three of them have an asserted can fly fact. A factual query, “Can Dana fly?”, remains UNKNOWN. The explicitly probabilistic-form query, “Is Dana likely to fly?”, permits induction and returns:

status: INDUCTIVE
value: true
class: sparrow
support: 3
observed population: 4
confidence: 0.75

The confidence value is observed coverage, not a calibrated probability. Absence of a flight fact is not an explicit counterexample, and the current fact format has no general negative predicate semantics. bAbI Task 16 now supplies a second, model-scoped induction policy: color statements are typed, one-example transfer is allowed by that dataset's convention, conflicting candidates are ranked by the latest class-member evidence, and the proof retains target membership, exemplar membership and exemplar color. The accepted learning cycle scored 1,000/1,000 fresh and 1,000/1,000 aggregate official test cases, but this policy is not generalized to arbitrary natural-world properties.

Grounded abduction

Abduction starts from an observed result and searches for rule premises that could produce it. ESLM considers only rules explicitly marked abductive. The observation must already have direct or deductive support; the wording of a question alone cannot manufacture the effect being explained.

The unit fixture asserts that the lawn is wet and contains two forward rules: rain wets the lawn, and an active sprinkler wets the lawn. The query “What could explain why the lawn is wet?” matches both rule conclusions. Reversing them produces the missing premises (weather, condition, rain) and (sprinkler, state, on). Neither premise is asserted, so the response calls them hypotheses rather than causes.

The current score is a deterministic completeness heuristic based on supported and missing premises, not a probability of causation. There is no intervention model, causal discovery, mutually exclusive explanation logic, or public abductive benchmark result yet.

RetrievalDoes an asserted fact match?ANSWEREDThe accepted source directly states the semantic value.
