PrOntoQA: controlled ontology deduction and proof planning

PrOntoQA uses fictional ontologies and controlled proofs to test multi-step deduction outside memorized real-world facts. ESLM compiles its supported formula templates into generic finite propositional tasks and solves them with the same proof-producing Boolean entailment method available to other adapters; no dataset identifier or example constant enters the reasoner.

Current measurements: Read the generated PrOntoQA rows on the evaluation dashboard or inspect the raw v2 report. Fresh-receipt state and aggregate outcomes are not maintained here.

The adapter owns the controlled source language and grounding. The generic method owns formula semantics and the finite witness.

What the protocol measures

The source varies deduction rule family, proof width, hop depth, composition, and distractors. Development membership is balanced across every official experiment file rather than selected from an easy prefix. The official natural-language reference proof remains evaluator-only; semantic correctness requires the answer plus an independently valid solver witness, not textual imitation of that proof.

Method and witnesses

The adapter grounds its controlled finite ontology into validated atom, not, and, or, and implies formulas. It explicitly selects classical explosion because the documented generated calculus includes proof by contradiction; this choice is visible task metadata. The generic core checks the complete context, constructs a transitive query-relevance cone for consistent theories, and searches the negated query with deterministic DPLL. Entailment carries a replayable split/conflict certificate. Non-entailment would carry a complete countermodel. Inconsistent contexts solved under the source calculus retain a separate explosion certificate.

Algorithmic advance beyond exhaustive enumeration

The former exhaustive assignment method scaled as 2n and returned RESOURCE_LIMIT on larger theories. The accepted mechanism changes the algorithm: linear-size Tseitin encoding, unit propagation, deterministic branching, exact dependency closure, complete-context satisfiability, and a separate witness verifier. Search still has exponential worst-case complexity, so explicit atom, variable, clause, and node budgets remain. Crossing them retains the case and returns a resource witness; it never removes data from the denominator.

Fresh boundary and claim

A protected execution is fresh only when the official Apache-2.0 artifact is partitioned label-blind and all behavior modules, adapter code, tests, source identity, and membership are frozen before the protected loader opens. Only aggregates and rule-family counts may leave that evaluator; no protected sentence, identifier, label, reference proof, or per-case outcome may become repair input. A valid receipt establishes semantic entailment and witness validity for its frozen generated source, not natural-language proof-trace equivalence or an official leaderboard submission.
