Unanswered questions now preserve useful KB context

If the runtime cannot support an answer, it does not convert a nearby fact into one. For eligible UNKNOWN and UNPARSED results, it may attach a separate, bounded grounding bundle containing related entries, contributor KB versions, search receipts, truncation, and completeness. The bundle says answerSupported: false. It can help a person reformulate the question or ground a downstream LLM, while the primary answer and provenance remain unchanged.

Grounding uses the original visible text rather than parser corrections, queries exact bounded postings, and retains the session state produced earlier in the same episode. It does not run after RESOURCE_LIMIT, and incomplete provider searches cannot claim that no related evidence exists. See grounded failure recovery for examples and DS009 for the normative failure contract.

Evidence labels matter

The local evaluate and benchmark run scripts execute five authored fixture cases apiece. They are useful regression checks and explicitly carry benchmarkComparable: false. Public rows may instead be raw-language, source-template, structured-task, source-annotation, or solver-conformance tracks. Those routes validate different layers and must not share an unlabeled headline score.

A report can also be assembled today from an older frozen receipt. The report timestamp is assembly time; it is not the execution time of every row. Receipt audits distinguish current, historical-stale, historical-unrecoverable, invalid, and unavailable evidence. Forced-choice abstentions stay in the full denominator: a method that attempts no cases has 0% end-to-end accuracy, 0% attempt coverage, and no selective accuracy. The full dashboard and row-level diagnoses live only on the evaluation page.

Next release gates

  1. Evidence integrity: freeze a clean code and dependency identity, rerun feasible development tracks in isolated processes, measure real peak memory and elapsed time, and mark stale or unrecoverable receipts as historical.
  2. Generalization: replace row-hash “fresh” splits with generator-, template-, lexicon-, world-, proof-graph-, and source-grouped splits. Keep raw language separate from formulas and task adapters.
  3. Grounded failure quality: freeze independently authored answerable, partial, unanswerable, ambiguous, conflicting, typo, paraphrase, multi-KB, and distractor queries. Score answer support, abstention, retrieval recall and precision, citation validity, contradiction, unsupported claims, completeness, latency, and resource use separately.
  4. Production controls: add enforced process-level resource boundaries where promised, expand exact document indexes behind DS018–DS021 gates, and require replayable receipts for release claims.

The normative acceptance sequence is DS011. Evaluation and claim rules are in DS010. Source, routing, and cache gates are in DS016 through DS021.
