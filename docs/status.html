ESLM Documentation / Implementation status

Implemented Stage A boundary and the work that remains explicitly open

The repository has completed the structural reset from executable generated knowledge modules to a trusted generic runtime plus declarative KB packages. This page separates working behavior from architectural commitments that are specified but not yet implemented.

Implemented now

The runtime supports deterministic normalization and a controlled English subset, session facts and rules, explicit query objects, task frames, a capability registry, plan records, direct retrieval, safe Horn deduction, structured results, provenance, and structured unsupported-language or unresolved-goal behavior. The CLI exposes interactive, one-shot, batch, KB administration, training preparation, Codex dry-run or execution, evaluation, benchmark, and documentation operations.

The KB toolchain validates canonical record types and cross-record references, rejects unsafe rules, compiles stable JSON shards and manifests, checks hashes, opens allowlisted paths, and projects canonical data into reasoning indexes. quick exercises that generic path. Open English WordNet and ATOMIC have been rebuilt from preserved source caches as non-executable JSON packages with eager and query-directed loading.

Training has four self-contained skills and an isolated subprocess runner. Prepared legacy datasets, old candidates, transient work, the global generated model, and executable KB payloads have been removed. A training run now begins from an explicit train-visible packet, a namespace, and a hashed Stage A baseline analysis, and ends with an untrusted declarative candidate and receipt. The portable skill validator and trusted host compiler enforce the same field and reference contract. Candidate validation, compilation, package audit, and registration are distinct implemented operations. Promotion remains a distinct required gate but has no CLI command yet, so no candidate can become a published package merely by completing the currently implemented sequence.

Partially implemented

Contexts exist in records and result structures, but full branching world models, temporal projection, speaker commitments, and contradiction policies remain incomplete. Capability descriptors include induction and abduction, while the mature, generally usable execution path is retrieval plus safe Horn deduction. Resource plans and shard caches are exposed and exercised for public KBs, but operating-system hard memory enforcement is not claimed.

The evaluation and benchmark harnesses exist, but prepared public benchmark datasets were intentionally cleared during the reset. Fixed repository fixtures verify the new protocol while each public adapter is rebuilt under current split, packet, and package gates. Published numbers from the previous executable-module architecture were removed because they do not describe this runtime.

Not yet claimed

The project does not currently claim unrestricted English understanding, learned construction grammar, general temporal or modal reasoning, complete defeasible logic, unconstrained narrative generation, calibrated probabilistic language scoring, or parity with broad neural language models. The specifications describe how these capabilities must connect to explicit representations and evidence if implemented. Their presence in a DS file is not evidence that source and tests already satisfy them.

Acceptance path from here

The next implementation work deepens language constructions and discourse while keeping parser failures explicit; expands canonical logical types and context policies; adds capability methods with applicability checks and proof obligations; rebuilds benchmark adapters from frozen sources; runs benchmark-guided cycles using development-only packets; and publishes versioned capability and resource reports. Each step must preserve the security boundary, deterministic package behavior, negative controls, and core-versus-KB separation.

The normative phase sequence and acceptance conditions are in DS011. Documentation and current-state synchronization rules are in DS012.
