Processing-node architecture and exact strategy catalog

ESLM is a directed graph of bounded processing nodes, immutable typed packets, conditional edges, and non-voting authority gates. This chapter moves from one request-level circuit to the exact current strategy inventory. Every level preserves the same rule: confidence may choose work or a candidate, while parser, safety, schema, method, witness, and result contracts determine authority.

The two coordinates: zoom level and engineering plane

Zoom and plane answer different questions. A zoom level changes how much of the circuit is visible. An engineering plane changes what is being explained about that same circuit. Keeping the coordinates separate prevents an exact source module, a future graph node, a resource policy, and a semantic contract from being discussed as though they were equivalent objects.

Plane 1 — logical request and dataflow

The logical plane describes transformations without naming source files. A processing node has one stable responsibility, typed input and output, resource owner, exceptional outcomes, and receipt. A strategy is one reviewed implementation of a selectable node. A coordination node may compare candidates. An authority gate validates an invariant and cannot be reduced to a vote.

Graph roleEngineering meaning
Processing nodeOwns one typed responsibility, finite work, explicit normal and exceptional outputs, state effects, and a processing receipt.
StrategyImplements one selectable node contract. It can propose, abstain, fail, or exhaust its allocation, but cannot invoke another strategy or enlarge its own authority.
Coordination nodeAllocates work among several eligible strategies and arbitrates comparable typed candidates with correlation-aware confidence.
Authority gateChecks a parser, schema, safety, semantic, proof, package, or result invariant. It returns accept, reject, or gap and never participates in voting.

Zoom 0 · the complete request circuit

Ingress bounds text and session state. Interpretation and request planning establish executable meaning and obligations. Retrieval and method execution assemble evidence and a witness. Verification independently checks that witness. Construction can then shape accepted claims or an explicit gap, but it cannot add a fact or repair invalid reasoning. Conditional recovery paths branch from this circuit without changing those authority boundaries.

Zoom 1 · language and request macro-circuit

The English-likelihood boundary runs before this view and can refuse likely non-English input without translation. Direct interpretation executes first. Explicit request force may restore the incoming session snapshot and build ordered obligations before source-like instruction text commits as facts. Otherwise eligible outcomes admit local controlled-English proposals. The coordination node compares parse-only Semantic IR rather than answer success, and the semantic reparse gate protects operators and rejects unsafe meaning changes.

Zoom 1 · knowledge and reasoning macro-circuit

Focus uses task roles and visible content to choose bounded retrieval surfaces. Retrieval produces records with provenance and search completeness. Evidence assessment ranks that finite frontier using inspectable relevance signals. Method planning matches semantic capabilities rather than words, and the selected reasoning method returns values or hypotheses with its own witness. A high retrieval score cannot become a premise, and method applicability confidence cannot replace execution.

Zoom 1 · verification, construction, and inability

The witness gate replays bounded evidence without rerunning the executor. An invalid or exhausted witness produces a gap rather than a weak truth vote. Result construction owns format and coverage only. Separately, an eligible inability can schedule bounded related-evidence retrieval. The returned grounding bundle remains outside the answer, carries answerSupported: false, and preserves the primary status, values, provenance, and contributor accounting.

Zoom 2 · one selectable node from the inside

The host resolves exact statically registered identities, then preallocates and freezes a separate finite envelope for every eligible strategy in canonical identity order. The asynchronous coordinator starts all funded independent branches before awaiting their shared barrier; failures remain branch-local, and zero-allocation branches are recorded without execution. Completion order never enters the canonical receipt, which contains no timing fields. The synchronous coordinator and the current deployed local-language path remain sequential until explicitly migrated. Each branch returns a typed proposal, confidence kind, correlation group, resource receipt, or explicit abstention, failure, or resource outcome. Concurrent execution and greater resource spend add no confidence: only validated evidence from independent correlation groups contributes separate support. The selected candidate must still cross the separate type, semantic, safety, or proof authority gate, which never votes and can reject every candidate.

Only coordination nodes vote. A reasoning node instead returns semantic values or hypotheses plus a method witness. A parser, schema validator, safety check, witness verifier, result contract, or package compiler is an authority gate. Agreement among unverified methods does not authorize an answer, and a failed mandatory gate cannot be outvoted.

Conditional and exceptional edges

EdgeTrigger, carried state, and authority consequence

Incomplete frontierA lookup, source, byte, candidate, or receipt bound carries an explicit coverage gap. Unvisited evidence cannot be interpreted as absent.

Provider transaction failureA failed begin, query, or cleanup phase discards that provider's tentative contribution and adds a bounded diagnostic; independent providers may continue.
Unsupported constructionIf accepted semantic content cannot satisfy the output contract, construction returns a typed output gap rather than inventing presentation content.

Plane 2 — named data and protocol boundaries

Later nodes consume typed packets rather than repeatedly reinterpreting prose. Every live packet identity has a closed high-level contract; its semantic owner additionally validates nested values and exact domain schemas. A packet carries only the authority established before its edge. A strategy receipt proves that an invocation was accounted for, not that its proposal or answer was correct.
