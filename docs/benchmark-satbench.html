SATBench: Boolean search, assignments, and unsatisfiability certificates

SATBench asks whether generated propositional constraint systems are satisfiable. ESLM's completed track consumes the official machine-readable CNF annotation and evaluates the generic SAT method. It is a fresh symbolic result, but it is not the authors' natural-language-only prompt score.

What is tested

The official source contains 2,100 cases balanced between satisfiable and unsatisfiable instances, with 5 through 90 variables and easy, medium, and hard groupings. Every row is retained. The label-blind partition reserves 420 cases for development and seals 1,680 for one fresh execution. No file or valid case is rejected because of its size; the JSONL source is streamed and resource use is recorded separately from semantic acceptance.

Each signed integer literal becomes a generic Boolean atom or its negation, each source clause becomes a disjunction, and the complete constraint set becomes strict premises. Deterministic DPLL uses unit propagation and bounded search. For satisfiable inputs, the output contains a total assignment and a separate verifier checks every original clause. For unsatisfiable inputs, the output contains a split/conflict certificate and a separate replay verifies that both branches close. A bare SAT or UNSAT label is insufficient.

How to read the fresh result

All 420 development cases passed before the adapter, generic solver, verifier, tests, source identity, and partition membership were frozen. The fresh evaluator then opened the 1,680 protected members once and returned only aggregates: no puzzle, clause, identifier, assignment, certificate, label, or per-case outcome left the evaluator. All 1,680 fresh cases passed and every witness was independently valid. The dashboard displays that exact tested/available denominator and the zero Language Agent count from the live JSON report.

The result applies to the source-annotated formula track. The authors' public prediction protocol supplies a scenario, natural-language conditions, and a question without the clauses annotation. Consequently, 100% here means complete fresh execution of the frozen symbolic track; it must not be reported as a natural-language leaderboard score. A future English constraint compiler needs its own development boundary and a new untouched evaluation source.

Why the method is reusable

The reasoner exposes Boolean formulas, assignments, conflicts, and budgets; it has no benchmark dispatch and does not know SATBench fields. Clause order and variable renaming are invariant, while removing a conflicting clause changes an unsatisfiable instance into a satisfiable one in contrast tests. The same method already supports query-directed entailment in PrOntoQA. This is an algorithmic capability—DPLL search with independently checked evidence—not a table of benchmark answers.

Source and citation

The dataset and code revisions are pinned on the source registry. The official dataset card declares Apache-2.0. The benchmark publication is SATBench: Benchmarking the Reasoning Capability of Large Language Models in Satisfiability Problems (EMNLP 2025).
