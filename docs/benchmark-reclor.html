ReClor: logical analysis of arguments in unrestricted passages

ReClor asks a reader to choose one of four answers after analyzing a short argument. The questions span entailment, assumptions, flaws, principles, strengthening, weakening, resolution, and parallel reasoning. ESLM has a complete source adapter and task boundary, but it does not yet have a generic method that can justify these choices from unrestricted English.

What the current run means

The official v1 release contains 4,638 training, 500 validation, and 1,000 test records. Every train and validation record is retained and streamed through a closed schema. The preferred option is removed from the visible task and held by the evaluation host. The test file is retained in the ignored cache but was never parsed; only its byte length and digest were checked.

All 500 validation tasks reached the capability registry. Every one returned NO_APPLICABLE_METHOD, so the dashboard shows 500 of 500 task contracts executed and no accuracy percentage. This is not 0/500: the runtime did not choose 500 wrong answers. It refused to guess before an argument method existed. The Language Agent was not called because translation cannot supply the missing argument semantics.

Required generic method

A defensible method must compile propositions, quantifiers, conditionals, alternatives, causal claims, normative principles, speaker commitments, and discourse roles into an explicit argument graph. It must distinguish the question operator—entails, assumes, weakens, strengthens, explains, resolves, matches a flaw, or instantiates a principle—then evaluate every candidate using proofs, countermodels, or typed defeaters. Candidate order and open-class vocabulary must remain renameable; removing or reversing a premise must change only the consequences licensed by that premise. A broad multiple-choice heuristic would not satisfy this contract.

A deliberately smaller candidate was tested before expanding this design. It accepts only complete monadic categorical propositions—all, none, some, and some-not—and only necessary-conclusion or sufficient-premise questions. It checks every candidate by finite satisfiability: a qualifying candidate makes the premises plus the negated obligation inconsistent; a nonqualifying candidate receives a concrete object-type countermodel. The generic executor passes complete renaming, premise ordering, candidate permutation, semantic reversal, and proof-replay controls.

The candidate remains unregistered. A complete train-and-validation projection audit found no ReClor record for which the question operator, every premise, the conclusion boundary when needed, and all four candidates were simultaneously inside that fragment. Registering it would enlarge the trusted runtime without an executable source use case. More importantly, silently ignoring an opaque conditional or compound candidate can reverse the correct choice. The detailed rejection and failure clusters are retained as review evidence; this is an engineering coverage gap, not an impossibility result.

The relevant theoretical background includes informal logic, theories of argument, and abstract argumentation frameworks. Those sources motivate representations; they do not replace source-grounded implementation and falsification tests.

Source, rights, and claim boundary

The official encrypted release and repository revision are pinned in the source registry. The official README delivers the data for non-commercial research and publishes the extraction password, but it does not state a separate dataset license identifier. The cache is therefore local and source rows are not redistributed. Cite Weihao Yu, Zihang Jiang, Yanfei Dong, and Jiashi Feng, ReClor: A Reading Comprehension Dataset Requiring Logical Reasoning, ICLR 2020.
