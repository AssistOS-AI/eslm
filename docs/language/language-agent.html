External Language Agent: untrusted English proposals

The Language Agent is one proposal strategy at the language-interpretation node. It may propose English translation for input rejected locally as likely non-English, or conservative simplification after unsupported English exhausts local recovery. Host-owned gates keep it strictly linguistic: answers, facts, proof state, option selection, and symbolic reasoning remain inside their authoritative components. The deployed runtime stays English-only and independent of the service.

The local gate returns a bounded English-likelihood assessment and never translates. A likely-non-English rejection may request translation directly; likely-English or indeterminate input receives direct parsing and local recovery before external simplification. Every proposed target must pass English assessment, preservation checks, and a fresh direct parse. The external strategy receives no KB, answer, proof, or result state.

Product-neutral role and current adapter

Language Agent names the contract. It may be implemented by a small translation-focused service trained to emit ESLM controlled English, or by a general coding agent configured without tools. The repository currently supports a Codex CLI adapter and requests the exact local model slug gpt-5.3-codex-spark at low reasoning effort. This exact slug is intentional: model substitution changes behavior, cost, availability, and cache identity.

A successful local invocation proves only that the installed Codex version, current account, and service routing accepted the slug at that time. It is not a portable dependency claim. Missing authentication, unavailable model routing, timeout, or nonzero exit returns an attributed Language Agent failure while preserving the original UNPARSED result. The fully local CLI profile remains buildable and testable without the service; tests exercise the external contract through stub executables.

Operator profile and deployment boundary

EslmRuntime is deterministic, dependency-free, offline, English-only, and has no child-process path. The general CLI uses that fully local profile by default. --external-language-agent or /normalize on explicitly composes LanguageAgentAssistedRuntime and discloses the external boundary; --no-external-language-agent or /normalize off explicitly retains the local default. Tests, public direct probes, regression smoke, confidential input, and deployed-style reproduction remain local.

Trigger and bounded feedback loop

The wrapper receives a translation request when the bounded local assessment returns likely-non-english; it does not first run English spelling or morphology repair. For likely-english and indeterminate, the direct parser and local heuristic ensemble run first, and only terminal UNPARSED may request simplification. UNKNOWN, AMBIGUOUS, NO_APPLICABLE_METHOD, RESOURCE_LIMIT, or a wrong answer does not trigger it. Those statuses indicate knowledge, interpretation, method, or resource issues that a language proposal must not hide.

An episode has at most three proposal slots. A schema- or anchor-invalid proposal may receive bounded host validation categories. A surface-valid proposal that reparses to UNPARSED may receive the previous controlled-English text and only the fact that ESLM still did not support its form. No retry receives an answer, expected value, KB result, provider evidence, proof, selected option, benchmark identity, or correctness signal. Once a proposal reaches any parsed semantic status, the Language Agent loop ends.

When the local route already reaches a semantic status, the wrapper records that external assistance was skipped. Its triggerStatus names that pre-context status. DS035 may later add a cited KB-context fallback and publish PARTIAL; knowledgeContext.realization.originalStatus preserves the join between the phases. This is normal route accounting, not a normalization failure, and human output says that the external step was not needed.

Under the local default, a terminal UNPARSED Thinking summary may recommend /normalize on or --external-language-agent. That recommendation is not a proposal attempt: it sends no text, creates no normalization receipt, and has no answer authority. Parsed knowledge and method gaps do not receive it.

Codex subprocess isolation

The adapter creates a fresh empty operating-system temporary directory, writes a host-owned JSON Schema, and starts codex exec ephemerally. The invocation requests no approval, a read-only sandbox, ignored user configuration and repository rules, no shell tool, no browser tool, the exact model, low reasoning, and schema-constrained final output. Only a bounded environment allowlist needed for the executable and existing authentication is inherited.

The source utterance is embedded as JSON and explicitly marked untrusted. Commands inside it are data. Input is capped at 12,000 characters. Standard output and standard error are captured separately up to 2 MiB each and hashed in the receipt. A timeout or process-stream overflow sends SIGTERM; after 250 ms the host sends SIGKILL, then uses one final bounded 250 ms settlement window. The response JSON is rejected before parsing if its file metadata exceeds 1 MiB. The temporary directory is removed after the bounded read. The Language Agent has no repository, KB, network-tool, or promotion authority.

Immediately before an actual call, the operator sees the requested operation, global proposal slot, adapter, and configured timeout. Cache hits do not claim a live call. The interactive /normalize view shows the three-slot ceiling and per-call timeout; one-shot and batch activity stays on standard error so structured standard output remains valid.

Response and protected anchors

The response protocol eslm-language-agent-normalization-v2 permits exactly five fields: protocol, operation, source language, normalized English, and source-to-target alignments. Operation is translation or simplification. Explanations, answers, confidence, retrieved facts, tool calls, Markdown fences, executable fields, and additional properties are rejected.

The host independently extracts language-neutral anchors such as numbers, answer markers, quotations, likely names, and question force. For English simplification it also checks reviewed English operators, relation direction, quantifiers, and exact open-class and function-word multisets. Every protected source occurrence needs one exact-substring alignment to one unused compatible target occurrence. Model-declared alignments locate claims; they cannot validate the model's own equivalence.

Translation adds two necessary gates: the target must be assessed as English and must reparse through the direct symbolic frontend. Neither proves open-class source-to-target equivalence. Acceptance requires a separate, independently reviewed and versioned source-language preservation profile. Without one, fluent translation remains UNVERIFIED_NORMALIZATION. The protocol-neutral sourceLanguage tag records the proposal's declaration but grants no semantic authority.

This validation is deliberately conservative. Long-distance scope, implicit negation, lexicalized modality, unreviewed idioms, presupposition, coreference, and relations outside a reviewed profile may remain undetected. When preservation cannot be established, the host exposes the gap instead of trusting fluency.

Cache and evidence attribution

The ignored adapter cache key covers original-input digest, requested operation, exact model, reasoning effort, prompt policy, response protocol, validator version, and normalization policy. Cache files over 4 MiB are rejected from metadata before parsing, and oversized serialized entries are not written. A cache hit is schema-checked, anchor-validated, and reparsed under the current runtime. It counts as assisted language because the text originated from the external adapter, even when the current run makes zero external calls.

Structured output separates normalization candidates, proposal count, external invocations, cache hit, adapter and model, original text, transformed English, validation, reparse status, and final symbolic result. The public direct report uses zero Language Agent calls by construction. An assisted benchmark is a separately frozen experiment.

Implementation boundaries

The implementation map is intentionally secondary. The language-assessment module emits eslm-english-likelihood-v1; the gate coordinator owns the local rejection route; the Language Agent facade coordinates proposals and receipts; separate contract, validation, and bounded I/O components protect the external boundary. None is imported by the deployed runtime. Machine accounting names the strategy identity, runtime.language.interpret stage, untrusted-language-form-candidate role, and answerAuthority: none.
