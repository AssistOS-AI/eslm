ESLM Documentation / Language / Heuristic language approximation

Fast local English interpretation inside a disclosed assisted CLI

The heuristic language route extends controlled-English coverage with deterministic, confidence-bearing proposals. It repairs near-CNL wording, decomposes suitable complex requests, reparses every candidate through the ordinary symbolic runtime, and preserves uncertainty whenever several interpretations remain plausible.

The bounded English-likelihood gate rejects likely non-English input without translating it. English and indeterminate input continue to the direct parser. Explicit request force may select a query-local construction plan without retaining tentative direct assertions; otherwise eligible statuses may enter bounded local proposal inspection. Visible structural cues and parse-only Semantic IR decide whether an alternative is accepted. The general CLI's disclosed external strategy may propose translation for a gate rejection or simplification after English local recovery remains UNPARSED. Ordinary inability grounding follows the final result and cannot influence wording.

Proposal lattice, voting, and confidence

A permissive direct parser can accept a malformed question into the wrong UNKNOWN frame or flatten an apposition, coordination, or another visible cue while returning SOLVED or PARTIAL. Treating every parsed result as irrevocable would preserve those wrong meanings. ESLM therefore inspects bounded candidates for all four statuses. This is not answer-guided rewriting: candidate acceptance sees only parser and session compilation. A direct SOLVED or PARTIAL changes only when an accepted candidate has different Semantic IR; equal IR keeps the direct result, and a normal knowledge gap with no structurally licensed alternative passes through unchanged.

The analyzer preserves the original text and builds a bounded lattice of alternative repairs rather than destructively rewriting it once. Every edge records the source spans it changed, the heuristic family that proposed the change, protected operators, unresolved semantic risks, edit cost, and its confidence contribution. Compatible edges may compose. Equivalent terminal strings merge while retaining all independent supporting paths; semantically different candidates remain separate.

Heuristic families vote for candidates instead of choosing answers. Agreement among independent spelling, morphology, agreement, punctuation, and structural heuristics raises an interpretation score. Inferred open-class words, removed material, competing candidates, and interacting repairs lower it. The score estimates confidence in the interpretation, never confidence that the eventual answer is true. Candidates above the active work threshold are reparsed without persistent session effects. Close accepted candidates with different meanings yield an explicit ambiguity rather than a winner chosen by order.

A parser-accepted candidate receives no privileged path. Assertions, queries, provider access, planning, reasoning, provenance, and resource limits remain unchanged. Because a guessed spelling or decomposition can still differ from user intent, a result reached through a materially changed interpretation carries qualified epistemic status and an approximation receipt.

How a progressive verb gets its lemma

The runtime uses the rest of the episode as structural evidence instead of guessing from an -ing token in isolation. It first aligns three roles: the questioned entity must be an explicit member of a class, a universal rule must describe that class, and the rule and question must share the same object. An unrelated nearby verb is therefore ineligible.

  1. Generate a bounded set of possible lemmas from the progressive question.
  2. Prefer an exact finite-form round trip when available: invert the rule's observed third-person form to a candidate lemma, then regenerate it and require an exact match. This distinguishes forms such as ties → tie → ties, vies → vie → vies, and cries → cry → cries.
  3. Otherwise compare the observed rule predicate with the candidate finite forms using bounded Damerau edit distance. A unique nearest form supplies the contextual lemma.
  4. If direct lemma surfaces remain tied at the same edit distance, prefer one only when it preserves strictly more occurrences from the source token's character multiset. Equal coverage remains unresolved; alphabetical order does not choose a meaning.

This hierarchy lets renamed frames converge for spelling and morphology combinations around water, fix, pass, buzz, map, and move. It does not prove that arbitrary English morphology is solved. An unresolved contextual comparison supplies no contextual vote, KB frequency and answer success remain invisible, and the normal uncertain progressive analysis is still subject to voting, semantic protection, and reparse.

Decomposition techniques and their safety gates

Each technique below creates a proposal only when its local structural preconditions are visible. The safety column is executable review evidence, not an informal assurance.

Unsafe splits are first-class declined proposals. For example, splitting a negated coordination can change the scope of not; extracting a restrictive relative clause can create a false global fact; deleting because can erase the relation the user asked about. A declined edge retains its reason in the receipt, making conservative failure reviewable and giving future work a concrete acceptance target.

Request-intent planning for larger outputs

Request-force analysis runs independently of the ordinary direct result. If an explicit request is recognized, the runtime restores the caller's incoming session snapshot before planning, so quoted material or sentence-like content that direct parsing tentatively learned cannot persist. This preemption is query-local and changes task interpretation only; it does not grant the planner factual authority.

Requests such as summarize, expand, explain, compare, draft an essay, or assemble a document need more than sentence repair. The request-intent planner represents them as an explicit output contract and a bounded graph of subrequests. Proposals identify the requested operation, subject, audience, length or structure constraints, comparison axes, evidence requirements, and desired output form. Independent construction cues vote on those fields, and unresolved alternatives remain visible with confidence and gap records.

The current route first requires explicit request force: an imperative, negative imperative, polite modal request, first-person desire frame, explicit question, or bounded nominal request ending in “please.” Merely mentioning a report, essay, or summary in a declaration does not create a task. Negation covers coordinated operations and complements until punctuation or a contrastive boundary; a later “but” or “instead” instruction is analyzed independently.

Quoted source material is inert during intent matching, while instructions before and after the quotation remain active. Thus “Summarize ‘…’ as a table” retains the table constraint without treating command-looking source text as an instruction. Source markers such as “this text” and “following passage” never become retrieval topics. Topic receipts separately count observed and unique candidates, returned topics, count omissions, character truncations, and normalization collisions.

For a multi-instruction request, each segment owns its operation, topics, confidence, and output contract in discourse order. The bounded dependency graph creates operation-specific selection and shaping nodes; later operations depend on the previous shaped result, and an aggregate node combines the artifacts. When at least one obligation has supplied or KB material, grounded symbolic generation executes five named responsibilities: freeze the work order, admit provenance-bound claims through a non-voting gate, assign admitted claims to rhetorical sections, realize evidence-aligned sentences, and assemble the requested document form. Every obligation receives a visible grounded section or gap and an operationArtifacts receipt with its evidence, format, comparison witness, and gaps. A request with no admitted material still produces no fabricated document. Uncoordinated close intent alternatives remain AMBIGUOUS.

Current grounded construction returns PARTIAL. Four sentence strategies can realize a supplied source sentence, lexical definition, typed fact, or explicitly causal defeasible relation. Eight discourse and format strategies can plan sections, fuse compatible claims, state supported comparisons and coverage gaps, and assemble prose, sections, outlines, or tables. The final result contract reproduces every sentence, citation, section, and strategy trace from the closed plan and admitted evidence. Missing causal support, incomplete search, rejected records, and output-budget omissions remain visible gaps; relevance and polished wording never become proof. Future research extends this source-bound baseline to newly derived or abstractive claims only with separate derivation witnesses and claim-level verification.

The request-pattern catalog is versioned and grows through reviewed generic patterns, renamed examples, meaning-changing controls, confidence calibration, and release tests. Runtime requests may reveal useful failure clusters, but deployed execution never rewrites its own rules or memorizes an answer. This keeps step-by-step improvement visible and reproducible.

Content-focused grounding

Related-KB retrieval ranks accepted entity or predicate identities first, followed by exact multiword content phrases, content nouns and verbs, and conservative morphological variants. Articles, determiners, quantifiers, auxiliaries, copulas, pronouns, conjunctions, prepositions, request directives, output nouns, and style qualifiers are excluded as primary topics while content terms are available.

This rule keeps all out of the search topics for “All mura et bana”: all is a protected quantifier, while mura, the inferred predicate candidate, and bana carry subject matter. A quoted or definition-framed request such as “What does ‘all’ mean?” provides the explicit metalinguistic exception. The term-selection receipt exposes phrase boundaries, grammatical role, inclusion scores, exclusion reasons, variants, omissions, and search completeness.

A second, independent relevance estimator ranks the bounded records returned by those postings. It combines exact phrase and term coverage, co-occurrence of several focus terms, coverage of entity/predicate/object roles, a typed answer-bridge match, and a capped logarithmic vote for occurrence evidence in the active KB. This gives a fast symbolic estimate of which records are worth reviewing or reasoning over. Frequency is deliberately non-absolute: a very common token cannot outrank a record that matches the complete semantic frame merely because it appears more often.

Each ranked record exposes its matched terms and roles, frontier document frequency, available active-posting count, answer-bridge score, and additive relevance contribution. The receipt continues to declare answerSupported: false. A possible bridge is a retrieval hypothesis that can feed a later registered reasoner; it is not itself a proof or an answer.

From heuristic families to independently testable strategies

The built-in strategy catalog gives the major DS022 techniques exact identities across language approximation, request planning, query focus, retrieval ranking, reasoning, and result construction. This makes the research unit visible: contextual predicate spelling can be calibrated separately from clause decomposition; active-KB frequency can be ablated separately from term co-occurrence; and one output shaper can be compared with another under the same evidence ledger. Correlation groups stop duplicate implementations of one cue from manufacturing independent confidence.

All 24 approximation families are now real coordinated executors. A sealed StrategyRegistry binds each descriptor to its implementation. The synchronous stage coordinator resolves the exact allowlist, sorts identities canonically, reserves one invocation slot per family, validates every bounded eslm-strategy-result-v1, contains failures, and returns an eslm-strategy-execution-receipt-v1. Edit-distance work is a separate owner-specific dimension allocated only to the three spelling and predicate families that consume it; family receipts expose both that allocation and actual evaluations. The specialized DS022 proposal lattice then composes compatible edits, applies protected-anchor checks, votes over complete sentence candidates, and chooses reparse work. The coordinator's generic output ranking is executor accounting; it is not the final language interpretation arbiter.

--strategy-select and interactive /strategy can select an exact language subset, but the mandatory strategy:language:direct-controlled-parser@1 must remain. The approximation receipt exposes selection mode, selected exact identities, every family result, work, candidate votes, reparses, and session rollback. Request, focus, relevance, and construction identities are also real execution gates, though their owner modules remain instrumented-local. Named --strategy-preset and /strategies PRESET values only filter the inventory view and never change behavior. The Processing-node strategies chapter explains the three implementation states, finite work, voting, and remaining integration gates.

Local-first operation and bounded effort

Local heuristics use no network, child process, model, KB scan, or mutable global dictionary. The general CLI uses them without the external wrapper by default. --external-language-agent explicitly opts into that wrapper, which announces every real external proposal immediately before invocation; --no-external-language-agent explicitly retains the local default. Structured output preserves a machine-readable activity receipt. A cache-assisted route remains attributed to the Language Agent without being described as a live call.

Named work profiles coordinate candidate generation, reparses, proof search, provider routing, and grounding breadth through exact finite limits. Increasing a profile can complete a previously truncated search, but it cannot change logic, trust, tie-breaking, answer authority, or the meaning of an inability status. The result records requested and effective effort together with exhausted budgets, so speed and coverage remain inspectable.

Acceptance evidence

Acceptance tests cover renamed nonce entities and predicates, punctuation and agreement variants, unique and tied spelling repairs, predicate morphology, quantified rules, missing auxiliaries, request-envelope reduction, complex decomposition, unsafe declined splits, confidence monotonicity, deterministic replay, rollback, and hard candidate limits. Grounding tests prove that function words such as all are excluded from ordinary topical lookup and included for explicit metalinguistic questions.

The separate generated heuristic development report broadens that evidence to 1,200 deterministic runtime episodes instantiated from 43 reviewed shapes across 18 domains and 28 target families. The default receipt records 1,200 unique surface inputs and 593 of 774 possible declared technique-by-domain cells. Its typed oracles, nonce content, direct controls, four spelling processes, explicit morphology strata, repair-required forms, and unsafe contrasts expose aggregate behavior by oracle level, technique, target family, complexity, route, status, confidence, and resources. The eight oracle levels distinguish answer execution, semantic-query execution, candidate selection, query-local decomposition, request execution, request planning, proposal-only preservation, and safety abstention. Semantic-query execution requires the expected relation-shaped query even when evidence is missing; candidate selection binds the winning candidate, family, accepted parse-only reparse, episode, route, and status without claiming a complete relational query. Request planning records a correctly understood obligation that lacks source material, while request execution requires construction. The fixed-seed report is regenerated from the current source before release. Proposal-only rows measure proposal reach and safety, not executable interpretation. Route and status must therefore accompany the mixed contract rate. Earliest-failure clusters preserve domain and technique distributions. Maintainers use those collective signals to prioritize generic strategy work, then replay another seed and the focused safety tests before promotion. The report remains development-visible and explicitly non-comparable with public benchmarks. Because each domain still owns a fixed predicate, the observed cell count is not independent domain-by-morphology evidence.

The green fixed seed closes the repeated clusters observed in the expanded pre-fix baseline; it does not prove general English morphology. The same expanded default previously passed 1,170/1,200, while five pre-fix independent seeds passed 5,898/6,000. Those collective failures justified the generic round-trip and contextual arbitration change. The current machine-validated five-seed audit receipt then passed all 6,000 declared contracts with no failure cluster. Within those runs, candidate-selection rows can select the expected candidate but end UNKNOWN with missingEntity; that is candidate-routing evidence, not proof of a complete relational IR. The receipt preserves exact seed names, suite and behavior identities, configurations, counts, clusters, replay commands, and a content digest. Its claim remains stability evidence only for this fixed 43-shape generator distribution. Template-disjoint, vocabulary-disjoint, independently authored, grounded-KB, and public evaluations remain separate evidence.
