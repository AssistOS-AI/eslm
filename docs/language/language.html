Language interpretation, controlled English, and executable task meaning

This chapter zooms into the language-interpretation processing node and its data contract. It receives a bounded utterance plus an immutable session snapshot, produces direct or proposed Semantic IR, passes accepted meaning through a non-voting semantic gate, and emits a task frame or a typed language gap. It does not retrieve answer evidence or execute reasoning while selecting an interpretation.

The logical processing architecture owns the end-to-end graph. This page owns language meaning, protected source alignments, query-local session effects, and task-frame construction. Work allocation and strategy coordination are detailed in the heuristic and strategy chapters; implementation locations remain a reference concern rather than part of the language semantics.

The interpretation node and layered local recovery

Stage A implements a controlled natural language route for deterministic English constructions. Statements such as “Gertrude is a mouse,” “Mice are afraid of wolves,” and questions such as “What is Gertrude afraid of?” compile into entity references, predicates, constants, and safe rules. Movement, acquisition, release, property, possession, ability, class, and location constructions have additional bounded forms. The route is deliberately narrow and testable. It never pretends that an unrecognized phrase was understood merely because some tokens resemble a known form.

One implemented discourse slice handles simple transactional episodes without external help. An assertion-subject pronoun resolves only to the single current antecedent; lives in compiles to located_in; and a possessive location question resolves only through one exact owns edge. Where is her ferret living? and Where does his badger live? therefore preserve the possessed object as the query subject. A directly stated object location is strict retrieval. If only the owner's current location is known, ESLM may offer the owner's place as DEFEASIBLE, with confidence 0.62 and the explicit assumption that the possessed entity shares the owner's location. That grade is a fixed v1 heuristic, not a calibrated probability; missing or non-unique support remains unknown or ambiguous.

The deployed language contract is English-only. A bounded deterministic assessment returns likely-english, likely-non-english, or indeterminate. Its routing score combines the leading directional evidence share with bounded evidence mass. ASCII letters, nonce and technical words, and formulas are compatibility-only; common suffix shapes can add support only after a reviewed English function word, operator, or sentence frame is present. Long repeated identifiers or another ASCII-written language therefore cannot become likely English merely through length. Classified outcomes meet the visible threshold, weak or conflicting complete evidence remains below it, and incomplete inspection has zero routing confidence. The receipt validator recomputes the score from its signals. This confidence never authorizes meaning or an answer. The gate can refuse likely non-English text but never translates, guesses meaning, or treats unfamiliar names as evidence by themselves. Continuing input enters direct-symbolic, which performs Unicode and declared lexical normalization, session compilation, query parsing, task construction, capability selection, and reasoning without Language Agent, network access, or a language service. An ambiguous entity, missing capability, or resource limit remains on this route because those states do not establish a surface-language failure.

After the English-likelihood gate, the CLI builds the mandatory bounded basic-question and task context from explicit and embedded questions before direct execution. The context is answer-blind and never participates in language selection. The CLI independently recognizes explicit artifact requests so an imperative with source-like sentences cannot be committed as assertions. Otherwise direct UNPARSED and UNKNOWN enter deterministic local approximation for spelling, morphology, auxiliary reconstruction, request envelopes, and safe decomposition. Direct SOLVED or PARTIAL can also be challenged when a structurally licensed candidate has different parse-only Semantic IR; equal IR preserves the direct route. Eligible candidates return through the same parser and reasoner without persistent session effects. The dedicated heuristic language chapter explains the proposal lattice, voting, confidence, work policies, and content-focused grounding governed by DS022.

The general CLI remains local by default. --external-language-agent or /normalize on explicitly composes and discloses language-agent-assisted-normalization; --no-external-language-agent or /normalize off explicitly retains the local default. At the same logical interpretation node, the opted-in external strategy may propose translation after a likely-non-English rejection or simplification after English local recovery remains UNPARSED. A candidate again returns through the same non-voting English parser and reasoner, so the agent receives no privileged reasoning or knowledge path. Translation remains unverified without an independent reviewed source-language preservation profile. The complete protocol, feedback loop, adapter, validation schema, cache identity, and failure accounting are documented on the dedicated Language Agent page and governed by DS013.

The bounded gate refuses likely non-English input without translation; English and indeterminate input continue to the direct parser. UNPARSED and UNKNOWN enter the local proposal lattice; direct SOLVED or PARTIAL may also be compared with a structurally licensed alternative. Parse-only Semantic IR decides whether a candidate is accepted, and equal IR preserves the direct result. An accepted changed interpretation returns to the parser instead of entering reasoning through a privileged path. External proposals attach to this same node under a separate trust regime.

Normalization is observable

Normalization may regularize case, punctuation, and known spelling variants, but the runtime returns the original form, tokens, normalized form, corrections, and language code. This makes correction behavior reviewable and prevents a hidden preprocessor from silently rewriting the question. A correction must be deterministic, bounded, and tied to a known vocabulary or construction. When several corrections are plausible, the system should expose ambiguity rather than choose a semantically convenient one.

Language Agent proposals have a stricter and separately attributed record. English simplification requires one exact source-to-target alignment per protected occurrence, equality of typed protected identities, and preservation of normalized open-class and reviewed function-word multisets. Translation must additionally pass target-English assessment and direct reparse, but those checks cannot establish open-class cross-language equivalence. A model's alignment is not independent evidence; without a reviewed preservation profile, the host returns UNVERIFIED_NORMALIZATION. This page retains the frontend boundary; External Language Agent defines the response object, exact limits, and operational checks.

Protected meaning is not measured by an indiscriminate bag of words. The validator reasons over recognized constructions, typed anchors, argument roles, and direction rather than counting every repeated spelling. Unknown content stays visible instead of being guessed. The transformed question remains untrusted until the non-voting English parser accepts it and every independently checkable preservation obligation passes.

The interactive view presents accepted assistance as an explicit chain: original input, translated or simplified English, then the symbolic status and answer. This order lets an operator review what changed before interpreting the result. Rejected assistance similarly shows the original, any proposed English, and the validator or reparse reason rather than only a generic UNVERIFIED_NORMALIZATION label.

Every request also exposes a bounded operational view. A live muted line states that symbolic work started and names the effective work profile and selected caps. The completed gray panel summarizes route, human-readable outcome, method, cited support, task context, and resource limits. External proposal activity is separately attempt-aware and timed. These messages expose reproducible stage receipts and budgets rather than hidden chain-of-thought; a request-local validation failure is humanized, leaves session state unchanged, and returns control to the interactive prompt.

Terms, variables, predicates, and contexts

Ground entities have stable identifiers. Variables are explicit symbols such as ?entity and cannot be confused with entity identifiers. Assertions identify a subject, predicate, and value or object, and carry context, polarity, modality, confidence or trust metadata where the relevant DS contract requires it. Rules contain premises and conclusions; every conclusion variable must be bound by a positive premise. This range restriction is checked when canonical records are accepted, not postponed until a query happens to trigger the rule.

A context is not a text label added for display. It scopes assertions and establishes whether two claims may participate in the same derivation. Baseline world knowledge, a session episode, a hypothetical branch, quoted speech, or a source-specific view may be distinct contexts. A method must explicitly justify any projection or inheritance between them. Contradictory claims are therefore not automatically collapsed into one global truth value.

Discourse and session state

An interactive session can accumulate entities, facts, rules, and a last salient entity. That state is separate from promoted KB packages: saying “Gertrude is a mouse” in one session does not rewrite the repository’s world knowledge. Reference resolution consults the session context and reports failure when a pronoun or description has no unique valid antecedent. A batch request receives its own deterministic context unless its input format explicitly defines episodes.

Compilation is transactional. Every episode ending UNPARSED rolls back all tentative entities, facts, rules, and history, including an episode whose early assertions parsed but whose final question was unsupported. A selected changed interpretation always starts from the incoming session snapshot and remains query-local for every eligible direct status. The gate runs before selected public providers: input is limited to 64 KiB UTF-8, 128 segments of 8 KiB, and the retained overlay to 512 entities, 1,024 facts, 256 rules, and 1,024 history events. Nested fields and strings are also shape- and byte-bounded; excess returns RESOURCE_LIMIT without inference or provider consultation.

Session state is evidence in the result. Reviewers can determine which entity a query resolved to and whether the supporting assertion came from a loaded package or the current interaction. Movement updates replace the current location while retaining an ordered history. Acquisition causes an object to follow its holder’s later movements, and release leaves it at the holder’s current location. The supported predecessor question, such as “Where was the token before the hall?”, reads the state immediately preceding a named boundary and returns a witness containing both history events. This is a narrow state-history method, not general temporal logic.

Configured property induction

A surface statement such as “Ari is yellow” is not interpreted as a generic property merely because its adjective looks plausible. A loaded KB must declare the predicate’s allowed value domain. The babi-v1.2-language package declares the visible Task 16 color values and an explicit induction policy with minimum support, minimum coverage, selection strategy, and inductive uncertainty. When that package is selected, “What color is Bela?” can request the registered induction method. Its result retains observations, coverage, confidence, selection policy, and inductive status. Unloading the package removes that vocabulary and policy without changing trusted parser code.

Task adapters for non-conversational benchmark formats

Some benchmark artifacts already declare a machine task rather than an ordinary user question. Entity Tracking supplies an initial set of numbered boxes, an ordered program of Move, Put, and Remove operations, and one masked final container span. The adapter validates the official row, reconstructs the mask with a host-only oracle, and compiles the visible source into a label-free finite-relation-state-program-v1. That frame contains initial contains assertions, typed transfer, add, and remove transitions, and a relation query. The generic core executor never sees the source verbs or expected span; it validates the bounded symbolic program, applies set transitions, and returns sorted semantic values and a trace.

This path is labeled direct-symbolic-task-adapter. It does not imply that parseQuestion understands arbitrary T5 masks, and it does not give the adapter permission to embed the expected answer. The host scorer joins the returned values with the isolated oracle after execution. A future public adapter must preserve the same separation between visible task content, runtime method, and host-only label.

Factoid frames and provider routing

The factoid frontend recognizes bounded question constructions and preserves their operation even when the narrow assertion-and-rule parser does not have a matching ordinary query form. A eslm-factoid-question-v1 records the WH category, construction type, DS035 family, relation wording, direction when known, subject when recoverable, and a deterministic list of conservative question paraphrases. Natural copular definitions such as What is a cat? route to What does cat mean?; progressive and arithmetic neighbors are not treated as definitions. Country capitals, place locations, passive “used for” questions, and event-continuation questions also have explicit projections; other WH questions may retain an open relation surface without pretending that its predicate has been resolved.

The provider router submits those surfaces to every loaded provider. It does not stop at the first answer. If GeoNames and another provider return the same normalized semantic value set, their provenance is merged. If they disagree, the result is AMBIGUOUS and names every alternative and provider. If no provider responds, the runtime reports that it understood a factoid operation but lacks evidence. This distinction is important for SimpleQA: a question can be linguistically recognized while the independent public KBs still lack the requested fact.

Narrative event frames

Story continuation is an explicit structured task rather than an ordinary factoid. The narrative compiler tokenizes at most the declared number of bounded sentences, preserves the source surface, lemmatizes a small reviewed irregular inventory, and emits content terms, predicate candidates, named participants, pronoun groups, polarity, modality, and tense. The sequence records the named participant inventory and dominant tense. An ending is compiled by the same function as a context sentence, so candidates cannot acquire privileged features from their answer position.

The Story Cloze adapter supplies four visible context frames and two candidate frames to select-narrative-continuation. Candidate identifiers are content-derived and the correct ending remains in the host oracle. Semantic providers may attach bounded causal, goal, social, state, event, or contradiction evidence using candidate identifiers, source references, relations, and match types. The task never contains the expected label. This route establishes inspectable input to a defeasible ranker; it is not a claim that the frontend has solved unrestricted discourse, intention, or narrative generation.

The task frame as the downstream data boundary

The frontend’s most important output is not a string intent label but a task frame. The target shape has a task identifier; instructions; asserted inputs; constraints; one or more ordered goals; an output contract; a context stack; the chosen language route; and budgets for time, memory, search nodes, and shard bytes. A yes/no question can require a Boolean output. A definition can require glosses and lexical relations. A procedural request may eventually require an ordered plan plus verification obligations.

The current taskFrameFromQuery creates exactly one goal from one accepted query, and the planner selects one capability match with a linear audit sequence. The next planning gate adds an AND/OR goal graph and premise-level applicability proofs before inference. A missing advertised capability can be rejected during planning; missing evidence for an advertised method is normally discovered by execution and reported as UNKNOWN or another method-specific status.

Instructions state actions requested by the user. Assertions state content offered as premises. Constraints limit acceptable solutions. Goals state conditions to establish. This distinction prevents an imperative from being inserted as a world fact and prevents an input statement from being mistaken for an instruction. Output contracts determine whether an otherwise correct derivation can be realized as the required Boolean, entity, list, explanation, or structured record.

Review and implementation reference

A parser change is incomplete unless its symbolic output, negative examples, ambiguity behavior, task-frame consequences, result diagnostics, and documentation are tested together. Adding a surface pattern that only produces the desired answer is not a language capability. The reviewer should be able to substitute entities, reverse relevant relations, remove a premise, introduce a competing antecedent, and observe principled changes. The generic core must not contain benchmark identifiers or domain constants; lexical and domain-specific mappings belong in KB records.

The implementation is organized by responsibility: direct language analysis, deterministic approximation, request planning, session compilation, and operator-only normalization are separate owners. The authoritative details are in DS003, the task representation and method contracts in DS008, the local strategy and work contract in DS022, and the external normalization boundary in DS013.
