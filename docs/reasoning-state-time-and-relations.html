Finite state transitions, observed time, typed relation composition, and spatial constraints

The current state and relation methods are explicit finite algebras. One executes add, remove, and transfer operations; one reads the predecessor of an observed discrete state; one composes relation classes along bounded paths; one closes a finite graph under declared inverses and binary relation rules; one solves exact point displacements; and one derives directional relations between extended objects from boundary inequalities. None is a generic story simulator, unrestricted temporal logic, or continuous geometry engine.

State execution follows ordered operators. Relation execution searches a typed graph and reduces edge classes under package-supplied algebra. Both return the exact steps that justify the result.

Finite relation-state programs

A finite-relation-state-program-v1 names one relation, initial subject-to-value sets, an ordered transition array, and one query subject. add inserts the deduplicated values into the destination set. remove deletes them from the source set. transfer deletes the named values from the source and inserts them into the destination. The implementation validates relation consistency, bounded identifiers, value lists, subject count, and operation count before returning a sorted final set and trace.

The source adapter owns language such as “moves the contents” or “is put into.” It must compile that language into one of the typed operations. The core cannot branch on words such as Box, benchmark identity, or masked-answer position. Tests use fully renamed vessels and nonce contents to enforce the separation. This is a deterministic transition system related to a finite-state machine, although ESLM stores an explicit finite relation rather than a single enumerated control-state label.

Finite episodic-world orchestration

A finite-episodic-world-task-v1 is broader than one container relation but remains a finite typed transition system. Its ordered operations can update state and possession sets or contribute immutable event-role, graph-edge, vector, class, property, and motive evidence. The task declares inverse relations, vector mappings, transitive relations, induction selection, and motive-to-goal policy. The executor never assigns meaning to an identifier by spelling; the adapter must translate an external source into these operations and policies.

Execution uses one shared entity and operation identity space so a later movement can change the location of an object currently carried by that entity, an event-role query can return every matching theme, and a path or vector query can reuse the same accepted graph evidence. This is orchestration rather than a competing universal calculus. A pure container task should still use method:core:container-state-transitions; a pure vector task should use method:core:spatial-vector-constraints. The episodic method is appropriate when one bounded episode requires several of these operation families to share ordered state.

The output witness contains every operation identifier needed by the result. Independent replay validates the task, reconstructs all state and graph structures, recomputes the complete semantic value set, and rejects nonexistent or unnecessary host-oracle references. Several distinct values satisfying the same visible event query yield AMBIGUOUS. The executor may not select by insertion order, story identity, or answer position. This design follows event-sourcing ideas—an ordered event log determines current projections—while keeping a purpose-built symbolic semantics rather than adopting a software architecture pattern as a logical theory. See Martin Fowler's Event Sourcing description for the architectural analogy and the situation calculus overview for a more expressive logical account of actions and change that ESLM does not yet implement.

Observed temporal predecessor

The temporal predecessor method filters state-history events for one subject and predicate, sorts by explicit sequence, and removes consecutive duplicates. It locates the last occurrence of the requested boundary value and returns the immediately preceding distinct event. The witness contains both event records and their provenance.

This method answers “where was the entity before the observed boundary state?” only inside retained discrete history. It has no interval endpoints, duration constraints, concurrency, transitive temporal closure, uncertain time, or missing-event interpolation. James Allen's Maintaining Knowledge about Temporal Intervals defines a much richer qualitative interval algebra with relations such as before, meets, overlaps, during, starts, and finishes. The Allen interval algebra overview is useful background, but those relations remain planned for document KBs rather than claimed by the current predecessor scan.

Typed relation algebra input

A typed-relation-algebra-v1 declares surface relation identifiers, their semantic classes, optional target-feature requirements, reciprocal inverse mappings, and binary composition entries. A task supplies typed edges, entity features, query endpoints, an algebra identifier, and a maximum depth. The implementation rejects undeclared operands, non-reciprocal inverses, duplicate compositions, invalid identifiers, and conflicting entity features.

inverse(parent) = child
compose(parent, sibling) = {uncle_or_aunt}
refine(uncle_or_aunt, target.sex = male) = uncle

The algebra is declarative package data. The generic executor never assumes kinship, spatial direction, or another domain. Classical relation algebra studies Boolean operations, converse, identity, and composition over binary relations; ESLM uses a finite declared fragment inspired by that theory, not the complete abstract algebra.

Search and dynamic composition

The executor adds an inverse edge only when the algebra declares one. It performs bounded breadth-first search over path states. For a sequence of edge classes, a dynamic-programming table computes every result obtainable from every binary parenthesization: each interval [i,j] combines results from splits [i,k] and [k+1,j]. This matters when composition is partial or not assumed associative by the finite table.

The first depth with endpoint solutions defines the shortest-path layer. Each derived semantic class is refined into output relations using target features. No compatible output yields UNKNOWN. Several compatible refinements yield AMBIGUOUS. Independent shortest paths with incompatible values yield INCONSISTENT_CONTEXT. A solved witness includes the asserted or inverse path, explored-state count, derived classes, and nested composition tree. Breadth-first search is described in standard algorithm texts and the BFS reference overview.

Declarative qualitative relation closure

A declarative-qualitative-relation-system-v1 defines a finite vocabulary without assigning any meaning in core code. Every relation names a reciprocal inverse, may be included in the ordered output domain, and may participate in binary composition rules of the form r1 ∘ r2 → {r3, …}. A self-inverse declaration gives a relation symmetric behavior; the executor does not presume that an arbitrary relation is symmetric. Exclusivity groups state which simultaneous query conclusions would make the accepted context inconsistent. A qualitative-relation-task-v1 supplies finite typed facts and an ordered pair of query entities.

The executor begins with asserted subject–relation–object triples and the reverse triples licensed by their inverse declarations. It maintains indexes by ordered endpoint pair and by incoming and outgoing entity. Each newly accepted triple is joined with triples that end at its subject or begin at its object. If the two relation identifiers match the left and right operands of a declared rule, every declared result is added over the outer endpoints. Duplicate triples are ignored, while genuinely new triples re-enter the queue. This semi-naive work-list process stops at the least fixed point or at a declared resource bound. It is monotone: adding facts can add derivations or reveal an exclusivity conflict, but cannot retract a previously entailed triple.

The method separates mechanism from policy. The core implements reciprocal inversion, rule matching, fixed-point iteration, conflict detection, and proof construction. A source adapter or declarative package decides which relations are inverses, which are self-inverse, and exactly which compositions are sound. For the current SpaRP PS1 development method, source-local declarations make horizontal, vertical, and depth directions transitive; compose nested tangential or non-tangential proper-part links into a non-tangential proper part; and lift direction, far, and disconnection through containment. The absence of a rule is semantically significant: near, external connection, and partial overlap are symmetric but do not lift through arbitrary contained objects. No benchmark name or source relation identifier occurs in the generic module.

A solved result may contain several relations because qualitative spatial descriptions can establish independent horizontal, vertical, depth, distance, and topology facts for the same ordered pair. Output ordering is declared rather than inferred from discovery order. If the query endpoints have no accepted evidence, or closure derives no output relation between them, the status is UNKNOWN. If closure derives two members of one exclusivity group, the status is INCONSISTENT_CONTEXT. Invalid systems return UNPARSED, and configured limits on facts, entities, relation types, rules, derived triples, or proof depth return RESOURCE_LIMIT.

Every output has a replayable proof tree. Asserted leaves identify and reproduce an accepted source fact. Inverse nodes must reverse the premise endpoints and use its declared reciprocal. Composition nodes identify the declared rule and intermediate entity and contain complete left and right premise trees. The verifier recursively checks these local conditions, recomputes the full closure independently, and compares the complete ordered output set. It therefore rejects a changed fact, an undeclared rule, a malformed intermediate join, an invented relation, a duplicate proof, or omission of a relation that the declarations entail.

Spatial difference constraints

A typed-spatial-vector-system-v1 declares abstract axes and assigns each relation an integer vector. If a fact says that subject s bears relation r to object o, the core reads the declaration as the difference equation p(s) − p(o) = v(r). It never learns that a particular word means east or above. A source adapter or KB supplies that mapping as provenance-bearing data, so fully renaming dimensions, relations, and entities leaves the calculation unchanged.

The solver anchors the query object at the zero vector and propagates coordinates through asserted and algebraically inverted edges. A path o → x → s has displacement equal to the vector sum of its edges. When two paths reach one entity, their sums must agree exactly. Disagreement is an inconsistent constraint cycle, not a cue to select the shorter or earlier assertion. Disconnected graph components are ignored because they impose no equation on the query difference.

After obtaining the exact displacement, the method maps its component-wise sign to a declared qualitative output. In two dimensions, for example, a positive first component and negative second component may be declared as one diagonal class, regardless of magnitude. This is a finite form of a constraint satisfaction problem over additive group-valued differences and is related to graph-based potential assignments. It is not the Region Connection Calculus, Allen interval algebra, Euclidean distance inference, or probabilistic localization.

The witness lists every asserted or inverse edge in order, the exact sum, and the selected sign vector. An independent verifier checks each edge against its original fact, recomputes the sum, and redoes output classification. The declared bound applies to path depth and finite task structure; crossing it returns a resource or unknown result without discarding the source case.

Spatial extent inequalities

Point-vector composition is too strong when a source describes regions whose widths and heights matter. The extent method assigns every entity two abstract boundaries—start and end—on every declared dimension. It always admits the well-formedness inequality end(x) ≥ start(x). A declared positive separation between subject s and object o adds start(s) ≥ end(o); the negative polarity reverses subject and object. These are qualitative ordering constraints: they establish separation without inventing coordinates, widths, or distances.

The task must also state what a relation says about dimensions it does not mention. The currently supported policy, overlap-unmentioned-dimensions, adds the two inequalities needed for the projected extents to overlap on every orthogonal dimension. This policy is not inferred from words or benchmark identity. A different source calculus must declare and implement another policy rather than silently reuse it.

All constraints become a directed graph in which an edge u → v means u ≥ v. Reachability is transitive inequality closure. For every dimension, the executor searches from the subject's start boundary to the object's end boundary and also searches the converse. One path proves the positive relation; the converse path proves the negative relation. Paths in both directions mean an inconsistent context. No path means that the direction is underdetermined. Independent dimensions may yield several simultaneous output relations, and every relation receives its own path witness.

This construction is a deliberately narrow qualitative spatial calculus. It relates to work on cardinal direction relations for extended objects, including Schneider, Chen, Viswanathan, and Yuan's treatment of cardinal directions between complex regions, but ESLM implements only the documented finite inequality fragment. It does not claim the direction-relation matrix, the complete object-interaction matrix, RCC topology, metric geometry, or disjunctive region configurations. The mathematical core is reachability in a finite preorder; its result is reviewable because the proof is an ordered chain of original or policy-declared inequalities.

Complexity and resource boundaries

Container execution is linear in accepted transition values plus set-operation cost. The predecessor scan is dominated by sorting unless history is already ordered. Relation-algebra search can grow exponentially with depth and branching, while sequence reduction adds a cubic interval structure multiplied by the number of relation classes. Qualitative closure has at most one stored triple for each ordered entity pair and relation identifier, but rule joins can revisit many incoming–outgoing combinations as the graph becomes dense; the implementation therefore caps facts at 10,000, entities at 10,000, relation types at 256, rules at 4,096, derived triples at 100,000, and proof depth at 128. Spatial vector propagation is linear in the query component's vertices and directed edges after validation, because the first coordinate assignment fixes every later consistency check. Extent reasoning performs bounded reachability searches over at most four declared dimensions; after graph construction, each search is linear in its vertices and edges. These bounds report resource failure; they do not remove source cases from retained data.

Structural impossibility and missing representation

If two accepted typed graphs are isomorphic after alpha-renaming but their benchmark oracles demand different refinements, no invariant method over that representation can return both labels. That is a legitimate representation-level exception until new distinguishing evidence is supplied. By contrast, failure to parse a relation sentence, absence of a composition, or exhaustion of the path budget is an engineering gap. The project documents only the first kind as a demonstrated impossibility.
