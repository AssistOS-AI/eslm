SimpleQA: short factoid questions with broad factual coverage

SimpleQA asks short questions whose answers are usually brief factual values. The linguistic surface can look simple while the required knowledge ranges across people, places, dates, organizations, works, science, and many other encyclopedic topics.

What the current route tests

The factoid frontend recognizes a bounded collection of interrogative frames and routes understood questions to selected public knowledge providers. Open English WordNet supplies lexical facts, GeoNames supplies a selected geographic profile, ConceptNet supplies reviewed commonsense relations, and other packages provide narrower evidence. The runtime does not use the SimpleQA answer column as a KB and does not ask Language Agent to supply facts.

Current ESLM protocol

The latest diagnostic selects 100 questions deterministically across topics from 4,326 official records. Reference answers remain in the host evaluator. The local scorer normalizes the returned short string and applies exact match. This deliberately differs from the official semantic model grader, which can accept semantically equivalent wording and distinguish incorrect answers from non-attempts. The local percentage is therefore a parser-and-KB diagnostic, not an official SimpleQA score.

UNKNOWN and UNPARSED are different failures

UNPARSED means the direct symbolic frontend could not construct a supported question representation. Only this outcome is a candidate for operator-side Language Agent normalization, because a conservative language rewrite may bring the same request into the supported grammar. UNKNOWN means the question frame was understood but the selected declarative knowledge packages did not provide sufficient evidence for an answer. Rephrasing an UNKNOWN question would not supply the missing fact and is therefore not an authorized normalization trigger.

The published direct probe made no Language Agent calls. Its normalization percentage is the fraction of cases that ended UNPARSED; it is not a count of external invocations and not a claim that the Language Agent could solve those questions.

What progress requires

Parser failures require reusable interrogative constructions with renamed and contrastive tests. Parsed unknowns require independently licensed, provenance-bearing factual sources and query-directed package access. A correct exact string without independently sourced evidence would not satisfy the ESLM contract, and a missing fact is not a proof that symbolic factual question answering is impossible.
