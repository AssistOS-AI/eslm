ESLM Documentation / Benchmarks

Public benchmarks and comparable evidence

One public synthesis and evaluation run is complete: bAbI v1.2 Task 15 English 10k. Tasks 2, 3, and 16 have cached, prepared train/test splits but no synthesis candidate or score. Other suites remain portfolio entries, not implemented results. Every score names its split, active KB selection, evidence regime, and machine-recorded source identity.

English language and factual knowledge

Purpose. BLiMP tests whether the English language layer prefers grammatical minimal pairs across defined phenomena. EWoK tests world-knowledge preferences, while SimpleQA tests precise short factual answers. These suites separate construction competence from the amount of encoded knowledge.

State and relational reasoning

Purpose. bAbI supplies controlled worlds and supporting facts. Entity Tracking tests final state after ordered operations. CLUTRR varies kinship composition length. Together they test parsing, execution, proof depth, distractor resistance, and generalization to longer compositions.

Narrative evaluation

Purpose. Story Cloze and future narrative suites require event and world-state modules that are not implemented in version 0.1. The adapter should report parse coverage, state consistency, schema support, and ending selection separately so a stylistic preference is not mistaken for narrative execution.

Local benchmark execution

Purpose. The implemented neutral protocol accepts canonical QA cases and good/bad sentence pairs. Reports include a protocol identifier and dataset hash. Public adapters will convert official formats into this protocol while retaining source metadata, split, phenomenon, and license information.

External model comparison

Purpose. benchmark export removes answers and deterministically shuffles preference options. A separate runner calls the chosen external model. benchmark score-predictions applies the same local oracle. ESLM therefore contains no external SDK, credentials, or model call.

Published numbers remain reference-only unless dataset hash, split, prompt, examples, grader, tools, and evidence regime match.

Knowledge modules and benchmarks

Optional educational KBs are never loaded into the default Task 15 command. If --kb is supplied to a benchmark, the report records those IDs and marks the model non-comparable. A future benchmark-specific KB may be synthesized only from that benchmark's authorized train split; hidden test answers remain excluded. This allows modular experiments without concealing additional knowledge.
