Public benchmarks: what was actually run

The project currently has one completed public benchmark result: bAbI v1.2 Task 15, English 10k. Three more bAbI tasks are locally prepared but have not been learned or scored. BLiMP, CLUTRR, EWoK, SimpleQA, Entity Tracking, and Story Cloze are documented future experiments, not current results.

English language and factual knowledge

Purpose. BLiMP tests whether the English language layer prefers grammatical minimal pairs across defined phenomena. EWoK tests world-knowledge preferences, while SimpleQA tests precise short factual answers. These suites separate construction competence from the amount of encoded knowledge.

State and relational reasoning

Purpose. bAbI supplies controlled worlds and supporting facts. Entity Tracking tests final state after ordered operations. CLUTRR varies kinship composition length. Together they test parsing, execution, proof depth, distractor resistance, and generalization to longer compositions.

Narrative evaluation

Purpose. Story Cloze and future narrative suites require event and world-state modules that are not implemented in version 0.1. The adapter should report parse coverage, state consistency, schema support, and ending selection separately so a stylistic preference is not mistaken for narrative execution.

How a public case becomes a result

The native adapter converts an official record into a stable case containing its visible context, question, expected semantic value, split, support annotations, and dataset identity. Training commands expose only the authorized train split to the coding agent. The evaluator loads the isolated test split only after a candidate has been promoted, executes the same offline runtime used by the CLI, and compares canonical semantic values rather than relying on wording.

The machine-readable report preserves source identity and per-case outcomes for audit. This explanatory page deliberately omits integrity hashes; they are implementation evidence, not useful introductory documentation.

External model comparison

Purpose. benchmark export removes answers and deterministically shuffles preference options. A separate runner calls the chosen external model. benchmark score-predictions applies the same local oracle. ESLM therefore contains no external SDK, credentials, or model call.

Published numbers remain reference-only unless dataset hash, split, prompt, examples, grader, tools, and evidence regime match.

Reproduce the completed public run

node src/cli.mjs dataset status --dataset babi-15-en-10k-v1.2
npm run benchmark
node src/cli.mjs benchmark references

npm run benchmark evaluates the promoted symbolic core on the prepared Task 15 test split and refreshes both the readable report and the detailed JSON report. It does not download data, run a coding agent, retrain the model, or load QUICK, WordNet, or ATOMIC.

Knowledge modules and benchmarks

Optional KBs are never loaded into the default Task 15 command. If --kb is supplied to a benchmark, the report records those IDs and marks the run non-comparable with the clean result. A benchmark-specific module may be synthesized only from that benchmark's authorized train split; hidden test answers remain excluded. This allows modular experiments without concealing additional knowledge.
