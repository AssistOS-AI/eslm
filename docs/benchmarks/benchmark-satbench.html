SATBench: Boolean search, assignments, and unsatisfiability certificates

SATBench asks whether generated propositional constraint systems are satisfiable. ESLM's formula track consumes the official machine-readable CNF annotation and evaluates the generic SAT method. This route measures formula execution separately from the authors' natural-language-only prompt protocol.

Current measurements: Read the generated SATBench rows on the evaluation dashboard or inspect the raw v2 report. Fresh execution, score, witness validity, and receipt currentness remain report-owned.

Both answers require constructive evidence. The verifier checks the source clauses independently of the search decision.

What is tested

The official source contains 2,100 cases balanced between satisfiable and unsatisfiable instances, with 5 through 90 variables and easy, medium, and hard groupings. Every row is retained. A label-blind split separates development-visible and protected membership. Exact split sizes and execution state belong to the partition receipt and generated report. No file or valid case is rejected because of its size; the JSONL source is streamed and resource use is recorded separately from semantic acceptance.

Each signed integer literal becomes a generic Boolean atom or its negation, each source clause becomes a disjunction, and the complete constraint set becomes strict premises. Deterministic DPLL uses unit propagation and bounded search. For satisfiable inputs, the output contains a total assignment and a separate verifier checks every original clause. For unsatisfiable inputs, the output contains a split/conflict certificate and a separate replay verifies that both branches close. A bare SAT or UNSAT label is insufficient.

How to read a fresh result

A protected evaluator may open the label-blind partition only after the adapter, solver, verifier, tests, source identity, and membership are frozen. It returns aggregates only: no puzzle, clause, identifier, assignment, certificate, label, or per-case outcome may leave the evaluator. The report then distinguishes answer correctness from independent witness validity and labels the exact behavior checkpoint.

The result applies to the source-annotated formula track. The authors' public prediction protocol supplies a scenario, natural-language conditions, and a question without the clauses annotation. A formula-track percentage therefore must not be reported as a natural-language leaderboard score. An English constraint compiler needs its own development boundary and untouched evaluation source.

Why the method is reusable

The reasoner exposes Boolean formulas, assignments, conflicts, and budgets; it has no benchmark dispatch and does not know SATBench fields. Clause order and variable renaming are invariant, while removing a conflicting clause changes an unsatisfiable instance into a satisfiable one in contrast tests. The same method already supports query-directed entailment in PrOntoQA. This is an algorithmic capability—DPLL search with independently checked evidence—not a table of benchmark answers.

Source and citation

The dataset and code revisions are pinned on the source registry. The official dataset card declares Apache-2.0. The benchmark publication is SATBench: Benchmarking the Reasoning Capability of Large Language Models in Satisfiability Problems (EMNLP 2025).
