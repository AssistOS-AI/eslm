LogiQA: expert-authored deductive reading comprehension

LogiQA contains examination-style passages, questions, and four physical answer slots in English and Chinese. It requires a reader to recover constraints and argument structure from prose, then prove which candidate satisfies the question.

Current measurements: Read the generated LogiQA row on the evaluation dashboard or inspect the raw v2 report. Adapter state, executed language profile, and outcomes are report-owned.

Different question forms require different evidence. The final choice must follow from the explicit model rather than candidate position or linguistic plausibility.

Source scope and forced-choice scoring

The pinned source contains 17,356 physical records: 8,678 semantic cases in English and the parallel 8,678 in Chinese. For each language there are 7,376 train, 651 development, and 651 test records. All six source files are retained. Train and development are streamed record by record; the two test files remain unopened and are identified only by bytes and digests.

Each evaluated case requires one of four physical answer slots. If a non-empty evaluated pool receives no in-domain predictions, end-to-end accuracy and attempt coverage are both 0%, while selective accuracy is null. NO_APPLICABLE_METHOD explains an abstention but does not remove it from the denominator. The generated row also states which language profile ran; preserved rows outside that profile are coverage gaps, not scored failures.

Physical answer slots and anomalies

Each source record occupies eight physical lines: a separator, one answer letter, passage, question, and four answer slots. Some visible answer strings have swapped, missing, lower-case, full-width, or punctuation-variant A/B/C/D prefixes. The official README defines the physical lines as the alternatives, so the adapter records prefixes as presentation anomalies and never lets them reorder the slots or alter label semantics. The host-only oracle joins the answer letter only after predictions exist.

What must be implemented

Like ReClor, LogiQA needs a reusable compiler from prose to quantified, conditional, ordering, exclusivity, and argumentative constraints. The method must represent the question's modality, test each candidate under the same theory, and return a proof, countermodel, or explicit unresolved status. It must pass candidate permutation, full vocabulary renaming, premise-order, and meaning-changing contrast tests before the sealed test files may be opened. Translation of the Chinese track is a separate measured language route and cannot substitute for this reasoning method.

A narrower research route covers monadic categorical propositions and necessary-conclusion or sufficient-premise selection. It proves a qualifying option by contradiction and supplies a finite countermodel for every nonqualifying option. The executor is generic and requires nonce renaming, candidate permutation, semantic reversal, and independent witness replay.

That fragment cannot safely run a case unless the question operator, every premise, the conclusion boundary when required, and all four candidates are supported. Ignoring an opaque relational, conditional, cardinality, ordering, or compound candidate can change uniqueness and is forbidden. Promotion therefore requires multiple independent complete source cases and separate proof contracts for each additional semantic family.

Source and rights

The exact official repository revision appears in the source registry. The repository provides data and citation but no dataset LICENSE, so ESLM retains a local academic-research cache and does not redistribute rows pending clarification.
