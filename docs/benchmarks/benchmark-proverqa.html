ProverQA: first-order inference with independently checked witnesses

ProverQA combines natural-language theories, source-provided first-order annotations, three-way entailment labels, and reference reasoning. ESLM keeps annotation adaptation plus generic finite entailment separate from any claim that the ordinary language frontend derived those formulas from English.

Current measurements: Read the generated ProverQA rows on the evaluation dashboard or inspect the raw v2 report. Tested counts, correctness, witness totals, and checkpoint state are generated evidence.

The answer and reference reasoning remain outside the visible task. A label match is accepted only when the returned semantic witness is valid.

Source and partition boundary

The pinned official dataset release contains 1,500 public evaluation cases—500 easy, 500 medium, and 500 hard—and 5,000 training records. ESLM retains every row and validates all 15,842 premise annotations and 17,342 formulas. Three malformed JSON strings embedded in training-output text are retained and counted; they are not silently dropped or executed.

Before adaptation, each difficulty is sorted by a stable hash that excludes the answer and divided into development-visible and protected membership. The separate training source is never part of an evaluation denominator. Exact membership sizes, partition digests, executed scope, and one-shot checkpoint state are read from the report and frozen partition receipt.

Logical execution

The adapter parses source annotations into inert formulas, grounds their finite domain, and asks the same generic entailment method used by other sources. Answer A requires the conclusion to follow, answer B requires its negation to follow, and answer C requires neither. Every outcome carries either a proof/conflict certificate or a model witnessing non-entailment; an independent verifier evaluates that witness against the original formulas.

The source occasionally renders morphologically related predicate names differently across annotations. The adapter applies a label-blind reconciliation policy based on normalized predicate morphology and records when it does so. It does not inspect the answer or reference reasoning, and the core contains no ProverQA name, case identifier, answer constant, or difficulty-specific branch. Nonce predicate renaming and meaning-changing controls test this boundary.

How to read the result

Strict answer agreement and semantic-witness validity are separate measurements. An aggregate-only protected receipt may disclose their totals and broad strata, but not affected members; those outcomes cannot become a post-fresh repair list. Once the oracle is opened, the report must retain the historical checkpoint rather than imply that later code was tested on unseen cases.

Predicate reconciliation remains label-blind: a shorter same-arity identifier may omit exactly one content root only when every aligned source statement using it explicitly contains that root. A nonce positive control and a contrast lacking the surface evidence protect the boundary; an unrestricted lexical subset merge remains rejected because it can create inconsistency.

This is fresh evidence for an annotation-assisted logical-form track. It shows that the generic finite reasoner executes supplied logical representations; it does not show that ESLM derived them from all ProverQA English or reproduced the official end-to-end protocol. The next English-to-formula candidate requires newly untouched evidence.

Rights and reproducibility

The source is public and intended for academic research, but the pinned dataset card does not state an explicit license identifier for the assembled benchmark. ESLM therefore keeps source rows in the ignored local cache, publishes only manifests and aggregate receipts, and does not infer redistribution permission from licenses of upstream WordNet or name resources. The ICLR 2025 paper is the primary methodological citation.
