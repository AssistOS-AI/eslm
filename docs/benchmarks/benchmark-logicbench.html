LogicBench: controlled arguments across classical and non-monotonic logic

LogicBench tests whether a system can interpret short natural-language arguments and decide their consequences. Its BQA form asks for a binary judgment; MCQA asks the system to compare several candidate answers. ESLM reports a source-adapter diagnostic, not the paper's language-model prompting score.

Current measurements: Read the generated LogicBench rows on the evaluation dashboard or inspect the raw v2 report. The dashboard identifies executed tracks and audits receipt currentness.

The adapter handles source syntax; the generic core evaluates finite classical models or prioritized defaults. The oracle sees only the final decision.

What the protocol measures

Propositional cases require connectives and validity. First-order cases require entity, quantifier, predicate, and coreference alignment before a finite projection can run. Non-monotonic cases add explicit defaults and exceptions and require skeptical agreement across equally preferred models. MCQA additionally requires a comparable decision for every nonempty option.

How to read the outcomes

SOLVED means the adapter produced a usable decision; correctness still depends on agreement with the oracle. UNPARSED means the controlled clause or option did not become a safe formula. UNKNOWN means a supported task lacked decisive evidence. UNDERDETERMINED means equally preferred models support different choices. These statuses must not be collapsed into one “wrong reasoning” category.

Development and fresh evidence

The augmented source is development-visible. A protected evaluation source can support a one-shot fresh claim only when membership, candidate behavior, generic dependencies, scorer, and oracle are frozen before labels are opened. Once opened, that receipt is a historical checkpoint. Later improvements cannot reuse its item failures while still calling the same rows untouched; the v2 report labels the receipt as current, historical-stale, historical-unrecoverable, invalid, or unavailable.

Next acceptance gates

The generic finite and preferred-model methods exist. The next gates expand language and task generalization across clause alignment, pronouns and entity identity, existential paraphrases, controlled exceptions, and multiple-choice option semantics. Fixes belong in generic language representations and source adapters with nonce and contrastive tests, never branches on LogicBench family names or answer positions.
