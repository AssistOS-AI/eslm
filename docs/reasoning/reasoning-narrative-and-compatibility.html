ESLM Documentation / Reasoning / Narrative and compatibility

Bounded narrative state and signed semantic compatibility

ESLM's plausibility methods are explicit ranking systems over bounded event and relation frames. They combine structural continuity with independently sourced semantic evidence. The output is defeasible, exposes every feature contribution, and abstains when the margin is insufficient.

The scorer does not read an expected ending. It compares visible candidates using declared features and source-attributed evidence, then applies a visible margin rather than candidate order.

Event-frame approximation

compileNarrativeSentence normalizes and tokenizes at most 4,096 characters and 512 tokens. It recognizes bounded named-participant candidates, pronoun groups, content lemmas, predicate candidates, polarity, modality, and a coarse tense. Event identifiers are derived from sentence content and position, not answer choice. A sequence has at most 64 events and records all named participants plus the dominant observed tense.

This representation is deliberately reviewable and deliberately incomplete. It uses allowlisted morphology and finite lexical cues rather than a full syntactic parser. It does not establish deep coreference, implicit goals, event identity across paraphrases, presupposition, discourse relations, or causal truth. These missing distinctions explain why a deterministic structural ranker cannot solve unrestricted story continuation.

Structural feature equation

For candidate c, the current score is an integer-weighted sum:

score(c) = Σᵢ valueᵢ(c) × weightᵢ

Features count named-participant continuity, newly introduced participants, resolvable pronouns, content overlap with the two most recent events, global content overlap, repeated predicates, tense agreement, polarity conflict, content and predicate specificity, participant counts, non-asserted modality, and lexical novelty. Counts are clipped to explicit bounds. Each contribution stores the feature ID, value, weight, product, and provenance references that explain the value.

Weights may come from source-visible adapter policy, but only for an allowlisted feature. They cannot introduce a benchmark record, ending position, expected label, or arbitrary callback. Reordering candidates cannot change their semantic scores; the identifier order is used only to make the ranking array deterministic after a genuine tie, never to manufacture a winner.

Provider evidence

Provider adapters contribute candidate-specific support records with a bounded score in [-1,1], semantic family, relation, source reference, and match type. The ranker maps evidence into causal, goal, event, social, state, or contradiction features. ATOMIC can provide event-centered tendencies; ConceptNet can provide purpose, capability, property, cause, and location edges; the authored world-relations package can provide reviewed construction and implication rules. Every record remains attributed to its package.

Provider order is not epistemic authority. Duplicate support may be deduplicated by stable evidence identity. Contradictory evidence remains signed and visible. A benchmark answer never becomes provider evidence.

Selection semantics

The ranker sorts candidate scores, computes margin = best − second, and compares it with the declared minimum. If the margin is smaller, the result is UNKNOWN with score-tie-or-insufficient-margin. Otherwise it returns DEFEASIBLE and the selected candidate identifier. The witness includes the margin, policy, all rankings, every feature, and the provider-evidence count.

This is not probability normalization: scores need not sum to one and a margin is not a calibrated confidence. It is not deduction: structural continuity and commonsense tendencies do not prove that one event occurs. It is not unrestricted generation: candidates are explicit input. The broader traditions of script-based story understanding and commonsense inference are relevant background, including Schank and Abelson's Scripts, Plans, Goals, and Understanding and the overview of commonsense reasoning, but ESLM claims only its executable feature contract.

Semantic compatibility

The compatibility core converts bounded clauses into unary, binary, proposition, change, comparison, possessive, material, action, or numeric frames using reviewed ontology constructions. It normalizes argument order and polarity, applies only declared inverse relations and bounded implications, and compares target frames with context frames. Contributions are signed and retain the matched construction or provider edge.

A compatibility preference compares the same target against two contexts. The preferred context must receive a strictly higher score. Equality is a tie and fails a strict preference protocol. This matters because breaking a tie by sentence order would create a high score without new knowledge.

Factoid routing is a different operation

A factoid frame represents a recognized information request, not a plausibility candidate. The router consults all selected providers with conservative paraphrases. Equal semantic value sets merge provenance; different authoritative values return AMBIGUOUS; no evidence returns a knowledge gap. Language understanding and factual coverage therefore remain separable in diagnostics.

What must improve

Broader narrative competence requires typed goals, causal preconditions and effects, social roles, richer negation and contradiction, event and entity coreference, temporal intervals, procedure knowledge, and independent world evidence. Adding more lexical overlap weights would not supply those semantics. New work must introduce reviewed representations and provider-independent tests, then demonstrate transfer on fresh stories without inspecting their labels.
