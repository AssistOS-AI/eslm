Knowledge-base ingestion: current line and next targets

The current catalog contains eight concrete packages. They cover a small tutorial world, two benchmark-policy packages, lexical knowledge, defeasible event knowledge, geography, everyday relations, and reviewed relation semantics. They form useful foundations; broad document-trained world modeling remains a separate ingestion and evaluation program.

node src/cli.mjs kb list is the current inventory view. npm run kb:validate checks package structure and identities. Neither command proves that every package contributed to a particular answer; the runtime result separately names selected, consulted, and answer-contributing packages.

Where one package sits in the ingestion pipeline

  1. Source reviewed: origin, revision, rights, split, and retention policy are frozen.
  2. Canonical records built: typed facts, terms, rules, constraints, and provenance are emitted as inert data.
  3. Package compiled: deterministic indexes and shards are produced without changing canonical meaning.
  4. Package validated and catalogued: files, references, namespaces, checksums, and supported projections pass the registration boundary.
  5. Queried and witnessed: a request reaches the package through a real access path, and any contributing record appears in result provenance.

A source can stop at any stage. “Downloaded,” “compiled,” “registered,” “consulted,” and “used in an answer” are intentionally different states.

What would count as real progress

The next package should improve held-out questions that require its source, preserve citations to exact source spans, expose unresolved identity or conflict instead of guessing, and leave unrelated package answers unchanged. More records alone are not enough. Extraction coverage, factual spot checks, provenance reachability, query routing, proof validity, memory behavior, and regression stability must move together.
