Basic Eval status and processing evidence

Basic Eval converts 1,000 development-visible Romanian proposals into traceable English cases and measures what the offline symbolic runtime can frame, execute, ground, and express. It is a discovery instrument, not an unseen-test claim: every result retains conversion lineage, profile boundaries, executable identity, and its earliest failed processing stage.

Current progress

Loading the generated Basic Eval checkpoint…

The status cards are generated from the canonical case file, the three profile summaries, the semantic-review ledger, and the separate structural controls. A raw review is never counted as success. Only a decision bound to the exact result file enters the validated-pass or qualitative-fail totals; changed result bytes make that review stale. A stale profile remains visible and explicitly marked stale whenever its executable or case-manifest digest differs from current source.

What the evaluation is allowed to teach

The converted cases can expose repeated language shapes, operation semantics, missing evidence, realization problems, and overly mechanical failure presentation. They cannot authorize benchmark-specific branches or answer tables. A recurring, vocabulary-independent responsibility becomes a core proposal only after renamed, nonce, negative, and metamorphic controls. Missing world knowledge remains provenance-bearing KB data. A genuinely new processing node, coordination node, authority gate, or strategy family receives a separate contiguous DS before entering the runtime catalog.

The generic bounded-operation path

After the English boundary and direct parser decline to answer, the request-operation framer may represent one explicit bounded operation. That responsibility belongs to request/session processing; deterministic value and supplied-text executors belong to method selection; declarative fact inspection belongs to knowledge routing; and typed result assembly belongs to response construction. These nodes exchange exact packets across the ordinary runtime graph instead of forming an evaluation-named side circuit. Unsupported requests continue into normal request planning and language recovery.

DS031		Runs exact arithmetic, percentage, conversion, clock, grouping, mean, sequence, or strict-order semantics and emits packet:runtime:deterministic-value-result with a replayable witness.

Request framing

The framer normalizes Unicode punctuation and admits at most one closed semantic frame from a request of at most 64 KiB. It recognizes semantic operations rather than case identities. A capture must contain every required finite operand, declared option, source span, or output constraint; an ambiguous or incomplete capture abstains. English framing cannot repair a likely-non-English rejection and cannot translate quoted content. The separately disclosed Language Agent remains the only operator-side translation proposal boundary, and its proposal still returns through the unchanged local parser.

The initial operation vocabulary includes scalar arithmetic, percentage and proportional calculations, unit and clock conversion, equal grouping, remaining quantity, arithmetic mean, parity, arithmetic-sequence continuation, strict-order extremes, supplied-text classification and extraction, bounded correction and rewriting, title generation, entity summary, and person listing. Adding another surface phrasing for one of these operations changes DS030 and framing tests. Adding a stable responsibility with a different state, authority, resource, or failure boundary requires a new DS.

Exact quantity and order methods

The DS031 executor treats the frame as typed data, never as executable text. Every success carries the equation or relation rule, operands, relevant intermediate state, and result. Division by zero returns an explicit underdetermined gap. A non-constant sequence, invalid clock, zero proportional denominator, negative remaining inventory, non-integer parity input, or malformed order chain cannot be guessed into success. Currency aliases are normalized only for answer presentation; they do not change the numeric witness.

Method classReplay and falsification evidence
Scalar and percentageRecompute from finite operands; test sign changes, commutative permutations where valid, zero, percentage scaling, and division-by-zero rejection.
Time and unitsReplay the explicit factor or minute conversion; test midnight wrap, invalid clock fields, undeclared pairs, singular/plural presentation, and non-integral minute rejection.
Sequence and orderReplay every adjacent difference or strict relation edge; rename all entities, translate sequence values, reverse contrastive relations, and reject inconsistent chains.

Operations over supplied text

DS032 keeps request-provided material separate from external evidence. Option-conditioned intent classification scores only closed labels and generic word-boundary cues; a tie or zero score abstains. Sentiment is a bounded cue estimate, not a claim about a writer’s inner state. Extraction copies explicit spans into a declared shape and uses an explicit missing marker instead of filling likely values. Orthographic correction, polite rewriting, title generation, and single-sentence condensation retain source propositions under narrow transformation rules and record their source-to-output witness. Condensation must actually reduce or reorganize an admitted relation; echoing the source is not accepted merely because it remains factual.

Exact labels and spans can use deterministic scoring. Open-form quality remains semantic review. A fluent string is not automatically a correct answer, and this node does not own professional correspondence, multi-paragraph synthesis, argument critique, unconstrained advice, or creative generation. If further evaluation establishes one of those as a stable constraint-aware process, its implementation begins with a separate DS.

Grounded conversational knowledge

DS033 provides a short natural bridge from loaded facts to an operator-facing answer. It prefers exact normalized names and admits a one-character correction only when the loaded candidate is uniquely closest; the correction is disclosed. A summary deterministically selects subject facts, realizes only the selected predicates, and binds every sentence to fact provenance. A person listing depends on explicit class facts rather than a hard-coded famous-person inventory.

When no admitted fact answers the question, the response says so directly. Related dictionary senses and graph neighbors may remain available in an explicit trace, but they are not printed as though they answered the request. Machine output preserves real KB package and external-source identities; ordinary answer prose does not repeat version strings. QUICK is a small independently authored smoke package, while real-KB evaluation must demonstrate source-derived coverage without QUICK.

Profiles and reproducibility

ProfileQuestion answered by the profile
core-onlyCan reusable framing and deterministic operations solve the request without domain facts? A world-knowledge miss is expected here and must not be patched with constants in core code.
quick-assistedDoes a small validated declarative package support smoke and interaction examples while preserving provenance? Its score is reported separately because QUICK may be authored during development.
real-kbCan normal source-derived packages, exact routing, and memory policy provide the necessary evidence without QUICK? This is the required direction for genuine knowledge coverage.

Each result records the case-corpus digest, executable digest, selected profile, package-manifest digests, machine status, route, method, operation, answer, contributing and consulted KB identities, score state, and earliest failure. The runner does not silently invoke the external Language Agent. The checked-in report is a checkpoint artifact and becomes stale when source, cases, or package identities change.

Vocabulary cases use the source-derived real-KB profile rather than pretending synonym and antonym facts belong in generic core code. The WordNet compiler preserves source sense order, part of speech, and sense-specific antonym groups. That removes several mechanically valid but irrelevant first-edge answers. Provenance alone still does not disambiguate a context-free polysemous word, so responses that select the wrong intended sense remain qualitative failures rather than being credited as lexical success.

Known boundary and next discovery cycle

The Romanian source is preserved immutable research input; the current eval corpus is its English development projection. Translation tasks whose quoted payload remains Romanian cannot be claimed by the local English runtime. They require a separately evaluated Language Agent proposal or a future independently validated language profile. Vocabulary, factual, classification, professional communication, complex planning, advice, and creative cases remain distinct clusters rather than one misleading aggregate failure.

The improvement loop is: validate conversion lineage; run the relevant profile; cluster the earliest failed node; decide KB, existing operation, new strategy, or genuinely new component; write the owning DS first when architecture is new; add renamed and metamorphic tests; run focused and regression suites; rerun the eval; and publish both gains and remaining gaps. Passing development cases is useful engineering evidence, not a claim of human-level language understanding.

Normative contracts: DS030 request framing, DS031 deterministic operations, DS032 supplied-text operations, DS033 knowledge inspection, and DS004 benchmark-guided learning.
